# FRD: Інтеграція з SMTC (System Media Transport Controls)

- **Статус:** реалізовано (2026-06-11), гілка `feature/smtc-integration`.
  Дизайн: [спека](../superpowers/specs/2026-06-11-smtc-integration-design.md),
  [ADR](../decisions/2026-06-11-smtc-via-windows-crate.md).
- **Тип:** Feature Requirements Document — *що* і *навіщо*; технічні рішення
  фіксуватимуться окремим ADR на момент реалізації.
- **Походження:** аналіз дефолтів глобальних хоткеїв
  ([keyboard-shortcuts.md](../keyboard-shortcuts.md), Tier 1): транспортні дії
  (play/pause, prev/next, гучність) семантично належать медіа-клавішам, але
  реєструвати `MediaPlayPause` тощо як глобальні хоткеї означає вкрасти їх у
  всіх інших плеєрів. SMTC — системний механізм, який вирішує це без крадіжки.

## 1. Проблема

Tapir керується OS-глобальними хоткеями (`Ctrl+Shift+R`, `Ctrl+Shift+P`, …).
Вони працюють, але:

1. **Апаратні медіа-клавіші не працюють.** Клавіша ⏯ на клавіатурі, кнопки
   гарнітури/навушників (single/double/triple tap), Bluetooth-пульти — все це
   іде через SMTC і Tapir його не чує.
2. **Системний медіа-оверлей Windows порожній.** Win+волюм-попап показує
   «що грає» для Spotify/браузера, але не для Tapir; немає обкладинки, назви
   станції, кнопок prev/next.
3. **Будь-який глобальний хоткей щось краде** в інших застосунків. SMTC —
   єдиний канал транспортних команд, який ОС маршрутизує кооперативно
   (активній медіа-сесії), без захоплення комбінацій.

Для незрячих користувачів (основна аудиторія) це не «нішевий комфорт»:
кнопка гарнітури — найшвидший спосіб поставити радіо на паузу, не перемикаючи
фокус і не згадуючи комбінацію.

## 2. Цілі / не-цілі

**Цілі:**

- Tapir видимий для Windows як медіа-сесія, коли щось відтворюється.
- Апаратні медіа-клавіші та кнопки гарнітури керують відтворенням.
- Системний оверлей показує метадані поточного потоку.

**Не-цілі:**

- Заміна наявних Tier-1 хоткеїв — вони залишаються (toggle_recording і
  stop_all через SMTC невиразимі в принципі; SMTC доповнює, не замінює).
- Керування *записом* через SMTC (немає такої кнопки в протоколі; плутати
  play з record небезпечно).
- Кросплатформність (Tapir — Windows-only; macOS MPNowPlaying поза скоупом).

## 3. Функціональні вимоги

| # | Вимога | Пріоритет |
|---|---|---|
| FR-1 | Коли плеєр у стані `Playing`/`Paused`, Tapir реєструє SMTC-сесію зі станом, що дзеркалить `PlaybackState` | must |
| FR-2 | SMTC-кнопка Play/Pause → той самий шлях, що `toggle_playback` у [shortcuts.rs](../../src-tauri/src/shortcuts.rs) (resume/pause плеєра) | must |
| FR-3 | SMTC Next/Previous → існуючий міст `transport-skip` → webview (рішення «що таке next» лишається у фронтенді, як для `Ctrl+Alt+←/→`) | must |
| FR-4 | Метадані сесії: назва станції/потоку + поточний трек з ICY-метаданих (`icy-metadata` вже в стеку); оновлення при зміні треку | must |
| FR-5 | SMTC Stop → зупинка відтворення (НЕ запису) | should |
| FR-6 | Обкладинка/логотип станції в оверлеї (favicon з Radio Browser, якщо є) | could |
| FR-7 | Налаштування «Інтеграція з системними медіа-кнопками» (on/off) у Settings → Hotkeys; off — сесія не реєструється | should |
| FR-8 | Коли відтворення зупинено (`Stopped`/нічого не грає), сесія знімається — Tapir не висить у оверлеї мертвим записом | must |

## 4. Нефункціональні вимоги

- **Кооперативність:** Tapir стає «поточною» медіа-сесією лише коли реально
  грає; пауза іншого плеєра через нашу появу — стандартна поведінка ОС,
  але ми не повинні займати сесію у стані `Stopped` (FR-8).
- **Дедуплікація команд:** команда з SMTC і одночасний глобальний хоткей не
  повинні давати подвійний toggle — спільний debounce із
  [shortcuts.rs](../../src-tauri/src/shortcuts.rs) (`recently_fired`).
- **A11y:** SMTC-оверлей — системний UI, NVDA читає його нативно; жодних
  додаткових ARIA-вимог. Стан play/pause у самому Tapir уже анонсується.
- **Запис не залежить від SMTC:** збій/відсутність SMTC (N-серії Windows без
  Media Feature Pack) не впливає на запис і наявні хоткеї — graceful no-op.

## 5. Технічний напрям (ескіз, деталі — в ADR)

- Кандидати: crate `souvlaki` (обгортка SMTC, потребує HWND — беремо з
  `tauri::Window::hwnd()`) або прямий `windows`-crate
  (`ISystemMediaTransportControlsInterop::GetForWindow`). Вибір — за ADR
  (обрано прямий `windows`-crate, див. посилання в шапці).
- Точки інтеграції: player engine (`PlaybackState` переходи → оновлення
  сесії), ICY-метадані (→ FR-4), `handle_shortcut_action` (спільні обробники
  для FR-2/FR-3/FR-5).
- Подія від SMTC приходить не в UI-потоці — маршрутизувати через
  `tauri::async_runtime`, як це вже робить обробник хоткеїв.

## 6. Критерії приймання

1. Запустити відтворення станції → натиснути ⏯ на клавіатурі → пауза;
   ще раз → продовження. Spotify при цьому не реагує.
2. Оверлей гучності/медіа Windows показує назву станції та поточний трек,
   трек оновлюється при зміні ICY-метаданих.
3. Кнопки prev/next в оверлеї перемикають потік так само, як `Ctrl+Alt+←/→`.
4. Зупинити відтворення → Tapir зникає з медіа-оверлея; медіа-клавіші
   повертаються попередньому плеєру.
5. Запис під час усіх сценаріїв вище не переривається й не стартує.
6. NVDA: фокус у будь-якому застосунку, кнопка гарнітури — пауза без зміни
   фокуса і без озвучення зайвого.

- ~~Поведінка при кількох одночасних прев'ю (Browser)~~ — знято: двигун
  плеєра має одну сесію нараз, прев'ю витісняє попереднє відтворення;
  SMTC дзеркалить усе, що грає (станції, файли, прев'ю).
- FR-6 (обкладинка): відкладено — ліцензійність/кешування favicon'ів
  лишаються відкритими; Cargo-фічу `Storage_Streams` додамо разом з FR-6.
