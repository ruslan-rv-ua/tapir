# Ручне тестування — Фаза 1 (MVP: Core Recording)

## Передумови

- Білд: `just build-fast` → `src-tauri\target\release-fast\tapir.exe`
- Тестові потоки: див. [test-streams.md](test-streams.md)
- Перевірка тегів: mp3tag, foobar2000, або `ffprobe`
- Скрінрідер: NVDA (рекомендовано), JAWS або Narrator
- ОС: Windows 11

> Перед кожним сценарієм видалити папку `data/` поряд з exe, якщо не зазначено інше.

---

## 1. Перший запуск

- [x] 1.1 Запустити `tapir.exe` → вікно з'являється за 1–3 секунди
- [x] 1.2 Перевірити `data/` → створено: `data/settings.json`, `data/profiles/Default.tapirprofile`, `data/recordings/`, `data/logs/`
- [x] 1.3 Перевірити мову інтерфейсу → якщо системна локаль «uk-*» → українська, інакше → англійська
- [x] 1.4 Перевірити `settings.json` → `language` відповідає визначеній мові; `activeProfile` = `"Default"`
- [x] 1.5 Перевірити інтерфейс → порожній стан: «Потоків ще немає», кнопка «Додати потік» з автофокусом
- [x] 1.6 NVDA: оголошення → «Ласкаво просимо до Tapir. Натисніть Enter щоб додати перший потік.» (assertive)

## 2. Додавання потоку

- [x] 2.1 Натиснути «Додати потік» → діалог з полями URL і Назва; фокус на URL
- [x] 2.2 Ввести URL: `https://ice2.somafm.com/groovesalad-128-mp3` → поле приймає введення
- [x] 2.3 Натиснути «Зберегти» → діалог закривається; потік з'являється у таблиці; тост «Потік додано: {назва}»
- [x] 2.4 Перевірити таблицю → стовпці: статус (Очікування), назва, трек (—), бітрейт (—)
- [x] 2.5 Перевірити профіль → у `Default.tapirprofile` присутній потік з полями `id`, `url`, `name`, `addedAt`
- [x] 2.6 Escape під час діалогу → діалог закривається без збережень
- [x] 2.7 Порожній URL + «Зберегти» → валідація: показано помилку, діалог не закривається

### 2A. Додавання через PLS/M3U

- [x] 2A.1 Додати PLS URL (наприклад, SomaFM .pls) → URL резолвиться до прямого потоку; потік додано
- [x] 2A.2 Додати M3U URL → аналогічно, URL резолвиться

## 3. Запис потоку

- [x] 3.1 Натиснути «Почати запис» → статус: Очікування → Підключення → Запис
- [x] 3.2 Перевірити таблицю → «Трек» показує «Виконавець — Назва»; бітрейт заповнений (напр. 128 kbps)
- [x] 3.3 Перевірити файлову систему → у `data/recordings/{Станція}/` з'являються файли
- [x] 3.4 Зачекати зміну треку → новий файл створюється; попередній перейменований (без `_incomplete`)
- [ ] 3.5 Перевірити теги файлу → ID3v2: Artist, Title, Album = назва станції
- [x] 3.6 Натиснути «Зупинити запис» → статус → Очікування; файл фіналізований
- [x] 3.7 NVDA: запуск запису → «Запис розпочато: {назва}» (polite); тост (success)
- [x] 3.8 NVDA: зупинка запису → «Запис зупинено: {назва}» (polite)
- [x] 3.9 NVDA: зміна треку → стовпець «Трек» оновлюється; окреме оголошення НЕ реалізовано

## 5. Видалення потоку

- [x] 5.1 Натиснути «Видалити» на потоці (Очікування) → діалог підтвердження: «Видалити потік "{назва}"?»
- [x] 5.2 Підтвердити видалення → потік зникає з таблиці; тост «Потік видалено: {назва}»
- [x] 5.3 Скасувати видалення → потік залишається
- [x] 5.4 Видалити потік під час запису → запис зупиняється, потім потік видаляється
- [x] 5.5 NVDA: видалення → тост «Потік видалено: {назва}» (info) зачитується через aria-live
- [x] 5.6 Натиснути Delete на виділеному рядку таблиці → діалог підтвердження; підтвердити → потік видалено

## 7. Іменування файлів

- [x] 7.1 Записати потік; зачекати трек з метаданими → файл: `{Станція}/{Виконавець} - {Назва}.mp3`
- [x] 7.2 Заборонені символи в метаданих (`: * ? "`) → замінені на `_` у імені файлу
- [ ] 7.3 Колізія імен (той самий трек ще раз) → файл: `{назва}_2.mp3`, потім `_3.mp3`
- [x] 7.4 Файл `_incomplete` під час запису → існує; після фіналізації перейменований
- [ ] 7.5 Auto-correct case → `"artist - title"` → `"Artist - Title"` (якщо `autoCorrectCase: true`)

## 8. Мережеві помилки та перепідключення

## 10. Доступність (Accessibility)

### 10A. Навігація клавіатурою

- [ ] 10A.1 Tab від Activity Bar → фокус переходить на таблицю потоків
- [ ] 10A.2 Arrow Up/Down у таблиці → переміщення між рядками
- [ ] 10A.3 Tab у Activity Bar → переміщення між кнопками секцій (disabled кнопки пропускаються)
- [x] 10A.4 Tab у діалозі → фокус між полями і кнопками; не виходить за межі діалогу
- [x] 10A.5 Focus-visible індикатори → видимий outline на всіх кнопках при Tab-навігації
- [x] 10A.6 Delete key на виділеному рядку → діалог підтвердження видалення

### 10B. Скрінрідер (NVDA)

- [ ] 10B.1 Activity Bar → «Головна навігація», кнопки з назвами секцій
- [ ] 10B.2 Вимкнена секція (Браузер) → зачитується як disabled; `aria-description` «Буде доступно у Фазі 2»
- [ ] 10B.3 Таблиця потоків → зачитується як grid/table; заголовки стовпців; рядки з даними
- [ ] 10B.4 Checkbox у таблиці → aria-label: «Вибрати потік: {назва}»
- [ ] 10B.5 Кнопки дій → усі мають aria-label: «Почати запис», «Зупинити запис», «Видалити», «Редагувати»
- [ ] 10B.6 Status bar → зачитується кількість записів (role="status")
- [ ] 10B.7 Тости → зачитуються через aria-live="polite"
- [ ] 10B.8 Порожній стан → заголовок, опис; кнопка з автофокусом
- [ ] 10B.9 `<main>` landmark → скрінрідер розпізнає контент-зону як main region
