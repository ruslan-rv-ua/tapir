# Ручний прогін з NVDA: розрізнення однакових імен потоків

Цей чекліст приймає P0 `stream-name-disambiguation` — авто-суфікс імені при
колізії, попередження про дубль URL і про зайняте ім'я, і те, що `%s` бере ім'я
з профілю, а не сире ICY-ім'я з сервера.

Автотести (703 vitest + 425 cargo) покривають логіку, але не покривають те, як
це звучить. Саме це й перевіряємо тут: чи розрізняються на слух рядки з
однаковою назвою станції, і чи чутно кожне попередження.

Запис беклогу: `docs/backlog/done/p0-stream-name-disambiguation.md`.
Правило іменування: `docs/data-models.md`, розділ 3.1.

## Як користуватись цим файлом

Кожен пункт — одна дія і те, що має статись. Позначай прямо у файлі:

- `- [ ]` ще не перевірено
- `- [x]` перевірено, поведінка правильна
- `- [!]` перевірено, поведінка НЕ така — опиши в рядку «Нотатки» під сценарієм

Сценарії пронумеровані і незалежні один від одного, окрім сценарію 12 (запис у
дві теки) — йому потрібні потоки, додані в сценарії 2 або 5. Решту можна робити
в будь-якому порядку і зупинятись де завгодно.

Навігація NVDA: заголовки другого рівня — клавіша `2`, список усіх сценаріїв —
`NVDA+F7`, далі «Заголовки». Таблиць у файлі немає навмисно.

## Підготовка

- [ ] Зроби копію активного профілю з теки `data/profiles` — прогін додає
      близько десятка потоків, і відкотитись копією швидше, ніж чистити руками.
- [ ] Створи новий порожній профіль для прогону (Alt+0, «Створити профіль») —
      так колізії імен видно чисто, без наявних станцій.
- [ ] Перевір, що шаблон імені файлу — типовий `%s\%a - %t` (Ctrl+, → Запис).
      Саме `%s` перетворюється на теку, і саме його перевіряє сценарій 12.
- [ ] Знайди теку записів: типово `recordings` поруч із `tapir.exe`.
- [ ] Увімкни в NVDA режим мовлення (не брайль-онлі) — частина перевірок про те,
      що саме проговорюється.

Комбінації, що знадобляться: Alt+1 — Потоки, Alt+2 — Браузер станцій,
Ctrl+N — додати потік, F2 — редагувати рядок, Shift+F10 — меню рядка,
Ctrl+Enter — почати або зупинити запис рядка, F6 — перехід між зонами.

## Сценарій 1. Рядок браузера озвучує кодек і бітрейт

Навіщо: у BBC Radio 6 Music шість однойменних варіантів. До додавання їх можна
розрізнити тільки за кодеком і бітрейтом, тож вони мають бути в назві рядка.

- [x] Alt+2, знайди у пошуку `BBC Radio 6 Music` (або `Groove Salad`) —
      результати з'являються, NVDA повідомляє їх кількість.
- [x] Стрілкою вниз пройди кілька рядків — кожен рядок читається як
      «назва, країна, кодек, бітрейт kbps, жанр», а не просто «назва».
- [x] Знайди два рядки з однаковою назвою і переконайся, що на слух вони
      відрізняються — різним кодеком або бітрейтом.
- [x] Рядок, де каталог не знає кодека чи бітрейта, читається без порожніх
      «пробілів» — відсутні дані просто пропущені, а не озвучені як кома-кома.

## Сценарій 2. Два варіанти однієї станції з браузера дістають різні імена

Навіщо: головний сценарій фічі. Другий варіант має отримати суфікс автоматично.

- [x] Alt+2, знайди `Groove Salad`. Додай перший варіант (Enter на рядку) —
      NVDA каже «Станцію «…» додано».
- [x] Додай другий варіант із такою самою назвою, але іншим кодеком чи
      бітрейтом — теж повідомляє про додавання.
- [x] Alt+1, пройди список потоків — другий потік читається з суфіксом на
      кшталт «(AAC 64k)» або «(MP3 128k)», перший лишився без суфікса.
- [x] Суфікс звучить природно: чути кодек і бітрейт як частину назви, без
      літерного проговорювання дужок і без «кей» окремим словом, що збиває.
- [x] Обери в браузері кілька однойменних варіантів разом і додай їх однією
      дією (виділення + «Додати вибрані») — усі отримали різні імена, жодні два
      не збіглися.
- [x] Якщо два варіанти мали ІДЕНТИЧНІ кодек і бітрейт — другий отримав
      «(AAC 64k) (2)», тобто порядковий поверх інформативного суфікса.

## Сценарій 3. Повторне додавання вже доданої станції озвучується

Навіщо: раніше натискання Enter на вже доданій станції не робило нічого і
нічого не казало — для незрячого це просто «застосунок мовчить».

- [x] Alt+2, знайди станцію, яку щойно додав у сценарії 2. Її рядок читається
      як доданий (кнопка додавання позначена «Додано»).
- [x] Натисни Enter на цьому рядку — NVDA каже «Станція «…» вже додана».
- [x] Перевір, що другий запис із тим самим URL НЕ з'явився: Alt+1, кількість
      потоків не змінилась.

## Сценарій 4. Потік, доданий без імені, одразу дістає людську назву

Навіщо: раніше такий потік лежав у списку своїм URL і читався як URL — аж до
першого запису. Тепер ім'я береться з ICY одразу при додаванні.

- [x] Alt+1, Ctrl+N. Встав у поле «URL потоку»
      `https://ice5.somafm.com/groovesalad-128-mp3`, поле «Назва (опціонально)»
      лиши порожнім, збережи.
- [x] Під час перевірки чути «Перевіряю потік…», далі діалог закривається.
- [x] У списку потоків новий рядок читається назвою станції
      (щось на кшталт «SomaFM: Groove Salad»), а не URL-ом.
- [x] Тепер додай без імені `https://somafm.com/groovesalad130.pls` — це та сама
      станція іншим кодеком, подана через PLS-плейліст.
- [x] Другий рядок читається тією самою назвою, але з суфіксом — наприклад
      «SomaFM: Groove Salad (AAC 128k)».

## Сценарій 5. Введене вручну ім'я, що збігається з наявним, дістає суфікс

Навіщо: те саме правило, але коли назву друкує користувач, а не станція.

- [x] Alt+1, Ctrl+N. URL — `https://ice6.somafm.com/indiepop-128-aac`,
      у поле назви впиши ім'я, яке вже є в списку (скопіюй його з наявного рядка).
- [x] Збережи — діалог закривається без помилки і без питань.
- [x] Новий рядок читається з суфіксом за кодеком і бітрейтом; наявний рядок
      не змінився.
- [x] Впиши ім'я, що відрізняється лише регістром від наявного (наприклад
      усе великими) — суфікс усе одно додано, бо тека на диску була б та сама.

## Сценарій 6. Недоступний потік дістає порядковий суфікс

Навіщо: коли probe не вдався, кодек і бітрейт невідомі, тож суфікс має бути
просто числом — і чесно лишитись числом назавжди.

- [x] Alt+1, Ctrl+N. URL — `http://127.0.0.1:9/nope`, у поле назви впиши ім'я,
      яке вже зайняте наявним потоком.
- [x] Збережи — замість збереження чути попередження «Потік не відповів —
      можливо, він недоступний. Ви все одно можете його додати.»
- [x] Фокус САМ опинився на кнопці, і NVDA сказав «Все одно додати, кнопка» —
      без жодного Tab чи Shift+Tab з твого боку.
- [x] Натисни пробіл або Enter одразу, не шукаючи кнопку — потік додано з
      порядковим суфіксом «(2)», а не з кодеком.

## Сценарій 7. Дубль URL попереджає, але не забороняє

Навіщо: URL — це ідентичність потоку, тож про повтор треба сказати; але
заборони немає, бо той самий URL може знадобитись з іншими обліковими даними.

- [x] Alt+1, Ctrl+N. Встав URL потоку, який уже є в профілі (скопіюй з рядка
      через Shift+F10 → «Копіювати URL»). Збережи.
- [x] Чути попередження «Цей URL уже є в профілі — потік «…». Ви все одно
      можете додати його.» — і в ньому названо саме той потік, що вже є.
- [x] Потік НЕ збережено: діалог лишився відкритим.
- [x] Фокус САМ опинився на кнопці, і NVDA сказав «Все одно додати, кнопка» —
      без жодного Tab чи Shift+Tab з твого боку.
- [x] Натисни пробіл або Enter одразу, не шукаючи кнопку — тепер потік додано.
      Повторної перевірки доступності не було (не чути «Перевіряю потік…» вдруге).
- [x] Зміни URL у полі на інший — попередження зникає, не лишається висіти.

Нотатки:

## Сценарій 8. Перейменування на зайняте ім'я попереджає, але не забороняє

Навіщо: явний вибір користувача поважається. Застосунок лише каже, чим це
обернеться — два потоки писатимуть в одну теку.

- [x] Alt+1, стань на потік, F2 — відкривається «Редагувати потік», фокус у полі
      назви.
- [x] Впиши ім'я іншого наявного потоку, збережи — чути «Це ім'я вже використовує
      потік «…» — записи підуть в одну теку.»
- [x] Зміни не збережено, діалог лишився відкритим.
- [x] Фокус САМ опинився на кнопці, і NVDA сказав «Все одно зберегти, кнопка» —
      без жодного Tab чи Shift+Tab з твого боку.
- [x] Натисни пробіл або Enter одразу — ім'я збережено ТОЧНО як введено,
      без жодного суфікса.
- [x] Відкрий F2 знову і переконайся, що в списку тепер справді два потоки з
      однаковим іменем — застосунок їх не «полагодив» самовільно.
- [x] Поверни потоку унікальне ім'я, щоб не заважало далі.

Нотатки:

## Сценарій 9. Кнопка «Використати офіційну назву»

Навіщо: доступ до назви, яку віддає сама станція, без прихованих
автоперейменувань.

- [x] Стань на потік, доданий у сценарії 4 (він уже знає свою ICY-назву), F2.
- [x] Перейменуй його вручну на щось своє, збережи.
- [x] Відкрий F2 ще раз — у діалозі є блок «Отримана від станції назва: …»
      і кнопка «Використати офіційну назву».
- [x] Кнопка досяжна табом і читається NVDA як кнопка з цим текстом.
- [x] Натисни її — поле назви заповнилось офіційною назвою, а сам блок зник
      (бо тепер поле і офіційна назва збігаються).
- [x] Збережи. Якщо офіційна назва зайнята іншим потоком, спрацювало те саме
      попередження зі сценарію 8 — і «Все одно зберегти» його приймає.
- [x] Тепер додай будь-який потік, який ще жодного разу не підключався
      (наприклад через сценарій 6, з «Все одно додати»), і відкрий йому F2 —
      блоку з офіційною назвою НЕМАЄ, бо станція нічого не повідомила.

## Сценарій 10. Імпорт плейліста з однаковими назвами

Навіщо: плейліст, де перелічені всі mountpoints однієї станції, — типове
джерело дублів. Колізії треба ловити і проти профілю, і всередині партії.

Створи файл `test-same-name.m3u` будь-де на диску з таким вмістом:

```
#EXTM3U
#EXTINF:-1,Radio Test
https://ice5.somafm.com/seventies-320-mp3
#EXTINF:-1,Radio Test
https://ice6.somafm.com/u80s-128-mp3
#EXTINF:-1,Radio Test
http://ice.bassdrive.net/stream32
```

- [x] Alt+1, натисни «Імпорт…» (або Ctrl+K → «Імпортувати потоки…»),
      обери створений файл.
- [x] Діалог імпорту озвучує прогрес перевірки, далі підсумок
      «N працюють, N з помилкою, N вже в профілі».
- [x] Натисни «Імпортувати вибрані (3)» — чути «Імпортовано: 3, пропущено: 0».
- [x] У списку потоків усі три рядки читаються по-різному: одне «Radio Test»
      і два з суфіксами за кодеком і бітрейтом.
- [x] Імпортуй той самий файл ще раз — усі три рядки позначені «вже в профілі»,
      нічого не додано, жодне ім'я не зайняте «про запас».

Нотатки:

## Сценарій 11. Запис двох варіантів дає дві окремі теки

Навіщо: це та поламка, заради якої все робилось. Раніше `%s` брав ICY-ім'я з
сервера, тож обидва mountpoints писали в одну теку.

- [x] Alt+1, стань на перший варіант станції з сценарію 2 або 4, Ctrl+Enter —
      запис почався, стан рядка це озвучує.
- [x] Стань на другий варіант тієї ж станції, Ctrl+Enter — теж пише.
- [x] Дай обом попрацювати хоча б до першої зміни треку (кілька хвилин).
- [x] Зупини обидва записи (Ctrl+Enter на кожному).
- [x] Відкрий теку `recordings` — там ДВІ окремі підтеки, названі за іменами
      потоків: одна без суфікса, друга з суфіксом у назві.
- [x] У назві теки двокрапка з ICY-імені замінена підкресленням — це нормально
      («SomaFM: Groove Salad» стає «SomaFM_ Groove Salad»), Windows не дозволяє
      двокрапку в імені теки.
- [x] Жодного файлу не перезаписано: якщо обидва потоки писали той самий трек,
      це два файли у двох різних теках.

Нотатки:

## Сценарій 12. Наявні імена ніколи не змінюються самі

Навіщо: ім'я — це тека на диску. Ім'я, що змінилось саме по собі, ламає
попередні записи і бреше скрінрідеру.

- [x] Запиши десь ім'я потоку, який дістав порядковий суфікс «(2)» у сценарії 6.
- [x] Виправ йому URL на робочий (F2 не редагує URL — видали потік і додай
      заново з тим самим іменем, або просто візьми будь-який потік із «(2)»).
- [x] Запусти йому відтворення або запис, щоб застосунок дізнався кодек і
      бітрейт.
- [x] Перевір ім'я в списку — воно ЛИШИЛОСЬ з «(2)». Суфікс не «покращився»
      до «(AAC 64k)».
- [x] Перезапусти застосунок, знову перевір список — жодне ім'я не змінилось
      при завантаженні профілю.
- [x] Переключись на свій звичайний профіль (Alt+0) — якщо там були потоки з
      однаковими іменами до цього прогону, вони так і лишились однаковими.
      Стара база не мігрується, і це правильно.

## Після прогону

- [ ] Поверни активним свій робочий профіль, тестовий можна видалити.
- [ ] Прибери тестові записи з теки `recordings`.
- [ ] Якщо всі пункти `- [x]` — познач фічу прийнятою в

Загальний висновок прогону:
