# Ручне тестування — Фаза 2 (Player subsystem)

## Передумови

- Білд: `just build-fast` → `src-tauri\target\release-fast\tapir.exe`
- Тестові потоки: див. [test-streams.md](test-streams.md)
- Тестові файли: кілька `.mp3` і `.aac` файлів на диску (можна взяти записане Фазою 1)
- Скрінрідер: NVDA (рекомендовано), увімкнений перед запуском `tapir.exe`
- Аудіо: навушники або колонки, гучність ОС > 0
- ОС: Windows 11

> Знімок стану перед сесією: `data/profiles/Default.tapirprofile` — скопіювати якщо хочеш повернутися.
> Потоки з Фази 1 вже мають бути в профілі. Якщо немає — додати хоча б один перед початком.

---

## 1. Запуск і початковий стан PlayerPanel

- [ ] 1.1 Запустити `tapir.exe` → PlayerPanel відображається у нижній частині вікна (footer між StreamTable і StatusBar)
- [ ] 1.2 PlayerPanel завжди видима незалежно від вмісту вище
- [ ] 1.3 Кнопки Play/Pause і Stop — відображаються і мають вигляд disabled (opacity знижена)
- [ ] 1.4 Поле назви треку (source label) — порожнє
- [ ] 1.5 VolumeSlider — відображається справа; позиція відповідає збереженому значенню у профілі
- [ ] 1.6 NVDA: Tab до PlayerPanel → «Програвач, допоміжний орієнтир» (role="complementary")
- [ ] 1.7 NVDA: Tab по кнопках → «Відтворити, кнопка, недоступна» / «Зупинити, кнопка, недоступна»

---

## 2. Відтворення live-потоку

- [ ] 2.1 Натиснути «Почати відтворення» на потоці (або обрати через контекст-меню / IPC) → PlayerPanel: кнопка Play змінюється на Pause; source label показує назву станції
- [ ] 2.2 Аудіо чутно через динаміки/навушники за 1–3 секунди
- [ ] 2.3 PlayerPanel: відображається ProgressBar з анімацією (live-індикатор, не seekable)
- [ ] 2.4 SeekSlider відсутній — замість нього ProgressBar (isIndeterminate)
- [ ] 2.5 NVDA: при старті відтворення потоку → assertive: «Відтворення: {назва станції}»
- [ ] 2.6 Кнопки Pause і Stop тепер активні (opacity повна)
- [ ] 2.7 Паралельний запис: запустити запис того ж потоку → обидва (запис + відтворення) працюють одночасно; статус у таблиці → «Запис»; аудіо не переривається
- [ ] 2.8 Паралельний запис: запустити запис іншого потоку → аудіо відтворення не переривається

---

## 3. Пауза і відновлення (live-потік)

- [ ] 3.1 Натиснути Pause → аудіо зупиняється; кнопка змінюється на Play (стан: Paused)
- [ ] 3.2 NVDA: «Відтворення призупинено» (assertive)
- [ ] 3.3 Натиснути Play (відновити) → аудіо відновлюється з місця паузи або починає зі свіжого буфера
- [ ] 3.4 NVDA: «Відтворення відновлено» (assertive)
- [ ] 3.5 Source label залишається видимим під час паузи

---

## 4. Зупинка відтворення (live-потік)

- [ ] 4.1 Натиснути Stop → аудіо зупиняється; кнопки Pause і Stop стають disabled; source label очищається
- [ ] 4.2 NVDA: «Відтворення зупинено» (assertive)
- [ ] 4.3 ProgressBar (live-індикатор) зникає
- [ ] 4.4 Після Stop — можна запустити відтворення знову (2.1–2.6)

---

## 5. Обрив live-потоку (stream disconnect)

- [ ] 5.1 Відключити мережу (Wi-Fi off або заблокувати хост у firewall) під час live playback
- [ ] 5.2 Протягом ≤5 секунд: PlayerPanel переходить у стан Stopped (кнопки disabled, source label очищено)
- [ ] 5.3 NVDA: «Відтворення зупинено» (assertive) — анонс від backend-події, не від кнопки
- [ ] 5.4 Відновити мережу → можна знову запустити відтворення

---

## 6. Відтворення MP3-файлу

- [ ] 6.1 Запустити відтворення `.mp3` файлу (через IPC `play_file` або передбачений UI-тригер)
- [ ] 6.2 Аудіо чутно; source label показує ім'я файлу (без повного шляху)
- [ ] 6.3 SeekSlider відображається (замість ProgressBar); значення position починає зростати
- [ ] 6.4 NVDA: assertive «Відтворення: {ім'я файлу}»
- [ ] 6.5 SeekSlider заповнюється пропорційно до тривалості файлу
- [ ] 6.6 PlayerPanel отримує `player-progress` події кожну ≈1 секунду; position оновлюється

---

## 7. Seek (перемотка файлу)

- [ ] 7.1 Перетягнути SeekSlider мишею до середини → аудіо починає відтворюватися з нового місця (після відпускання)
- [ ] 7.2 Keyboard: Tab до SeekSlider → фокус на ньому → `→` → перемотка на +5 секунд; `←` → -5 секунд
- [ ] 7.3 `Home` → позиція 0:00; `End` → кінець файлу (відтворення завершується або зупиняється)
- [ ] 7.4 NVDA: при переміщенні SeekSlider стрілками → оголошує «{хв} хв {с} сек» (aria-valuetext)
- [ ] 7.5 Seek під час паузи → позиція оновлюється; відновлення після → аудіо з нової позиції
- [ ] 7.6 SeekSlider не доступний для live-потоку (не відображається)

---

## 8. Природне завершення файлу

- [ ] 8.1 Дочекатися завершення файлу (або seekнути на `End`) → PlayerPanel переходить у Stopped
- [ ] 8.2 NVDA: «Відтворення зупинено» (assertive) — тригер від backend події (не від кнопки Stop)
- [ ] 8.3 Source label очищається; кнопки disabled

---

## 9. Відтворення AAC-файлу

- [ ] 9.1 Запустити відтворення `.aac` / `.m4a` файлу → аудіо чутно (symphonia підтримує LC-AAC)
- [ ] 9.2 SeekSlider відображається і функціонує (seek працює)
- [ ] 9.3 HE-AAC (зазвичай 32–64 kbps потоки): відтворення повертає помилку → тост «Формат не підтримується (HE-AAC)»

---

## 10. Гучність (VolumeSlider)

- [ ] 10.1 Перетягнути VolumeSlider → гучність змінюється після відпускання (onChangeEnd)
- [ ] 10.2 Keyboard: Tab до VolumeSlider → `→` → гучність +1%; `←` → -1%
- [ ] 10.3 Keyboard: `Home` → гучність 0%; `End` → гучність 100%
- [ ] 10.4 NVDA: при зміні VolumeSlider стрілками → оголошує «{N}%» (aria-valuetext на SliderThumb)
- [ ] 10.5 Перезапустити програму → VolumeSlider відображається на тому ж рівні (збережено у профілі)
- [ ] 10.6 Перевірити `Default.tapirprofile` → `playerSession.volume` відповідає встановленому рівню (0.0–1.0)

---

## 11. Вибір аудіо-пристрою

> Потрібно два аудіо-виходи: наприклад, навушники та колонки, або фізичний вихід і HDMI.

- [ ] 11.1 Відкрити налаштування → побачити список доступних аудіо-пристроїв (`list_output_devices`)
- [ ] 11.2 Під час відтворення: обрати інший пристрій → відтворення зупиняється; аудіо перемикається на новий пристрій
- [ ] 11.3 Запустити відтворення знову → аудіо йде через обраний пристрій
- [ ] 11.4 Перезапустити програму → обраний пристрій залишається (збережено у `settings.json`)
- [ ] 11.5 Перевірити `settings.json` → `outputDevice` відповідає обраному пристрою

## 12. Збереження стану між сесіями

- [ ] 12.1 Встановити гучність на 60% → закрити програму → відкрити знову → VolumeSlider на 60%
- [ ] 12.2 Перевірити `Default.tapirprofile` → `playerSession.volume ≈ 0.6`
- [ ] 12.3 Встановити гучність на 0% → закрити → відкрити → VolumeSlider на 0% (беззвучний)
- [ ] 12.4 Обрати пристрій → закрити → відкрити → той самий пристрій обрано (або default якщо пристрій зник)

- [ ] 13.2 `playerSession.volume` записаний у профіль після закриття
- [ ] 13.3 Запустити file playback → закрити → програма завершується коректно

## 14. Клавіатурна навігація (Tab-order)

- [ ] 14.1 Tab від останнього елемента StreamTable → фокус переходить у PlayerPanel
- [ ] 14.2 Tab всередині PlayerPanel: Play/Pause → Stop → SeekSlider (якщо є) → VolumeSlider
- [ ] 14.3 Усі інтерактивні елементи PlayerPanel мають видимий focus-visible outline (синє кільце)
- [ ] 14.4 Disabled кнопки (Play/Pause, Stop) — НЕ отримують фокус Tab (пропускаються)
- [ ] 14.5 Escape у PlayerPanel → фокус повертається у StreamTable (не залишається у PlayerPanel)
- [ ] 14.6 Ctrl+K (Command Palette) відкривається і закривається коректно — PlayerPanel не перехоплює Escape

## 15. NVDA — доступність (повна перевірка)

### 15A. Стани кнопок

- [ ] 15A.1 Кнопки disabled → NVDA оголошує «кнопка, недоступна»; Space/Enter не спрацьовує
- [ ] 15A.2 Кнопка Play (активна) → NVDA: «Відтворити, кнопка»
- [ ] 15A.3 Кнопка Pause (активна) → NVDA: «Пауза, кнопка»
- [ ] 15A.4 Кнопка Stop (активна) → NVDA: «Зупинити, кнопка»
- [ ] 15A.5 Іконки всередині кнопок → не зачитуються окремо (aria-hidden={true})

### 15B. Source label

- [ ] 15B.1 Під час відтворення source label оновлюється; NVDA зачитує нове значення (aria-live="polite")
- [ ] 15B.2 Source label для потоку → назва станції; для файлу → ім'я файлу (без шляху)

### 15C. SeekSlider

- [ ] 15C.1 NVDA: «Позиція відтворення, повзунок, {хв} хв {с} сек»
- [ ] 15C.2 При переміщенні стрілками → NVDA оновлює aria-valuetext (наприклад «0 хв 15 сек»)
- [ ] 15C.3 SeekSlider не відображається для live-потоку (NVDA не може на нього потрапити)

### 15D. VolumeSlider

- [ ] 15D.1 NVDA: «Гучність, повзунок, {N}%»
- [ ] 15D.2 При переміщенні стрілками → NVDA оновлює значення («50%», «51%» тощо)

### 15E. Live-анонси подій

| Подія | Очікуване оголошення |
|---|---|
| Play (потік) | «Відтворення: {назва}» (assertive) |
| Play (файл) | «Відтворення: {ім'я файлу}» (assertive) |
| Pause | «Відтворення призупинено» (assertive) |
| Resume | «Відтворення відновлено» (assertive) |
| Stop (кнопка) | «Відтворення зупинено» (assertive) |
| Stop (обрив потоку) | «Відтворення зупинено» (assertive) |
| Stop (кінець файлу) | «Відтворення зупинено» (assertive) |

- [ ] 15E.1–15E.7 Перевірити кожен рядок таблиці вище

## Відомі обмеження (не тестувати як баги)

| Обмеження | Деталі |
|---|---|
| HE-AAC не підтримується | symphonia не декодує HE-AAC; відображається тост з поясненням |
| Live seek | Seek для live-потоків заблокований на рівні UI (відображається ProgressBar) і backend |
| VolumeSlider реагує після відпускання | Гучність змінюється на `onChangeEnd`, не під час перетягування — свідоме рішення для уникнення зайвих збережень |
