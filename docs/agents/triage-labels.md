# Мітки triage

Скіли оперують п'ятьма канонічними ролями triage. Трекер цього репозиторію —
локальний markdown ([`issue-tracker.md`](issue-tracker.md)), тож міток як таких
немає: роль кодується **полями YAML front-matter** запису беклогу. Другий словник
станів поверх наявного не заводимо.

| Роль у скілах    | У беклозі Tapir                | Зміст                                              |
| ---------------- | ------------------------------ | -------------------------------------------------- |
| `needs-triage`   | `status: draft`                | Ще формується — не брати в роботу, потрібен grooming |
| `needs-info`     | `type: research`               | Треба з'ясувати підхід/технологію/вимоги перед кодом |
| `ready-for-agent`| `status: ready` + `a11y: false`| Повністю специфіковано, агент може реалізувати сам   |
| `ready-for-human`| `status: ready` + `a11y: true` | Потребує ручного NVDA-прогону розробником            |
| `wontfix`        | `priority: P3`                 | Відкладено / під сумнівом — лише за явним тригером    |

Коли скіл згадує роль («постав мітку готовності для AFK-агента») — застосовуй
відповідну комбінацію полів front-matter, а не рядок-мітку.

## Нюанси

- **`ready-for-human` — це не «складно», а «потрібна людина».** a11y-зміни
  приймаються ручним прогоном з NVDA; агент фізично не може його зробити. Запис із
  `a11y: true` агент реалізує, але **не закриває** — приймання за людиною.
- **`type` і `status` — незалежні осі.** `type: research` + `status: ready` означає
  «дослідження можна починати», а не «код можна писати». Режим роботи задає пара
  (`type`, `status`) — див. [`backlog/README.md`](../backlog/README.md).
- **`blocked` не має аналога серед п'яти ролей.** `status: blocked` + обов'язковий
  `blocked_reason:` — сильніше за `needs-info`: чекає на зовнішню подію, а не на
  інформацію. Такий запис не брати.
- **`wontfix` ≠ видалення.** `P3` лишає запис у черзі внизу; видаляти не можна, поки
  на нього є посилання через `depends_on:`.
