# Трекер задач: локальний markdown (`docs/backlog/`)

Issues, ідеї та специфікації цього репозиторію живуть **не** в GitHub Issues, а
файлами в [`docs/backlog/`](../backlog/). GitHub-remote — `ruslan-rv-ua/tapir`.

**GitHub Issues увімкнено — як вхідна скринька, не як трекер.** Довідка веде туди
користувача, який зіткнувся з проблемою, тож місце подати повідомлення мусить бути.
Власні задачі проєкту там не заводяться й звідти не беруться: єдине їх джерело —
`docs/backlog/`. Чуже повідомлення, з якого справді виростає задача, стає звичайним
записом беклогу за правилами нижче, а не залишається жити в Issues.

Повні правила формату — [`docs/backlog/README.md`](../backlog/README.md). Цей файл
лише перекладає словник скілів (`/to-tickets`, `/triage`, `/to-spec`, `/implement`,
`/wayfinder`) на наявну конвенцію беклогу. **За розбіжності вір `backlog/README.md`.**

## Конвенції

- Один запис — один файл `docs/backlog/p<рівень>-<slug>.md` (`<рівень>` = `0`–`3`).
- **YAML front-matter — єдине джерело правди** про стан запису. Шаблон нового —
  [`_TEMPLATE.md`](../backlog/_TEMPLATE.md).
- `slug` завжди дорівнює імені файлу без префікса `p<рівень>-` і не змінюється.
  Посилання між записами — за slug'ом, не за номером.
- [`ROADMAP.md`](../backlog/ROADMAP.md) — черга, згрупована за `target` (semver).
  Підтримується вручну й може дрейфувати від front-matter.
- Виконаний запис переїжджає в [`done/`](../backlog/done/) (`git mv`, ім'я з префіксом
  не змінюється) — не видаляється, бо на нього посилаються через `depends_on:`.
- Стан triage кодується полями `status:` / `type:` / `priority:` front-matter, а не
  окремими мітками — див. [`triage-labels.md`](triage-labels.md).
- Обговорення й історія не накопичуються в файлі: змістовний висновок вписується в
  тіло запису (секції «Прийняті рішення» / «Відкриті питання» / `notes:`), а `updated:`
  ставиться на дату правки. Довговічні архітектурні рішення виносяться в
  [`docs/decisions/`](../decisions/) як ADR — див. [`domain.md`](domain.md).

## Коли скіл каже «опублікуй у трекер»

1. Створи `docs/backlog/p<рівень>-<slug>.md` за [`_TEMPLATE.md`](../backlog/_TEMPLATE.md)
   із заповненим front-matter (`priority` мусить збігатися з префіксом файлу).
2. Додай рядок запису у відповідну `target`-секцію [`ROADMAP.md`](../backlog/ROADMAP.md).

Якщо тема вже є фазою в [`implementation-phases.md`](../implementation-phases.md) —
вона живе **там**, а не в беклозі.

**Набір тікетів на одну фічу** (`/to-tickets`, `/to-spec`): один запис беклогу на
задачу, зв'язані через `depends_on:` / `blocks:`, а не один комбінований файл.
Спільний контекст фічі — або в найпершому записі ланцюжка, або окремим ADR у
`docs/decisions/`, на який решта посилається в секції «Документи».

## Коли скіл каже «візьми відповідний тікет»

Читай файл за slug'ом: спершу `docs/backlog/p*-<slug>.md`, потім
`docs/backlog/done/p*-<slug>.md`. Розробник зазвичай передає slug або шлях прямо.

Вибір наступного запису самостійно — за алгоритмом із
[`backlog/README.md` §«Алгоритм для агента»](../backlog/README.md): найменша
semver-секція ROADMAP з невиконаними записами → верхній запис зі `status: ready`.

Режим роботи диктує пара (`type`, `status`) — `idea`/`draft` → лише обговорення,
`research` → лише дослідження і звіт, `planned`+`ready` → реалізація. Не редагуй код
для запису, який не в режимі реалізації.

## Закриття запису

Три обов'язкові кроки (гейти беруться з `gates:` у front-matter):

1. front-matter: `status: done`, `completed:` = дата приймання, `updated:` = та сама дата;
2. `git mv docs/backlog/p<рівень>-<slug>.md docs/backlog/done/`;
3. перенести рядок у секцію «Виконано» [`ROADMAP.md`](../backlog/ROADMAP.md).

Для записів із `a11y: true` приймання вимагає **ручного NVDA-прогону** розробником —
агент не закриває такий запис самотужки. Чекліст створюється й видаляється за
скілом `.claude/skills/writing-nvda-checklists/`.

## Wayfinding (`/wayfinder`)

Робочий стан дослідження **не** живе в беклозі — беклог тримає лише курований,
довговічний список задач. Тимчасові карти й дочірні тікети `/wayfinder` пиши в
`.scratch/<effort>/` (додано в `.gitignore`):

- **Карта**: `.scratch/<effort>/map.md` — Notes / Decisions-so-far / Fog.
- **Дочірній тікет**: `.scratch/<effort>/issues/NN-<slug>.md`, нумерація з `01`;
  рядок `Type:` (`research`/`prototype`/`grilling`/`task`) і рядок `Status:`
  (`claimed`/`resolved`).
- **Блокування**: рядок `Blocked by: NN, NN` угорі; розблоковано, коли всі
  перелічені `resolved`.
- **Фронтир**: серед `.scratch/<effort>/issues/` — відкриті, розблоковані,
  незаявлені; перемагає найменший номер.
- **Заявка**: `Status: claimed` і збереження **до** початку роботи.
- **Розв'язання**: відповідь під заголовком `## Answer`, `Status: resolved`, потім
  вказівник (суть + посилання) у Decisions-so-far карти.

Коли дослідження дає задачу, яку справді робитимемо, — заводь повноцінний запис
беклогу за правилами вище. `.scratch/` після завершення можна видаляти.

## Зовнішні PR як джерело задач

**Вимкнено.** GitHub PR-и не потрапляють у чергу triage. Увімкни, змінивши цей
абзац, якщо в репозиторії з'являться зовнішні контриб'ютори.
