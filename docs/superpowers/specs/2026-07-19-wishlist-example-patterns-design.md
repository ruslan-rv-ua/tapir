# Приклади-патерни у порожньому стані Wishlist / Ignorelist

- **Дата:** 2026-07-19
- **Слаг беклогу:** `wishlist-example-patterns`
- **Гілка:** `feature/wishlist-example-patterns`

## Мета

Порожня вкладка Wishlist/Ignorelist зараз показує лише фразу «Список … порожній».
Новачок не бачить ані того, що це за список, ані як виглядає валідний патерн —
синтаксис `*`/`?` з'являється тільки в діалозі додавання, тобто вже після того,
як юзер здогадався натиснути «Додати».

Даємо «з чого почати»: CTA «Додати приклад» + приглушений бейдж синтаксису,
за зразком уже реалізованого порожнього стану Streams.

## Дані

Фіксований масив у коді фронту — `src/components/wishlist/examplePatterns.ts`.
Не i18n: seed однаковий для всіх локалей, бо метадані потоків диктує станція,
а не мова інтерфейсу (україномовний слухач SomaFM отримує англійські ICY-теги).

```ts
export const EXAMPLE_WISHLIST_PATTERNS = ["*новин*", "*news*"];
export const EXAMPLE_IGNORELIST_PATTERNS = [
  "*реклама*", "*джингл*", "*advert*", "*jingle*", "*promo*",
];
```

Усі патерни обгорнуті в `*…*`, бо `wildcard_match` — повнорядковий (anchored),
не підрядковий. Обгортка заодно демонструє синтаксис.

## Межі компонентів

`PatternList` отримує один новий необов'язковий проп `emptyExtra?: ReactNode`,
який рендериться всередині наявної фокусованої empty-області під `emptyMessage`.
`PatternList` нічого не знає про seed; `WishlistPanel` володіє кнопкою, викликами
tauri, оголошенням і передачею фокуса. Список лишається чистим презентером,
а логіка seed стоїть поруч з іншими add/remove-хендлерами, які вона дзеркалить.

## Хендлер seed

Один хендлер у `WishlistPanel`, параметризований `activeTab`:

1. Guard від повторного входу через стан `seeding` (кнопка лишається клікабельною
   через `aria-disabled`, як у Streams).
2. `announce` про початок.
3. Послідовні виклики `addToWishlist` / `addToIgnorelist`. Нової Rust-команди
   не додаємо — дедуплікація вже вбудована, тож повторний клік ідемпотентний.
   П'ять послідовних IPC для ignorelist трохи балакучі, але це свідомий обмін
   на відсутність нового бекенд-коду.
4. Одне оновлення стора наприкінці (не по одному на виклик).
5. Прапорець `pendingFocusFirstRow` → фокус у список.
6. `announce` результату.

Помилка → `addToast(String(err), "error")` + скидання `seeding`; фокус лишається
на кнопці, бо `aria-disabled` його не забирав.

## Фокус

Після оновлення стора список монтується. `useLayoutEffect` на
`wishlistItems`/`ignorelistItems` споживає прапорець і викликає
`patternListRef.current?.focus("forward")` — наявний хендл `ZoneEntry`,
без нового імперативного API.

## Бейдж синтаксису

Перевикористовуємо наявний ключ `pattern_hint` («Використовуйте * для будь-яких
символів, ? для одного») як звичайний `<p>` поряд із CTA. Не Tab-стоп: простий
inline-вузол, NVDA читає його в порядку документа. Той самий патерн, що
`streams_empty_palette_hint`.

## i18n

Нові ключі в `uk.json` і `en.json`, згенеровані через vite-плагін paraglide
(не вручну):

| Ключ | uk | en |
|------|----|----|
| `wishlist_add_example` | Додати приклад | Add example |
| `wishlist_examples_adding` | Додаю приклади… | Adding examples… |
| `wishlist_examples_added` | Додано приклади: {patterns} | Examples added: {patterns} |
| `wishlist_examples_failed` | Не вдалося додати приклади | Could not add examples |

**Рішення щодо оголошення:** один нерозмножений рядок зі списком патернів,
а не 4-компонентна плюралізація (`_zero/_one/_few/_many`), як у Streams.
Самі патерни несуть інформацію, а кількість чутно зі списку, у який переходить
фокус. Це вчетверо менша i18n-поверхня за ту саму користь для NVDA.

## Тести

`PatternList.test.tsx`:
- `emptyExtra` рендериться всередині empty-області;
- `emptyExtra` не рендериться, коли список непорожній.

`WishlistPanel.test.tsx`:
- CTA присутній у порожній вкладці Wishlist і в порожній Ignorelist;
- клік сіє саме `*новин*` + `*news*` у Wishlist;
- клік сіє п'ять сміттєвих патернів у Ignorelist;
- повторний клік не додає дублікатів;
- після seed фокус опиняється в списку.
