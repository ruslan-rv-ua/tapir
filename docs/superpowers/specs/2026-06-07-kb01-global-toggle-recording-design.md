# KB-01 · Глобальний `toggle_recording` — дизайн

- **Статус:** затверджено (brainstorming, 2026-06-07).
- **Бэклог:** [keyboard-shortcuts-backlog.md → KB-01](../../keyboard-shortcuts-backlog.md).
- **Реєстр клавіш:** [keyboard-shortcuts.md](../../keyboard-shortcuts.md).
- **Модель запису:** профілі — один активний профіль, «Записати все» / «Зупинити
  запис» (memory `profiles-recording-model`).

## Проблема

Глобальний OS-хоткей `Ctrl+Shift+R` (`toggle_recording`) зареєстрований, але його
обробник лише пише лог «no selected stream context» і нічого не робить
([shortcuts.rs:52-54](../../../src-tauri/src/shortcuts.rs#L52-L54)). Це справжній
**глобальний** хоткей — спрацьовує навіть коли Tapir не у фокусі (юзер працює в
іншій програмі), тож концепція «фокусованого рядка» там здебільшого недоступна.

## Узгоджені рішення

1. **Ціль хоткея:** перемикає **весь активний профіль** — `start_all` / `stop_all`
   (а не окремий рядок). Збігається з продуктовою моделлю профілів, де «Записати
   все» — головна дія, і працює незалежно від фокуса.
2. **Напрям toggle:** *будь-що активне → зупинити все*; якщо нічого не активне →
   записати все. Одне натискання гарантовано глушить усе, що пишеться.
3. **Озвучення для NVDA:** **Windows toast-сповіщення**. NVDA читає тости й коли
   застосунок у фоні, тост не краде фокус і працює з будь-яким скрінрідером.
4. **Гард stop-all:** **одразу, без підтвердження**. Зупинка не руйнівна (записане
   доті фіналізується у файл), а діалог підтвердження все одно не показати у фоні.

## §1 Архітектура

Уся логіка — в Rust, із наявного обробника глобальних шорткатів. Без фронтенду,
без IPC-раунд-тріпа, без нових залежностей (`tauri-plugin-notification` уже
підключений і AUMID зареєстрований).

```
Ctrl+Shift+R (OS global)
  → shortcuts.rs: handle_shortcut_action("toggle_recording")
      → recording_control::toggle_all(&state).await        // рішення + виконання
           active_count > 0  → manager.stop_all()              → Stopped(n)
           active_count == 0 → manager.start_all(streams,set)  → Started(n) | NothingToStart
      → notify::notify_recording_toggle(app, outcome)       // Windows toast (NVDA)
  → (manager і так емітить per-stream `recording-status` події → фронтенд оновлює
     UI і робить foreground live-region деталізацію, як для кнопки «Записати все»)
```

Тост — **авторитетне, незалежне від фокуса** оголошення (працює у фоні).
Per-stream live-region мова лишається коли Tapir у фокусі — та сама форма «summary
+ detail», що дає кнопка «Записати все», тож поведінка кнопки й хоткея однакова.

## §2 Рішення toggle (Rust)

Новий `src-tauri/src/recording_control.rs` (або функція в `stream_commands.rs`) з
чистим, юніт-тестовним ядром і тонким екзекутором:

```rust
enum ToggleOutcome { Started(usize), Stopped(usize), NothingToStart }

enum ToggleAction { Start, Stop }

// чиста — тривіально тестовна
fn decide(active_count: usize) -> ToggleAction   // Stop якщо >0, інакше Start

pub async fn toggle_all(state: &AppState) -> ToggleOutcome
```

- **«active»** = `entries` у стані `Recording | Connecting | Reconnecting`.
  Витягнути `StreamManager::active_recording_count()` і перевикористати в
  `confirm_quit_if_recording` (прибирає дубльований фільтр там). Широке означення
  (не лише `Recording`) означає, що натискання під час `connecting` скасовує
  під'єднання, а не провалюється в no-op start.
- **Stop-шлях:** зафіксувати `active_count` ДО `stop_all()` → `Stopped(active_count)`.
- **Start-шлях:** `start_all(streams, settings, mgr)` повертає кількість нових →
  `Started(n)`; якщо профіль порожній → `NothingToStart`.
- **Реюз:** наявні IPC-команди `start_all_recordings` / `stop_all_recordings`
  (кнопки) можуть делегувати в цю функцію, лише якщо лишиться чистим однорядковим
  викликом; інакше не чіпати (поза скоупом).

`Error`-станції не в `entries` (їхні таски завершились), тому `active_count` їх не
рахує, а `start_all` їх перезапускає — узгоджено з поведінкою кнопки.

## §3 Тост (оголошення)

Новий хелпер у [tray/notify.rs](../../../src-tauri/src/tray/notify.rs) за зразком
`notify_track_change`:

```rust
pub fn notify_recording_toggle(app: &AppHandle, outcome: ToggleOutcome)
```

| Outcome | Title | Body |
|---|---|---|
| `Started(n)` | `Tapir` | `Запис розпочато: {n} {потік/потоки/потоків}` |
| `Stopped(n)` | `Tapir` | `Запис зупинено: {n} {потік/потоки/потоків}` |
| `NothingToStart` | `Tapir` | `Немає потоків для запису` |

Рішення:

- **(a) Обходить `show_tray_notifications`.** Цей тост — єдиний фідбек для дії у
  фоні; гейтити його означало б, що хоткей нібито мовчки нічого не робить.
  (Track-change тости лишаються під гейтом — вони ambient.)
- **(b) Лише українські рядки**, хардкод, за наявною конвенцією `notify.rs` /
  `show_quit_confirm`. en-US нативні тости — наявний пробіл у всьому застосунку;
  поза скоупом, але структурувати рядки так, щоб пізніший `match settings.language`
  був тривіальним. Додати ~6-рядковий UK-плюрал хелпер для `потік/потоки/потоків`.
- **(c) Показувати завжди** (навіть коли у фокусі) — заради простоти й надійності.
  Альтернатива (придушити коли `window.is_focused()`) відхилена як зайва гілка.

## §4 Крайові випадки

- **Авто-повтор / утримання клавіші:** короткий (~500 мс) дебаунс в обробнику, щоб
  утримуваний `Ctrl+Shift+R` не флапав start→stop→start. Це глобальний аналог
  KB-06.
- **Порожній профіль:** `NothingToStart` → інформативний тост, без помилки.
- **Залежність KB-02:** *кастомно записане* комбо на кириличній розкладці може
  зберегтись хибно (`Ctrl+Shift+К`) і не зареєструватись — це окремий баг (KB-02).
  KB-01 перевіряється на **дефолтному** `Ctrl+Shift+R`, який зберігається коректно.
  Зафіксувати залежність, не фіксити тут.
- **Зупинка не руйнівна:** часткові записи фіналізуються при скасуванні, тож
  негайна зупинка нічого не втрачає.

## §5 Тестування й верифікація

- **Rust:** юніт-тести на `decide(active_count)` та UK-плюрал хелпер;
  `active_recording_count()` якщо менеджер можна сконструювати в тесті. Гейти:
  `cargo build` + `cargo test` (+ `cargo clippy`).
- **Frontend:** не змінюється, але прогнати стандартні гейти `pnpm test` +
  `pnpm vite:build` (події менеджера ті самі).
- **Ручна (справжня приймальня) з NVDA:**
  1. Tapir **у фокусі**, натиск → чути тост + per-stream мову, запис стартує;
  2. натиск ще раз → «Запис зупинено»;
  3. **перемкнутись в іншу програму** (Tapir у фоні), натиск → NVDA все одно читає
     тост, запис перемикається.

  Це прямо задовольняє «Готово коли: глобальний хоткей реально стартує/зупиняє
  запис за визначеним правилом цілі, з оголошенням для NVDA».
