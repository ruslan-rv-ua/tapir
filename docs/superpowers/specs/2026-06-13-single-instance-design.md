# Phase 3E — Single Instance: дизайн v1

Дата: 2026-06-13
Статус: затверджено (brainstorming-сесія), очікує план імплементації

## 1. Мета й обсяг

Запобігти одночасному запуску двох копій Tapir. Повторний запуск має:
активувати наявне вікно першої інстанції (вивести на передній план, навіть якщо
воно згорнуте або сховане в трей) і передати їй свій `argv`, після чого друга
інстанція тихо завершується.

Ключова вимога доступності: при активації NVDA має **озвучити** перехід фокусу —
а це працює лише якщо вікно стає *справжнім* OS-foreground (див. §5 і
[docs/notes/screenreader-startup-foreground.md](../../notes/screenreader-startup-foreground.md)).

**Свідомо поза 3E** (винесено):

- `clean_shutdown` / resume записів після збою → **Фаза 3K (Crash Recovery)**.
- Парсинг CLI-аргументів (`--record`, `--play`, `--datadir`, `--minimize` …) →
  **Фаза 3G**. У 3E будується лише *шов*: `argv` доходить до спільного
  обробника, але ще не інтерпретується.

## 2. Зафіксовані дизайнерські рішення (з роадмапу)

- **Ключ mutex — глобальний** (bundle identifier `ua.ruslanrv.tapir`): одна копія
  на користувача незалежно від майбутнього `--datadir`. Наслідок: `--datadir`
  (3G) діятиме лише на ПЕРШІЙ інстанції; повторний запуск з іншим `--datadir`
  передасть argv першій і вийде. Документується для 3G.
- **Плагін реєструється ПЕРШИМ**, перед усіма іншими (зокрема перед log-плагіном):
  друга (вмираюча) інстанція не повинна торкатися спільного `tapir.log`
  (стратегія ротації `KeepOne` проротувала б/затерла файл).
- **single-instance активний завжди** (dev + release), без `cfg`-гейту — щоб
  поведінку можна було перевіряти під NVDA прямо в `just dev`. Наслідок:
  `just dev` конфліктуватиме з уже запущеною встановленою копією Tapir (той
  самий глобальний ключ) — очікувано.

## 3. Архітектура

Дві нові, сфокусовані одиниці + точкові зміни в `run()`.

### 3.1 Модуль `src-tauri/src/single_instance.rs`

Інкапсулює все, що стосується single-instance і foreground-handoff.

```rust
/// Викликається НАЙПЕРШИМ у run(), до tauri::Builder. Виконується в обох
/// інстанціях. Сенс — у ДРУГІЙ (вмираючій): вона віддає право foreground, поки
/// плагін ще не виявив дублікат і не завершив процес, інакше set_focus() першої
/// інстанції буде заблоковано ОС і NVDA промовчить (foreground-handoff, §5).
/// У першій інстанції — нешкідливий no-op (вона активує власне вікно своїм же грантом).
pub fn allow_foreground_handoff() { /* AllowSetForegroundWindow(ASFW_ANY), стиль smtc.rs */ }

/// Готовий плагін для реєстрації ПЕРШИМ у ланцюжку (перед log).
pub fn plugin<R: tauri::Runtime>() -> tauri::plugin::TauriPlugin<R> {
    tauri_plugin_single_instance::init(on_second_instance)
}

/// Колбек, що виконується в ПЕРШІЙ інстанції, коли стартує друга.
/// (Друга інстанція цей код не виконує і до .setup() не доходить.)
fn on_second_instance(app: &tauri::AppHandle, argv: Vec<String>, cwd: String) {
    if let Some(w) = app.get_webview_window("main") {
        let _ = w.unminimize();   // відновити зі згорнутого
        let _ = w.show();         // показати, якщо сховане в трей
        let _ = w.set_focus();    // справжній foreground (грант віддала друга інстанція)
    }
    crate::tray::notify_state_changed(app); // меню трею: видимість змінилась
    crate::cli::handle_args(app, argv, Some(cwd)); // проксі argv → шов під 3G
}
```

Win32-виклик (`AllowSetForegroundWindow`, `ASFW_ANY`) робиться в стилі наявного
`src-tauri/src/smtc.rs`; потрібна фіча `Win32_UI_WindowsAndMessaging` вже
ввімкнена в [Cargo.toml](../../../src-tauri/Cargo.toml).

### 3.2 Модуль `src-tauri/src/cli.rs`

Шов під Фазу 3G. Зараз — лише логування, без інтерпретації.

```rust
/// Спільний обробник аргументів. Контракт для 3G: викликуваний і на старті
/// (перша інстанція, з std::env::args), і з колбека single-instance (argv другої).
/// У 3E — no-op, що лише логує. У 3G тут з'явиться clap-парсинг і диспатч.
pub fn handle_args(_app: &tauri::AppHandle, argv: Vec<String>, cwd: Option<String>) {
    log::info!("CLI args (поки не інтерпретуються, див. Фазу 3G): argv={argv:?}, cwd={cwd:?}");
}
```

### 3.3 Зміни в `src-tauri/src/lib.rs`

1. Додати `mod single_instance;` та `mod cli;`.
2. Перший рядок `run()`: `single_instance::allow_foreground_handoff();` — до
   `portable::ensure_data_dirs()` та `tauri::Builder`, щоб гарантовано виконатись
   у другій інстанції до її завершення.
3. `.plugin(single_instance::plugin())` — **першим** `.plugin(...)`, перед
   `tauri_plugin_log` (§2).
4. У `setup()` (перша інстанція): `cli::handle_args(app.handle(),
   std::env::args().collect(), None);` — виконати контракт «викликувано й на старті».

Жодних змін у `capabilities/`, Paraglide-рядках чи frontend: колбек робить
Rust-side виклики вікна (не IPC), UI в цієї фази немає.

## 4. Потік виконання

**Перша інстанція (звичайний старт):**
`run()` → `allow_foreground_handoff()` (no-op за змістом) → builder з
single-instance-плагіном першим → mutex вільний, інстанція стає «головною» →
звичайний `setup()` → `cli::handle_args(env::args)` (лог) → працює.

**Друга інстанція (повторний запуск):**
`run()` → `allow_foreground_handoff()` (**віддає foreground**) →
`ensure_data_dirs` (ідемпотентно) + `GlobalSettings::load` (читання) → builder →
**single-instance-плагін виявляє дублікат** *до* ініціалізації log-плагіна →
надсилає `argv`+`cwd` першій інстанції → процес завершується (до `.setup()` не
доходить, `tapir.log` не чіпає).

**Перша інстанція отримує сигнал:** виконується `on_second_instance` →
`unminimize → show → set_focus` (foreground шанується ОС завдяки гранту другої)
→ `notify_state_changed` → `cli::handle_args(argv другої)` (лог). NVDA озвучує
сфокусований елемент.

## 5. Foreground-handoff: чому саме так

Розглянуті варіанти:

- **A (обрано): раннє `AllowSetForegroundWindow(ASFW_ANY)` на початку `run()`.**
  Код до `tauri::Builder` виконується в обох інстанціях; друга встигає віддати
  право foreground до того, як плагін її завершить → `set_focus()` першої
  шанується, NVDA озвучує. Просто, без патчингу плагіна. Компроміс: грант
  видається на кожен запуск (мікро-вікно) — для портативного single-user
  застосунку прийнятно.
- **B (відхилено): лише `set_focus()` без гранту від другої інстанції.** ОС
  блокує `SetForegroundWindow`; вікно блимне в таскбарі, але не активується,
  NVDA мовчить. Саме те, від чого застерігає роадмап.
- **C (нежиттєздатно): хук pre-exit у другій інстанції.**
  `tauri-plugin-single-instance` виконує колбек у *першій* інстанції; у другій
  немає відкритого хука перед виходом — довелось би форкати плагін.

Контекст foreground-grant: Windows дає право вивести вікно на передній план лише
на короткий час після дії користувача (запуск). Тому грант мусить надійти від
щойно запущеної (другої) інстанції; перша сама собі його видати не може.

## 6. Тестування й приймання

- **Юніт-тести тонкі за природою фази** (OS-рівнева + мульти-процесна поведінка).
  Автоматизовано покривається лише `cli::handle_args` (не панікує на порожньому /
  довільному `argv`). Решта механіки (mutex, foreground, плагін-ордеринг) не
  юніт-тестується.
- **Основне приймання — ручна перевірка під NVDA** (розробник незрячий, тестує
  слухом), що відповідає всім Done-критеріям роадмапу:
  1. Другий запуск активує перше вікно; працює і коли воно згорнуте, і коли
     сховане в трей.
  2. NVDA озвучує активацію вікна при другому запуску (доказ справжнього
     foreground; якщо B — мовчав би).
  3. `tapir.log` не пошкоджується другим запуском (плагін-ордеринг).
  4. `argv` другого запуску з'являється в логах першої інстанції (готовність до 3G).

## 7. Відображення на Done-критерії 3E (роадмап)

| Done-критерій | Покривається |
|---|---|
| single-instance зареєстрований першим плагіном (перед log) | §3.3 п.3 |
| Другий запуск → перша інстанція `unminimize+show+set_focus`, працює і з трею | §3.1, §4 |
| NVDA озвучує активацію вікна (foreground-handoff) | §3.1 `allow_foreground_handoff`, §5 |
| argv другого запуску проксюється у спільний CLI-обробник | §3.2 `cli::handle_args`, §3.1 |
| Задокументовано: `--datadir` діє лише на першій інстанції | §2 + doc-comment біля реєстрації плагіна |

## 8. Залежності й ризики

- Нова залежність: `tauri-plugin-single-instance = "2"`. **Точну сигнатуру
  `init(...)` та назву/наявність `ASFW_ANY` у `windows = 0.62` звірити на старті
  плану** (версії API могли змінитись).
- Друга інстанція виконує `ensure_data_dirs` (ідемпотентно) і `GlobalSettings::load`
  (читання існуючого файлу) до завершення — нешкідливо; критичний для захисту
  ресурс (`tapir.log`) прикритий плагін-ордерингом.
