# Context-aware keyboard shortcuts

- **Статус:** РЕАЛІЗОВАНО частково (2026-06-08) — `Ctrl+N`→Add Stream (Streams)
  через реєстр; wishlist/profiles лишаються майбутнім.
- **Дата:** 2026-06-02
- **Тип:** ADR — архітектурне рішення про реєстрацію контекстних глобальних шорткатів

## Проблема

`Ctrl+K` і `Ctrl+,` реєструються глобально в `App.tsx` і спрацьовують з будь-якого екрана — це правильно для командної палітри та налаштувань. Але для дій, що мають сенс лише на конкретному екрані (наприклад, "додати потік"), глобальний шорткат без умови дає несподіваний ефект: користувач на екрані Songs натискає `Ctrl+N` і отримує діалог додавання потоку.

## Рішення

**Глобальний обробник в `App.tsx` з умовою на `$activeSection`.**

```ts
// e.code (фізична клавіша), не e.key — на кирилиці e.key === "n" не спрацює.
// Конвенція: docs/keyboard-shortcuts.md, accessibility.md §12.
if ((e.ctrlKey || e.metaKey) && e.code === "KeyN" && $activeSection.get() === "streams") {
  e.preventDefault();
  $showAddStreamDialog.set(true);
}
```

### Чому не в `StreamsPanel.tsx`

- `onKeyDown` на контейнері панелі ловить події лише якщо фокус всередині нього; рядки таблиці можуть мати власних обробників, що зупиняють bubbling.
- Глобальний `document` listener надійніший — той самий підхід, що вже використовується для `Ctrl+K` / `Ctrl+,`.

### Розширення на інші екрани

Той самий патерн можна застосовувати для інших контекстних шорткатів у майбутньому:

| Шорткат | Умова (`$activeSection`) | Дія |
|---------|--------------------------|-----|
| `Ctrl+N` | `"streams"` | Відкрити "Add Stream" |
| `Ctrl+N` | `"browser"` | (майбутнє) Додати до wishlist |
| `Ctrl+N` | `"profiles"` | (майбутнє) Створити профіль |

## Обмеження

- Шорткати, що залежать від `$activeSection`, не конфігуруються через Settings → Hotkeys (там лише глобальні хоткеї через `tauri-plugin-global-shortcut`). Це інший рівень.
- Якщо в майбутньому кількість контекстних шорткатів зросте, варто виокремити реєстрацію в окремий хук `useContextualShortcuts`.

## Масштабування на нові спільні combo (керівні нотатки)

> Додано 2026-06-21 за підсумком аудиту дизайну
> [docs/superpowers/specs/2026-06-21-contextual-ctrl-n-design.md](../superpowers/specs/2026-06-21-contextual-ctrl-n-design.md).
> Нотатки для майбутнього, коли реалізовуватимуть **ще** combo, спільні для кількох екранів
> (на кшталт `Ctrl+N`). Стосуються саме розширюваності патерну.

**Уточнення до прикладу вище.** Код у блоці «Рішення» (inline-`if` у `App.tsx`) — *історичний*. Реально
диспетчеризація живе в реєстрі [src/lib/shortcuts.ts](../../src/lib/shortcuts.ts): кожен запис має
`match` (яка клавіша) + `when` (на якому екрані) + `run` (дія), а `matchShortcut` повертає **перший**
запис, де `match` спрацював і `when` істинний. Глобальний слухач — [src/hooks/useGlobalShortcuts.ts](../../src/hooks/useGlobalShortcuts.ts).

### Що масштабується само (нове спільне combo НЕ чіпає ядро)

- Додати спільне combo = N записів з однаковим `match` і **взаємовиключними** `when` по
  `activeSection`. Цикл `matchShortcut` не змінюється.
- F1-довідка (`ShortcutsHelp`) і захист KeyRecorder (`RESERVED_WEBVIEW_COMBOS`) — *похідні* від
  `SHORTCUTS`, тож новий combo потрапляє в них автоматично.
- Дедуплікація за `combo` в [src/lib/reservedShortcuts.ts](../../src/lib/reservedShortcuts.ts) — це
  **узагальнення**, а не хак під `Ctrl+N`: будь-який наступний спільний combo не потребує правок у
  `reservedShortcuts.ts` і не ламає `reservedShortcuts.test.ts`.

### Ціна на КОЖНУ клітинку «combo × екран» (boilerplate)

Поточний патерn вимагає ~5 точок дотику на клітинку: (1) булевий атом-сигнал; (2) метод у
`ShortcutActions`; (3) дріт у `actions` всередині `useGlobalShortcuts`; (4) `useStore` + місток-`useEffect`
у панелі; (5) bridge-тест. Прийнятно для 1 combo×3 екрани, але **не масштабується лінійно**: на ≥2-3
майбутні спільні combo отримаєш комбінаторне розростання однотипних атомів (`$showXyzDialog`).
**Тригер до рефактору:** при появі другого-третього спільного combo — генерувати записи декларативно з
однієї таблиці `{combo, section → action}` і ввести перевикористовуваний bridge-примітив замість
атома+ефекту на кожну клітинку (пор. «виокремити `useContextualShortcuts`» вище).

### Два latent-ризики, які закрити при масштабуванні (зараз свідомо НЕ робимо — YAGNI)

1. **F1 показує дублікати рядка combo.** Help не фільтрується контекстом: з кількома спільними combo
   довідка перелічить кожен combo по разу на екран (для NVDA — шумно). Закрити контекстною фільтрацією
   help-списку, коли спільних combo стане кілька.
2. **Взаємовиключність `when` — неперевірений інваріант.** Поки гейт лише `activeSection` (одна активна
   секція) — безпечно автоматично. Щойно `ShortcutCtx` розростеться (гейт по фокусу/вкладці/виділенню),
   перекриття стане можливим, і «перший виграв» спрацює тихо. Додати тест/асерт на колізію combo тоді ж.
