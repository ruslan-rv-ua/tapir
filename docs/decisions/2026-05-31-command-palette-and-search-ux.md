# Командна палітра і пошук/фільтр — наскрізна модель та план

- **Статус:** ПРИЙНЯТО (рішення узгоджені; правки FRD, спеки й реалізація — попереду)
- **Дата:** 2026-05-31
- **Автор:** Ruslan Iskov (за результатами брейнсторму з Claude)
- **Тип:** ADR + PRD — наскрізне архітектурне рішення з поекранною політикою,
  застосуванням до екрана потоків і планом фаз
- **Заміняє:** попередні окремі чернетки `…-streams-command-search-ux-prd.md` та
  `…-command-palette-search-architecture-adr.md` (зведені сюди)

## 0. Призначення

Один документ-рішення про те, як у Tapir співіснують **командна палітра** і
**пошук/фільтр на екранах** — наскрізно (всі екрани) і конкретно (екран потоків),
плюс **послідовність реалізації фазами**.

Послідовність робіт: **цей документ → правки FRD → спеки → плани → код.**

## 1. Контекст (факти на 2026-05-31)

- **FRD трактує палітру як наскрізну, а не екранну.** Тригер за вимогами входить у
  *першу зону кожного* екрана: Streams (§7.3), Browser (§7.4.2), Wishlist (§7.6),
  Songs (§7.11.2), Schedule (§7.12.2). Сама палітра — глобальний модальний overlay
  (§7.8). Джерело: FRD-navigation.md (видалено).
- **Задумана роль палітри ширша за потоки.**
  [implementation-phases.md:68](../../implementation-phases.md#L68): «CommandPalette
  — Ctrl+K: fuzzy search **дій, станцій, пісень**». Модель Spotlight/VS Code.
- **Поточна реалізація вужча за задум:** палітра містить лише *дії над потоками*
  (add, stop-all, per-stream record/stop). Станцій і пісень у ній ще немає →
  вона недобудована, а не «лише про потоки».
- **PRD про палітру не згадує** — вона з'явилась на рівні FRD/навігації, не
  продуктових вимог. Це дає свободу переглянути її роль.
- **Палітра вже глобальна:** `Ctrl+K` ([App.tsx:132](../../../src/App.tsx#L132)),
  спільна для Streams, Wishlist, Browser. Плюс у кожній шапці є **видима кнопка
  «Команди»**, що дублює `Ctrl+K`.
- **Екрани й очікувані розміри списків:** Streams — 3–15 (мало); Browser —
  серверний пошук Radio Browser API, результати великі; Songs/файли (3C,
  реалізовано) — записані файли, **накопичуються → сотні/тисячі**;
  Wishlist, Schedule — невеликі.

## 2. Концептуальна основа

Палітра команд і пошук/фільтр — **два різні інструменти**, не дві реалізації
одного:

| | Палітра команд (Ctrl+K) | Пошук/фільтр на екрані |
|---|---|---|
| Модель | дієслово-перший: «зроби / перейди» | іменник-перший: «звузь те, що бачу» |
| Життя | ефемерна, модальна, зникає | постійна, частина сторінки |
| Охоплення | глобальна, через увесь застосунок | прив'язана до списку поточного екрана |
| Виклик | клавіатура (Ctrl+K) | завжди на екрані |
| Список | **ховає** контент під overlay | список лишається видимим, оновлюється наживо |

Провідні застосунки (VS Code, Linear, GitHub, Slack, Raycast) мають **обидва
інструменти одночасно**: палітра — глобальний прискорювач; пошук/фільтр —
локальне ітеративне звуження з видимими результатами.

## 3. Наскрізні рішення (decision log)

| # | Рішення | Обґрунтування |
|---|---------|---------------|
| DA1 | Палітра лишається **однією глобальною поверхнею** (`Ctrl+K`); поступово добудовується до задуму: дії + станції + пісні + «перейти до…» | Узгоджено з phases.md; одна стабільна ментальна модель прискорювача |
| DA2 | Палітра стає **context-aware**: першими підіймає елементи поточного екрана (на Songs — пісні, на Browser — станції) | Доповнює локальний фільтр; так роблять GitHub, Linear |
| DA3 | Наявність пошуку/фільтра **на екрані** — поекранне рішення, кероване **розміром списку й типом пошуку** (клієнтський фільтр vs серверний запит) | Уникаємо YAGNI там, де список малий; даємо потужний фільтр там, де великий |
| DA4 | Палітра **НЕ заміняє** пошук/фільтр на екрані — вони співіснують | Модалка ховає список; серверний Browser-запит не лягає в одне fuzzy-поле; передбачуваність для NVDA; стабільність ментальної моделі |
| DA5 | **Видимий тригер палітри в шапці — переглянути застосунково:** лишити `Ctrl+K`, прибрати/приглушити дублюючі кнопки на всіх екранах | Кнопка дублює `Ctrl+K`, додає Tab-стоп і шум на кожному з 5 екранів |

## 4. Поекранна політика (наслідок DA3)

| Екран | Розмір | Пошук/фільтр на екрані | Палітра |
|---|---|---|---|
| Streams | 3–15 | **Ні** (YAGNI — див. §6) | глобальна (Ctrl+K) |
| Browser | великий, серверний | **Так, обов'язково** (форма + фільтри: країна/мова/кодек/бітрейт) | глобальна, + context-aware |
| Songs/файли | росте, може бути великим | **Так** (постійний пошук/фільтр) | глобальна, + context-aware |
| Wishlist | невеликий | ймовірно ні (перевірити при реалізації) | глобальна |
| Schedule | невеликий | ймовірно ні (перевірити при реалізації) | глобальна |

## 5. Наслідки для FRD

Потребує правок FRD-navigation.md (видалено):
- §7.8.1 та згадки тригера в §7.3, §7.4.2, §7.6, §7.11.2, §7.12.2: правило
  «кнопка-тригер у першій зоні кожного екрана» переглянути на «`Ctrl+K` доступний

- Зафіксувати, що палітра **глобальна й context-aware** (DA1, DA2).
- Зафіксувати **співіснування** локального фільтра й палітри (DA4), а наявність
  локального — поекранна за DA3/таблицею §4.

## 6. Застосування: екран потоків (варіант A) → переходить у спек

Конкретний перший зріз. Принцип: екран лишається тризонним і чистим (метрики →
чипи стану → список); палітра — лише глобальний рушій `Ctrl+K`.

**Streams-рішення:**

| # | Рішення | Обґрунтування |
|---|---------|---------------|
| S1 | Поле пошуку **не додаємо** | DA3 + масштаб 3–15: список вміщається, NVDA проходить за секунди; стан уже покрито чипами |
| S2 | Прибрати кнопку «Команди» з тулбара й порожнього стану | DA5 застосовано до Streams |
| S3 | Бейдж `Ctrl+K` — **лише в порожньому стані** | Користувач уперше бачить екран порожнім; там і навчається. Населений список чистий |
| S4 | **Без `aria-keyshortcuts`** і **без перемикача в налаштуваннях** (поки що) | Відкривність несе порожній стан; уникаємо ненадійного `aria-keyshortcuts` на нефокусованому регіоні та повної settings-обв'язки |
| S5 | `Ctrl+K` (рушій) **не чіпаємо** | Працює, наскрізний |

**Конкретні зміни в коді:**
1. Прибрати `cmdBtn` з тулбара → `toolbarRefs` стає `[addBtn, stopAllBtn, chip0,
   chip1, chip2]` (5 елементів, індекси 0–4); переіндексувати чипи на
   `toolbarTabIndex(2..4)`; виправити застарілий коментар «7 items (0–6)» → «5
   items (0–4)»
   ([StreamsPanel.tsx:142-145](../../../src/components/streams/StreamsPanel.tsx#L142-L145)).
2. Прибрати кнопку «Команди» з порожнього стану → лишається лише CTA «Додати
   потік»; `emptyBtns` стає одноелементним, зона `streams-empty` спрощується.
3. Приглушений `kbd`-бейдж «Ctrl+K» поряд із CTA в порожньому стані; не Tab-стоп;
   природно в порядку читання (доступний і NVDA).

**A11y-наслідки:** менше Tab-стопів у тулбарі (6→5) і порожній зоні (2→1);
`Ctrl+K` працює як раніше.

**Тести** ([StreamsPanel.test.tsx](../../../src/components/streams/StreamsPanel.test.tsx)):
прибрати перевірки кнопки «Команди»; оновити очікувані індекси roving-focus і
кількість кнопок у порожньому стані; додати: бейдж рендериться і не фокусується,
`Ctrl+K` досі відкриває палітру.

## 7. Відкинуті альтернативи (на випадок, якщо передумаю)

- **Палітра ЗАМІСТЬ пошуку/фільтра на екрані (динамічна підміна).** Відхилено:
  (1) модалка ховає список, який фільтруєш; (2) Browser — серверний запит зі
  структурованими фільтрами, що не лягають в одне fuzzy-поле; (3) a11y/NVDA —
  постійна form-зона передбачуваніша за фокус-крадучу модалку зі змінним змістом;
  (4) `Ctrl+K`, що означає різне на кожному екрані, вчиться важче.
- **Залишити видимий тригер у шапці кожного екрана (статус-кво FRD).** Відхилено
  на користь DA5.
- **Поле пошуку/фільтра в списку потоків.** Відхилено через масштаб (3–15).
  Переглянути, якщо типова кількість потоків зросте до десятків.
- **`aria-keyshortcuts` на регіоні потоків.** Відхилено: на нефокусованому
  лендмарку NVDA озвучує ненадійно; потрібен був би й перемикач багатослівності.
- **Перемикач у налаштуваннях «оголошувати підказки».** Відхилено зараз: один
  атрибут тягне Rust+TS+UI+i18n+міграцію профілів.
- **Бейдж біля заголовка / завжди видимий.** Відхилено на користь «лише порожній
  стан».

## 8. Фази реалізації

> Принцип послідовності: спершу **дешеві наскрізні чистки** з негайним a11y-
> виграшем, потім **функціональна добудова** палітри. Правки FRD передують коду,
> який наразі їм суперечить (бо чинний FRD вимагає видимий тригер у кожній шапці).

| Фаза | Що | Залежить від | Обсяг/ризик |
|------|----|--------------|-------------|
| **Ф0** | Правки FRD-navigation.md (видалено) під DA1–DA5 (§5) | цей документ | малий, лише докс |
| **Ф1** | **Streams варіант A (пілот):** §6 — прибрати тригер з тулбара й порожнього стану, бейдж `Ctrl+K` у порожньому стані, тести | Ф0 | малий |
| **Ф2** | Застосувати чистку тригера на решті екранів: Wishlist, Browser, Songs (лишити `Ctrl+K`, прибрати/приглушити дубль; на Browser шапка вже form-зона) | Ф1 (відточений патерн) | малий–середній |
| **Ф3** | Добудова **вмісту** палітри до задуму (DA1): станції (Browser), пісні (Songs), дія «перейти до…»/навігація | — (незалежна від Ф1–Ф2) | середній |
| **Ф4** | **Context-aware** палітра (DA2): підіймати елементи поточного екрана першими (+ можливі режими-префікси `>`/`@`) | Ф3 | середній |

**Обґрунтування порядку:**
- **Ф0 перша**, бо Ф1/Ф2 прибирають видимий тригер, а чинний FRD його вимагає →
  керівний документ має бути узгоджений раніше за код.
- **Ф1 перед Ф2:** Streams — найменший і найконкретніший зріз; відточуємо патерн
  на одному екрані, далі тиражуємо.
- **Ф3 перед Ф4:** спершу наповнюємо палітру вмістом, потім ранжуємо за контекстом.
- **Ф1–Ф2 (чистка) незалежні від Ф3–Ф4 (добудова)** і пріоритетніші: дешевші й
  дають негайний UX/a11y-виграш. Добудову можна планувати пізніше або разом із
  відповідними екранами.

**Cross-cutting (не окрема фаза):** локальний пошук/фільтр за DA3/DA4
застосовується **в межах роботи над кожним екраном**. Поточний стан: Streams —
без (Ф1); Browser — є (форма+фільтри); Songs — є; Wishlist/Schedule — оцінити при
реалізації/ревізії.

## 9. Відкриті питання

1. Чим саме приглушити/замінити видимий тригер на кожному екрані (поекранно може
   відрізнятись; Browser-шапка вже form-зона з власним пошуком).
2. Чи достатньо порожнього стану як єдиного місця навчання `Ctrl+K` на Streams;
   якщо ні — повернутися до `aria-keyshortcuts` (S4).
3. Поріг «великого» списку для DA3 на Wishlist/Schedule — підтвердити при
   реалізації.
4. Обсяг context-aware (DA2): лише ранжування поточного екрана першим, чи також
   режими-префікси (`>` команди, `@` пісні) у стилі VS Code.
5. Коли добудовувати палітру до повного задуму (Ф3) — окремою фазою чи разом із
   відповідними екранами.

## 10. Джерела (галузеві патерни)

Усталені патерни «command palette vs in-page search/filter»: VS Code
(Ctrl+Shift+P / Ctrl+P + панельні фільтри), Linear (Cmd-K + in-view filters),
GitHub (context-aware command palette), Slack, Raycast; принцип розрізнення
«дія/навігація» vs «звуження списку» (NN/g). *Конкретні URL за потреби додати
окремо — не вставляв, щоб не фабрикувати адреси.*
