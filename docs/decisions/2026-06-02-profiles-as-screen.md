# Менеджер профілів — екран замість діалогу

- **Статус:** ПРИЙНЯТО (рішення узгоджені; спека й реалізація — попереду)
- **Дата:** 2026-06-02
- **Автор:** Ruslan Iskov (за результатами брейнсторму з Claude)
- **Тип:** ADR — архітектурне рішення про модель навігації для керування профілями
- **Гілка:** `feature/pahse-3F-profiles`

## 0. Призначення

Зафіксувати рішення перевести **менеджер профілів** із модального діалогу в
повноцінний **екран** (як Streams/Browser/Wishlist/Songs), визначити його місце в
головному меню та політику під-операцій.

Послідовність робіт: **цей документ → спека → план → код.**

## 1. Контекст (факти на 2026-06-02)

- **Зараз профілі — модальний діалог** `ProfileManager`, що відкривається кнопкою
  внизу ActivityBar через `$profileManagerOpen`
  ([App.tsx:317](../../../src/App.tsx#L317),
  [ActivityBar.tsx:134-148](../../../src/components/layout/ActivityBar.tsx#L134-L148)).
- **Екрани** (streams/browser/wishlist/songs) рендеряться в `<main>` за
  `$activeSection` і вбудовані в систему зональної навігації
  (`onZonesChange` / `exitZone` / `ZoneEntry`, roving-focus, передача Tab між
  зонами) ([App.tsx:296-308](../../../src/App.tsx#L296-L308)).
- **Менеджер профілів — це CRUD над колекцією:** список + дії
  (switch/rename/duplicate/delete/import/export) + підтвердження. Концептуально —
  те саме, що екран потоків, лише запхане в модалку.
- **Поточна модалка має чотири вкладені під-діалоги** з ручним z-40/z-50
  стекуванням
  ([ProfileManager.tsx:284-396](../../../src/components/profile/ProfileManager.tsx#L284-L396)).
- **Уся остання серія комітів** (`refocusList`-флаг, відновлення фокусу після
  switch/delete, focus outline на під-діалогах) — це боротьба з крихкістю саме
  модальної моделі: disabled-кнопка після дії з'їдає фокус, доводиться вручну
  повертати його в список
  ([ProfileManager.tsx:51-56](../../../src/components/profile/ProfileManager.tsx#L51-L56)).
- **Roving-focus у ActivityBar уже єдиний** на всі 7 кнопок (5 секцій +
  Settings + Profile)
  ([ActivityBar.tsx:46-49](../../../src/components/layout/ActivityBar.tsx#L46-L49));
  footer від секцій відділяє лише візуально `mt-auto`
  ([ActivityBar.tsx:117](../../../src/components/layout/ActivityBar.tsx#L117)).
- **Кнопка Profile має дворядковий вигляд** із підписом активного профілю
  ([ActivityBar.tsx:144-147](../../../src/components/layout/ActivityBar.tsx#L144-L147));
  цього немає в секцій.
- **Scope цього рішення — лише профілі.** Settings **залишається діалогом**.

## 2. Рішення (decision log)

| # | Рішення | Обґрунтування |
|---|---------|---------------|
| P1 | **Менеджер профілів стає екраном**, а не діалогом: новий запис у `Section`, рендериться в `<main>` за `$activeSection`, бере участь у зональній навігації | CRUD-над-колекцією ідентичний Streams; прибирає вкладені модалки й більшість focus-хаків; однорідна ментальна й клавіатурна модель |
| P2 | **Кнопка профілю — на самому верху головного меню**, над групою секцій, **з розділювачем** під нею | Відображає ієрархію вкладеності (профіль = контейнер, екрани = його вміст); divider не дає профілю прикидатись рівноправною першою секцією й розв'язує `aria-pressed`-семантику |
| P3 | **Launch-фокус — на активній секції**, а не буквально на першому елементі меню | Профіль угорі візуально, але звична точка входу (напр. Streams) зберігається; рідковживана дія не перехоплює стартовий фокус |
| P4 | **Дворядковий header**: зберегти вигляд «Профіль / `<назва>`» у верхній кнопці як заголовок-контекст | Як header нагорі дворядковий вигляд природний і очікуваний (на відміну від «останньої секції в списку»); ім'я активного профілю завжди видно |
| P5 | **Під-операції (create / rename / duplicate / delete / import / switch-confirm) — однорівневі діалоги** над екраном, але вже НЕ вкладені одна в одну | Менше переробки; знайомий патерн `ConfirmDialog`; прибирає z-40/z-50 стекування модалки-над-модалкою |
| P6 | **Settings залишається діалогом** (поза scope) | Чистий поділ: верх = екрани (`aria-pressed`), footer = діалоги; Settings — конвенційно доречна модалка |

## 3. Цільова структура головного меню

```
┌─ Профіль / <активний профіль>   ← P2, P4: дворядковий header, aria-pressed коли активний
├──────────────────────────────── ← divider (P2)
│  Потоки                          ← група секцій
│  Браузер
│  Список бажань
│  Розклад (disabled)
│  Пісні
│                       (mt-auto)
└─ Налаштування                    ← footer: лишається діалогом (P6)
```

- Профіль перемикає `$activeSection.set("profiles")`, отримує `aria-pressed`,
  міняє `<main>` — як решта секцій.
- Settings лишається у footer і відкриває overlay (інша модель). Тоді **кожна
  візуальна група = одна модель взаємодії**: верх перемикає екран, footer
  відкриває діалог.

## 4. Наслідки для коду (орієнтовно; деталізувати в спеці)

1. **`Section`-юніон + render-switch** у [App.tsx:300-303](../../../src/App.tsx#L300-L303)
   отримують запис `"profiles"`; `ProfileManager` як модалку з
   [App.tsx:317](../../../src/App.tsx#L317) прибрати.
2. **Новий `ProfilesPanel`** (екран) реалізує контракт зональної навігації
   (`onZonesChange` / `exitZone` / `ZoneEntry`, roving-focus) — за зразком
   `StreamsPanel`. Переносить логіку зі `ProfileManager` (switch/create/rename/
   duplicate/delete/import/export), `ProfileList`/`ProfileActions` перевикористати.
3. **Під-операції** — однорівневі діалоги через існуючий патерн `ConfirmDialog` /
   простий prompt-діалог; зняти ручне z-40/z-50 стекування.
4. **ActivityBar:** кнопку профілю підняти нагору з divider; перевести `onPress`
   на `$activeSection.set("profiles")`; зберегти `aria-label` з іменем активного
   профілю ([ActivityBar.tsx:136](../../../src/components/layout/ActivityBar.tsx#L136))
   і дворядковий header (P4); додати `aria-pressed`. Прибрати стор
   `$profileManagerOpen`.
5. **Launch-фокус (P3):** на старті фокусувати кнопку поточного `$activeSection`,
   а не перший елемент
   ([App.tsx:127](../../../src/App.tsx#L127)).
6. **Видалити/спростити** `refocusList`-механіку та post-op refocus-хаки
   ([ProfileManager.tsx:51-56](../../../src/components/profile/ProfileManager.tsx#L51-L56))
   — на екрані з зональною навігацією фокус відновлюється однаково для всіх.
7. **Тести:** оновити/перенести `ProfileManager.test.tsx`; додати тести зон і
   roving-focus для `ProfilesPanel`; оновити `ActivityBar.test.tsx` під новий
   порядок кнопок, divider, `aria-pressed` і launch-фокус на активній секції.
8. **i18n:** наявні ключі профілів перевикористати; за потреби додати ключ
   назви секції в меню.

## 5. Відкинуті альтернативи

- **Лишити профілі діалогом.** Відхилено: модальна модель — джерело крихкості
  focus-менеджменту (вся остання серія комітів); CRUD природніше лягає в екран.
- **Профіль у кінці списку секцій.** Відхилено на користь верху: у кінці він
  виглядав би як рівноправний екран і ховав ієрархію вкладеності; дворядковий
  підпис там виламувався б зі стилю секцій.
- **Профіль у footer поруч із Settings (як зараз, але вже екран).** Відхилено:
  footer-кнопка з `aria-pressed`, що перемикає екран, поруч із Settings-діалогом —
  візуальне групування перестає відповідати поведінці.
- **Launch-фокус на кнопці профілю.** Відхилено: рідковживана дія перехоплювала б
  стартовий фокус і озвучення; до основного екрана щоразу треба стрілка вниз.
- **Інлайн-форми/зони замість діалогів для під-операцій.** Відхилено зараз:
  більше роботи й нова розмітка; однорівневі діалоги дають потрібний результат
  дешевше.
- **Переводити заодно і Settings.** Поза scope: Settings як модалка доречна;
  переглянути окремо, якщо знадобиться повна однорідність.

## 6. Відкриті питання

1. Назва секції профілів у меню та її іконка (зараз `Layers`
   [ActivityBar.tsx:142](../../../src/components/layout/ActivityBar.tsx#L142)) — лишити чи змінити.
2. Чи потрібен профілям локальний пошук/фільтр у списку (за політикою DA3 із
   [2026-05-31-command-palette-and-search-ux.md](2026-05-31-command-palette-and-search-ux.md)) —
   ймовірно ні (список малий), підтвердити при реалізації.
3. Чи додавати клавіатурний шортката для переходу на екран профілів (за аналогією
   з `Ctrl+,` для Settings) — наразі не передбачено.
4. Точна розкладка екрана: одноколонкова (список зверху, дії під ним) чи
   дві зони (список + панель дій), як у поточній модалці
   ([ProfileManager.tsx:255-279](../../../src/components/profile/ProfileManager.tsx#L255-L279)) —
   вирішити у спеці з огляду на зональну навігацію.
