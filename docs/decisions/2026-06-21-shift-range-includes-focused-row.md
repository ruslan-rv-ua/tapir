# Shift-діапазон включає сфокусований рядок

- **Статус:** РЕАЛІЗОВАНО (2026-06-21) — гілка `selection.size === 0` у [useCompositeList.ts](../../src/hooks/useCompositeList.ts) (клавіатура + Shift+click), тести оновлено/підсилено; гейти `pnpm test` (583) + `pnpm vite:build` зелені.
- **Дата:** 2026-06-21
- **Тип:** ADR — поведінка виділення в спільному хуку композитних списків (`useCompositeList`).
- **Область дії:** усі композитні списки (streams / browser / profiles / schedule / songs), бо guard живе у **спільному** хуку (узагальнено у віхі D).
- **Пов'язане:** [accessibility.md](../accessibility.md), [keyboard-shortcuts.md](../keyboard-shortcuts.md), парасолька масових операцій `p1-bulk-stream-operations` (реалізовано; запис видалено до появи `done/`).

## Проблема

У роздільній моделі «фокус (курсор) ≠ виділення» сфокусований, але **невиділений** рядок — валідний стан. Коли фокус на `потік1`, виділення порожнє, і користувач натискає `Shift+Down`, поточна реалізація виділяє **лише** рядок-ціль (`потік2`), а `потік1` мовчки не потрапляє у виділення.

Наслідки:

- **Розходження з Windows Explorer / стандартними списками**, де `Shift+Down` зі сфокусованого рядка включає поточний рядок у діапазон. NVDA-користувачі — Windows-користувачі за визначенням, у них найсильніша м'язова пам'ять цієї конвенції, і клавіатура — їхній єдиний канал.
- **`потік1` неможливо додати самим лише `Shift+Down`**: щоб виділити `потік1..потік3`, треба спершу `Ctrl+Space` на `потік1`. Стартовий рядок «губиться», і незрячий користувач помічає це лише за лічильником («виділено N»), а не візуально.
- Це **емерджентна** поведінка, а не свідоме UX-рішення: коментар і тест на guard виправдовують лише **скидання бази** (захист від «воскресіння» застарілого `anchorBase`), а перенесення *якоря* з фокусованого рядка на рядок-ціль — зчеплений побічний наслідок того, як написали guard.
- Навіть WAI-ARIA APG у командах діапазону (`Ctrl+Shift+Home/End`) трактує **сфокусований** рядок як частину діапазону — тобто поточна поведінка розходиться і зі специфікацією, на яку могла б спиратися.

## Рішення

**Перейти на Explorer-inclusive: `Shift+Down/Up` з порожнього виділення включає сфокусований рядок у діапазон.** Поширюється на **клавіатуру і `Shift+click` мишею** (узгодженість жестів).

`Shift+Down` із `потік1` (виділення `∅`) → `{потік1, потік2}`, курсор на `потік2`.

Зміна **хірургічна** — чіпає лише гілку `selection.size === 0`. Усе інше (розширення непорожнього діапазону через `anchorBase`, plain-навігація з `setAnchor`, `Ctrl+Space`, межі списку) — без змін.

### Клавіатура — [useCompositeList.ts:506-509](../../src/hooks/useCompositeList.ts#L506-L509)

```js
if (sel.current().size === 0) {
  anchorRef.current = activeItemId;   // було: cursorId — тепер рядок, де стояв фокус (потік1)
  anchorBaseRef.current = new Set();  // ЛИШАЄТЬСЯ: захист від stale-base
}
```

`activeItemId` (замикання обробника) на цей момент ще дорівнює `потік1` — `setActiveItemId` (React-сеттер) не флашиться синхронно в межах обробника. Далі `span = rangeIds(потік1, потік2) = {потік1, потік2}`, `base = ∅` → результат `{потік1, потік2}`.

### Shift+click — [useCompositeList.ts:593-597](../../src/hooks/useCompositeList.ts#L593-L597)

Те саме, але якорем стає **попередньо-активний** рядок. Пастка: `onClick` **не має** `activeItemId` у залежностях `useCallback` (stale-closure), тож читати треба з **`memoryRef.current.itemId`** (ref, завжди свіжий), а не із замикання.

```js
if (e.shiftKey) {
  if (sel.current().size === 0) {
    anchorRef.current = memoryRef.current.itemId;  // попередньо-активний рядок, не клікнутий id
    anchorBaseRef.current = new Set();
  }
  ...
}
```

## Чому це безпечно (інваріант guard'а збережено)

Guard захищає від одного: зовнішнє очищення виділення (тулбар / lifecycle-clear) лишає застарілий `anchorBase`, який `base ∪ range` «воскресив» би. Ми **й далі скидаємо `anchorBase` у `∅`** — змінюємо лише *якір*, не *базу*. Тому застарілі рядки не повертаються; додається **тільки** сфокусований рядок — через якір, легітимно.

Скидання бази (захист) і вибір якоря (UX) — **відокремлювані**; ми зберігаємо перше і виправляємо друге.

## Вплив на тести

Гейти проєкту: `pnpm test` + `pnpm vite:build` (+ `cargo test` за потреби), **не** `tsc`.

- **[useCompositeList.test.tsx:592](../../src/hooks/useCompositeList.test.tsx#L592)** «anchorBase guard» — **зміниться** і має бути **підсилений**, а не просто перенумерований. Тепер результат `["a","b"]`, не `["b"]`. Щоб тест і далі доводив головне (stale-base **не** воскресає), сценарій має містити рядок **поза** новим span'ом: напр. база `{a,b,c}` → зовнішнє очищення → фокус на `a` → `Shift+Down` має дати `{a,b}` (де `a` — з якоря, `b` — з діапазону), а **не** `{a,b,c}` (`c` не повертається).
- **[:571](../../src/hooks/useCompositeList.test.tsx#L571)**, **[:637](../../src/hooks/useCompositeList.test.tsx#L637)** — стартують із `Ctrl+Space` (виділення непорожнє на момент `Shift`) → **не зачіпаються**, лишаються зелені.
- **[:696](../../src/hooks/useCompositeList.test.tsx#L696)** «Shift+Click spans» — клікає `a` перед shift-кліком (виділення непорожнє) → **не зачіпається**. Додати **новий** тест порожнього виділення: Tab → активний `a`, виділення `∅`, `Shift+click c` → `{a,b,c}`.
- **[:604](../../src/hooks/useCompositeList.test.tsx#L604)** «without a selection adapter» — без адаптера, **не зачіпається**.
- **Аудит спільного хука:** пройтися по тестах інших консументів (`StationList.test.tsx`, `StreamList.test.tsx`, profiles/schedule/songs) на дзеркальні assert'и про empty-`Shift` і оновити за потреби.

## Наслідки

- **a11y/UX:** оголошення після `Shift+Down` із `потік1` тепер «виділено **2**» замість «1» — точніше відображає дію; збіг із Explorer; стартовий рядок не губиться.
- **Узгодженість** клавіатура↔миша збережена (обидва жести змінюються однаково).
- **Blast-radius:** спільний хук → зміна впливає на всі списки одразу. Це **навмисно** — консистентність між списками важливіша за локальність.

## Поза обсягом (YAGNI)

- Жодних змін у непорожньому розширенні діапазону, `Ctrl+Space`, `Ctrl+A`, `Escape`, plain-навігації.
- Жодного нового конфіг-перемикача «Explorer-режим vs поточний» — обираємо одну поведінку.
- Реалізація (правка коду + тести) — окремий цикл (writing-plans → executing-plans). Цей ADR лише фіксує **напрям**.
