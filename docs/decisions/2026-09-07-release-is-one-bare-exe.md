# Реліз — це один голий exe: без архіву, без інсталятора, без підпису

- **Статус:** ПРИЙНЯТО
- **Дата:** 2026-09-07
- **Тип:** ADR — форма того, що роздається
- **Контекст:** беклог — [release-workflow](../backlog/done/p2-release-workflow.md);
  межа портативності — [ADR 2026-09-04](2026-09-04-portable-boundary.md);
  ворота — [ADR 2026-09-05](2026-09-05-gates-refuse-rather-than-advise.md).

## Проблема

Tapir — «portable single EXE, без інсталятора». Поки застосунок ніхто не завантажував,
це було властивістю збірки. З першим тегом воно стає обіцянкою на публічній сторінці, і
її треба оформити: що саме лежить у GitHub Release, як воно зветься, чи загорнуте в
архів, чи підписане, і що бачить людина, яка його вперше запускає.

Кожен із цих пунктів має «правильну» відповідь у загальній практиці — ZIP із README
всередині, підписаний сертифікатом бінарник, інсталятор із ярликом, — і кожна з них
для цього застосунку хибна з однієї причини: **користувач Tapir може бути незрячим**, і
кожен зайвий крок між кнопкою «Download» і працюючим вікном — це крок, який треба вміти
пройти з клавіатури й читачем екрана.

## Рішення

**У Release лежить один файл `tapir-v<тег>-x64.exe` і його сайдкар `.sha256`.
Без архіву, без інсталятора, без підпису.**

- **Без архіву.** `data\` і `recordings\` застосунок створює сам при першому запуску;
  у ZIP не було б нічого, крім самого exe. Розпаковування — зайвий крок, який
  на екрані читача звучить як «архів із одним файлом усередині».
- **Без інсталятора.** Портативність — рішення продукту, не збірки:
  [ADR 2026-09-04](2026-09-04-portable-boundary.md) уже провів межу «що лежить поряд із
  exe». Інсталятор перекреслив би її, а `bundle.targets: ["nsis"]` у конфізі Tauri був
  мертвим рядком і знятий.
- **Без підпису.** Сертифікат коштує грошей щороку і прив'язаний до особи або
  організації. Те, що він купує, — відсутність одного екрана SmartScreen при першому
  запуску exe, завантаженого браузером. Той самий екран проходить і читач: «More info»
  → «Run anyway» — два стопи клавіатурою, і шлях записано в README поруч із
  посиланням. Другий канал — scoop — цього екрана не показує зовсім: перевірено
  2026-09-07, exe, встановлені scoop, не несуть позначки `Zone.Identifier`. Тобто
  за гроші купувався б екран, який один канал обходить, а другий проходить за два
  натискання.
- **Сайдкар** у форматі `<hex64> *<ім'я файлу>` — це те, що читає `sha256sum -c`, і
  те, з чого `autoupdate` scoop бере хеш без жодного коду на боці застосунку.
- **Версія в імені файлу**, а не `tapir.exe`: у теці Downloads двох версій не
  переплутати, а scoop однаково перейменовує через фрагмент `#/tapir.exe`, тож `bin`
  і ярлик стабільні.

Ім'я артефакту названо у двох репозиторіях — у workflow Tapir і в маніфесті bucket.
Це два місця, і збіг між ними стереже тест у `build/` на боці Tapir, а не пам'ять.

## Відхилені варіанти

**ZIP із exe, LICENSE і README** (форма шаблону в scoop-bucket). Відкинуто: усе, що в
ZIP, крім exe, є на сторінці репозиторію, а крок розпаковування — єдине, що ZIP додає.

**Підписати самопідписаним сертифікатом.** SmartScreen не довіряє йому так само, як
відсутності підпису; це витрати без ефекту.

**Купити сертифікат.** Не назавжди відкинуто — див. «Коли переглянути», — але не для
одного розробника з нульовою репутацією видавця: SmartScreen будує довіру за кількістю
запусків, і перші місяці екран показувався б і з підписом.

**Інсталятор NSIS «для тих, хто хоче ярлик».** Ярлик у Start Menu дає scoop
(`shortcuts` у маніфесті); другий канал заради ярлика — це два продукти замість одного.

## Обмеження / наслідки

- README мусить нести клавіатурний шлях через SmartScreen поруч із посиланням на
  завантаження, і називати scoop як шлях без цього екрана. Довідка `docs/help/` цього
  не несе: той, хто читає довідку, застосунок уже запустив.
- Форма артефакту — контракт із bucket: перейменування файлу або перехід на архів
  ламає `autoupdate` кожного наступного релізу. Змінювати форму — значить змінювати
  маніфест у той самий день.
- Непідписаний exe робить `VERSIONINFO` єдиним місцем, де бінарник заявляє, хто він.
  Тому релізний workflow звіряє версію в exe з тегом, а не довіряє `Cargo.toml`.

## Коли переглянути

- Якщо з'явиться організація або спонсор, що покриє сертифікат, — підпис стає
  дешевим і його варто додати; форма «один exe» при цьому не змінюється.
- Якщо SmartScreen перестане пропускати непідписані exe взагалі (політика Windows,
  а не репутація) — рішення про підпис переглядається негайно.
