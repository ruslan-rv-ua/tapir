# Індикатор стану потоку на екрані Streams — прибрати колонку-іконку

- **Статус:** ПРИЙНЯТО (рішення узгоджені; спека/реалізація — попереду)
- **Дата:** 2026-05-31
- **Автор:** Ruslan Iskov (за результатами брейнсторму з Claude)
- **Тип:** ADR — UI/a11y-рішення про візуальне кодування стану рядка потоку
- **Зачіпає:** [StreamItem.tsx](../../../src/components/streams/StreamItem.tsx),
  [StreamItem.test.tsx](../../../src/components/streams/StreamItem.test.tsx),
  [accessibility.md](../accessibility.md), [FRD-navigation.md](../FRD-navigation.md)
- **Ревізія:** §9 — конфлікти й гепи, виявлені звіркою з кодом, тестами, FRD та
  accessibility.md (2026-05-31, після першої редакції)

## 0. Призначення

Рішення про те, як показувати **стан потоку** (запис / відтворення / підключення /
помилка / простій) на екрані Streams: прибрати окрему колонку-іконку, що з'їдає
горизонтальний простір, не втративши при цьому жодного каналу інформації — ні для
зрячих, ні для NVDA.

## 1. Контекст (факти на 2026-05-31)

Стан рядка зараз кодується **чотирма** каналами одночасно:

1. **Окрема колонка-іконка**, 100px ліворуч
   ([StreamItem.tsx:172-185](../../../src/components/streams/StreamItem.tsx#L172-L185)):
   `Mic`/`Radio`/`Volume2`/`Loader2`/`AlertCircle`, `role="img"` з підписом.
2. **Колір тла рядка** + ліва межа
   ([StreamItem.tsx:141-147](../../../src/components/streams/StreamItem.tsx#L141-L147)):
   запис → `bg-red-950/30` + червона ліва межа; відтворення → `bg-blue-950/30`.
3. **Доступна назва рядка** — `aria-label` на `<li>`
   ([StreamItem.tsx:87-92](../../../src/components/streams/StreamItem.tsx#L87-L92)):
   «запис, Mera» / «відтворення, Mera» / «запис і відтворення, Mera». Це **головний**
   канал для NVDA.
4. **Колонка «статус»** (90px), окремий focus-stop, що з'являється лише коли потік
   активний ([StreamItem.tsx:27-32](../../../src/components/streams/StreamItem.tsx#L27-L32),
   [:220-234](../../../src/components/streams/StreamItem.tsx#L220-L234)) — показує
   **тривалість запису** (оновлюється щосекунди) чи текст підключення.

Сітка рядка ([StreamItem.tsx:164](../../../src/components/streams/StreamItem.tsx#L164)):

```
100px        | 1fr   | 1.5fr | 90px | 90px   | auto
іконка стану | назва | трек  | біт. | статус | дії
```

**Виявлені проблеми:**

- **A. Простір.** 100px під центрований гліф 16px ≈ 84px мертвого простору в кожному
  рядку; назва (`1fr`) і трек (`1.5fr`) від цього програють.
- **B. Семантика іконки запису.** Обрано `Mic`, що означає «запис із мікрофонного
  входу». Тапір захоплює і зберігає **потік інтернет-радіо** — це інша дія. До того ж
  кнопка запису в тому ж рядку вже використовує record-гліф `⏺`
  ([StreamItem.tsx:260](../../../src/components/streams/StreamItem.tsx#L260)) → дві різні
  метафори для однієї дії в одному рядку.
- **C. Дуальний стан показано лише наполовину.** «Запис + відтворення» є в `aria-label`
  (канал 3, ✅), але **візуально — ні**: ланцюжок вибору іконки ставить `recording`
  першим ([StreamItem.tsx:179](../../../src/components/streams/StreamItem.tsx#L179)), тож
  показується тільки `Mic`, а `Volume2` губиться; тло теж червоне. Зрячий не відрізнить
  «лише запис» від «запис + відтворення».

## 2. Концептуальна основа

- **Колір — ніколи не єдиний канал.** Тло як єдиний візуальний сигнал порушує
  [WCAG 1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html),
  а в режимі високого контрасту Windows (`forced-colors`) тло **стирається повністю** —
  стан зникне. Тож тло лишається **вторинним ambient-каналом**, а не основним.
- **Форма не залежить від кольору.** Іконка дає форму — другий канал поверх кольору;
  переживає `forced-colors` (гліф у `[Highlight]`); читається дальтоніками.
- **Стан для NVDA несеться не візуальною колонкою, а accessible-структурою рядка** —
  але **по-різному за станами** (важливо, див. §9):
  - `recording` / `playing` → у `aria-label` **summary** рядка (FRD §7.3, приклади
    рядки 305-307; §5.4 п.1). Прибрати іконку для них нейтрально.
  - `connecting` / `reconnecting` → у **сегменті «статус»** (окремий focus-stop, FRD
    §5.4 п.4). У summary їх немає — і FRD цього не вимагає.
  - `error` → **наразі лише у візуальній іконці** (не в summary, не focus-stop, бо
    `error` не входить у `active`). Це **пре-існуючий геп**, який прибирання іконки
    оголює — рішення в §9/§8.
- **Тривалість — динамічне значення для «опитування».** Окремий focus-stop дає
  незрячому стати стрілкою прямо на нього й почути тільки «03:21, тривалість запису»,
  не переслуховуючи назву. Це дешевше за «весь рядок, аби почути число в кінці».

## 4. Як це виглядатиме

Два позиційні слоти (R = запис/підключення, P = відтворення), назви на одному x:

```
[R][P] Mera         …   ← запис + відтворення (record-dot + Volume2)
[ ][ ] Radio NRJ    …   ← простій, назва на тому ж x
[R][ ] Music FM     …   ← лише запис (пульсуючий червоний кружечок)
[ ][P] Jazz24       …   ← лише відтворення (Volume2)
[R][P] Drive FM     …   ← підключення + відтворення (Loader2 + Volume2)
```

Цільова сітка (концептуально; точні значення — у спеці):

```
~40px        | 1fr   | 1.5fr | 90px | auto
слоти R|P+назва (об'єднані) | трек | статус | дії
```

де слоти можуть жити в одній клітинці з назвою (`flex`: `[R][P] <назва>`), а колонку
тривалості (статус, 90px) залишено окремою.

**Відповідність станів і гліфів:**

| Стан | Слот 1 (R) | Слот 2 (P) | Тло/межа |
|---|---|---|---|
| простій | — | — | — |
| запис | червоний кружечок (пульс) | — | червоне + ліва межа |
| відтворення | — | `Volume2` | синє |
| запис + відтворення | червоний кружечок (пульс) | `Volume2` | червоне (домінанта) + ліва межа |
| підключення | `Loader2` (spin) | — | — |
| підключення + відтворення | `Loader2` (spin) | `Volume2` | синє |
| перепідключення | `RefreshCw` (spin) | (як вище) | — |
| помилка | `AlertCircle` | — | — |

## 5. A11y-наслідки

- **NVDA:** для `recording`/`playing` без змін (стан у summary); для
  `connecting`/`reconnecting` — у сегменті «статус» (focus-stop); для `error` —
  **потрібен D9**, інакше прибирання іконки залишить errored-потік без доступного
  стану в списку. Колонка тривалості лишається окремим focus-stop; інлайн-іконки
  `aria-hidden` (після виконання D9).
- **Дальтонізм:** форма (кружечок vs спінер vs динамік vs трикутник) — канал поверх
  кольору.
- **High-contrast (`forced-colors`):** гліфи в `[Highlight]` лишаються (тло стирається,
  тож воно й не основне). **Увага:** залитий кружечок використовує `fill`, а не лише
  `stroke`/`text` — тож потрібен явний `forced-colors:fill-[Highlight]` (звичайні
  lucide-іконки stroke-based, де досить `text-[Highlight]`; залитий `Circle` — виняток,
  accessibility.md §1.3 вимагає `forced-colors:` саме для `StatusIcon`).
- **Слабкий зір / лупа:** резервування слотів → назви не «стрибають» при зміні стану.
- **`prefers-reduced-motion`:** пульс і спіннери вимикаються в статичний вигляд.

## 6. Відкинуті альтернативи

- **Тільки колір тла як основний індикатор** (без іконки). Відхилено: WCAG 1.4.1
  (лише колір) + тло стирається в `forced-colors` → стан зникне.
- **Один резервний слот замість двох** (друга іконка в overflow). Відхилено: дуальний
  стан (слухати потік, поки він пишеться) реальний → дуальні рядки інколи зсуватимуть
  назву. ~40px сталого жолоба прийнятні за відсутність смикання.
- **Згорнути тривалість в інлайн-бейдж біля назви** (прибрати колонку 90px). Відхилено:
  бейдж перестав би бути focus-stop → щоб почути тривалість, довелося б ставати на весь
  рядок і слухати назву (антипатерн для незрячих). Див. D6.
- **`Disc`/`Disc3` для запису.** Відхилено на користь залитого кружечка: «диск»
  читається радше як носій, ніж «триває запис»; кружечок збігається з `⏺` на кнопці.
- **`Download` для запису.** Відхилено: натякає на скінченне завантаження із
  завершенням, а запис — безперервний live-захват.
- **Без резервування простору (collapse).** Відхилено: назви стрибають при кожній
  зміні стану; колонку назв не просканувати згори вниз.

## 7. Наслідки для коду (орієнтовно; деталі — у спеці)

1. Сітку `gridTemplateColumns` перебудувати: прибрати першу колонку 100px; слоти
   R|P внести в клітинку назви (`flex`) або як вузький лідируючий жолоб ~40px
   ([StreamItem.tsx:164](../../../src/components/streams/StreamItem.tsx#L164)).
   **Геп-пастка:** усі сегменти позиціонуються явним `style={{ gridColumn: N }}` —
   назва=2, трек=3, техн=4, статус=5, дії=6. Прибирання col 1 зсуває **всі**
   індекси на −1; кожен інлайновий `gridColumn` у блоках треба переписати, інакше
   розкладка з'їде. (Якщо слоти лишити в клітинці назви через `flex`, а не окремою
   grid-колонкою — індекси однаково зсуваються на −1.)
2. Логіку вибору іконки переписати з «один із» на **два незалежні слоти**: слот 1 за
   `state` (recording→кружечок / connecting→`Loader2` / reconnecting→`RefreshCw` /
   error→`AlertCircle` / інакше порожньо), слот 2 за `isThisStreamPlaying`
   (`Volume2` / порожньо). Idle-індикатор `Radio` — переглянути: чи потрібен взагалі,
   чи порожні слоти достатні
   ([StreamItem.tsx:179-184](../../../src/components/streams/StreamItem.tsx#L179-L184)).
3. `Mic` → `Circle` із заливкою (`fill-red-500 text-red-500`
   **+ `forced-colors:fill-[Highlight]`**) + клас пульсації під `motion-safe:` /
   медіазапит `prefers-reduced-motion`.
4. Слоти `aria-hidden`; `role="img"`/`aria-label` зі старої колонки **прибрати** —
   **але спершу виконати D9** (донести `error`, а також за бажанням
   `connecting`/`reconnecting`, у summary чи в сегмент «статус»), інакше ці стани
   зникнуть для NVDA. Переконатися, що для `recording`/`playing` нічого не дублюється.
5. Колонку «статус»/тривалість (col 5) **не чіпати**
   ([StreamItem.tsx:220-234](../../../src/components/streams/StreamItem.tsx#L220-L234)).
6. `getStreamSegments` — без змін (сегмент `status` лишається).
7. Тести [StreamItem.test.tsx](../../../src/components/streams/StreamItem.test.tsx):
   **конкретний конфлікт** — три тести reconnecting-блоку
   ([:144-168](../../../src/components/streams/StreamItem.test.tsx#L144-L168))
   асертять `container.querySelector('[role="img"]')` і його `aria-label`
   (`спроба 3 з 10` тощо). Прибирання `role="img"`/`aria-label` з іконки → `querySelector`
   поверне `null` → `.getAttribute` кине помилку → тести впадуть. Перенести ці асерти на
   **сегмент «статус»** (ті ж тести вже перевіряють `[data-segment="status"]` поряд — там
   текст лишається) і **прибрати** перевірки іконки. Додатково: кейс дуального стану (дві
   іконки), перевірка `error`-стану за D9, перевірка, що тривалість лишається окремим
   focus-stop, відсутність дублювання для `recording`/`playing`.

## 8. Відкриті питання

1. ~~**Чи лишати окремий idle-індикатор (`Radio`)?**~~ **Вирішено:** порожні слоти
   для idle — без іконки. Порожній слот сигналізує «нічого не відбувається»;
   значущі стани (`●`, `▶`, спінер) виділяються чіткіше. `Radio` прибирається.
2. ~~**Слоти — `flex` у клітинці назви чи окремі grid-колонки?**~~ **Вирішено:**
   `flex` у клітинці назви — `<div className="flex items-center gap-1">` з двома
   `<span aria-hidden className="w-4">` (по 16px кожен) перед текстом назви.
   Прибирається лише одна grid-колонка (100px), решта індексів зсуваються на −1.
3. Параметри пульсації — визначити при реалізації. Орієнтир: period ~2s,
   opacity 1.0→0.4→1.0, `motion-safe:animate-pulse` (Tailwind) як відправна точка;
   підібрати вручну щоб читалось як «REC» і не дратувало.
4. Чи переносити це рішення на інші екрани зі схожими індикаторами стану (Browser/Songs)
   — поза обсягом цього ADR.
5. ~~**`error` у summary чи в сегменті «статус»?**~~ **Вирішено (D9):** `error` у
   `summaryLabel`, без нового сегмента. FRD §5.4/§7.3 не суперечить — додати приклад
   `"помилка, Radio Paradise, потік"` у FRD при реалізації.
6. ~~**Чи потрібен видимий текст «REC»?**~~ **Вирішено:** без тексту. Форма
   (залитий кружечок) + колір + пульсація задовольняють WCAG 1.4.1. Текст «REC» не
   додається — слоти лишаються лаконічними.

вже відображено вище (D8 уточнено, додано D9, правки §5/§7/§8).

| # | Тип | Знахідка | Де | Статус у ADR |
|---|-----|----------|-----|--------------|
