# Підтримка HLS-потоків

- **Слаг:** `hls-stream-support`
- **Тип:** ідея
- **Стан:** draft
- **Зусилля:** L
- **Оновлено:** 2026-06-15
- **Залежності:** Phase 1 (stream::connection, stream::format), PlayerEngine (symphonia)

## Опис

**HLS (HTTP Live Streaming)** — стандарт Apple для адаптивного стримінгу через HTTP. Замість одного безперервного потоку, HLS роздає короткі `.ts` або `.aac`-сегменти через `.m3u8` плейлист-маніфест.

**Поточний стан:** Tapir використовує `reqwest` для прямих ICY/Shoutcast потоків. HLS-потоки (прапор `hls: 1` у Radio Browser API) не підтримуються — `stream::connection` не знає як читати `.m3u8`-маніфест і завантажувати сегменти.

Частина станцій у Radio Browser має прапор `hls: 1`. Наразі при спробі підключення до такої станції Tapir або отримує помилку з'єднання, або завантажує текстовий `.m3u8` замість аудіо.

**Чому P3 (під сумнівом):**
- HLS не підтримує ICY metadata — зміна треку не виявляється автоматично
- Реалізація вимагає принципово іншої архітектури: сегментний downloader замість потокового reader
- Для запису треба конкатенувати сегменти — ускладнює splitter і логіку файлів
- `symphonia` (PlayerEngine) може відтворювати `.ts`-файли, але `.m3u8`-плейлист не підтримується нативно
- Великий обсяг роботи або велика зовнішня залежність (hls.js — JS, нативний HLS-крейт — перевірити)
- Невизначена реальна цінність: скільки % популярних станцій є виключно HLS?

## Технічна складність

### M3U8 парсинг
- Extended M3U8: `#EXT-X-TARGETDURATION`, `#EXTINF`, `#EXT-X-MEDIA-SEQUENCE`
- DRM: `#EXT-X-KEY` (AES-128, SAMPLE-AES) — навряд потрібно підтримувати
- Варіативний стрімінг: `#EXT-X-STREAM-INF` з кількома бітрейтами — треба обирати

### Сегментний завантажувач
- Черга з буфером (prefetch N сегментів наперед)
- Відстеження `#EXT-X-MEDIA-SEQUENCE` для уникнення дублікатів
- Поновлення плейлиста кожні `EXT-X-TARGETDURATION` секунд

### Запис (RecordingEngine)
- Без ICY metadata → немає сигналу для авто-сплітингу треків
- Для запису треба конкатенувати `.ts`-сегменти або транскодувати через ffmpeg
- Назва треку в UI: показувати лише назву станції без «Зараз грає»

### PlayerEngine
- Потребує нового джерела `HlsSource`, що підхоплює сегменти з черги downloader'а
- Альтернатива: передавати сегменти як `Cursor<Vec<u8>>` у `symphonia`

### Технічні варіанти реалізації
1. **Нативний Rust-крейт** (`m3u8-rs`, `hls_m3u8`) — парсинг маніфесту + власний downloader. Найбільше роботи, найкраще вписується в portable EXE.
2. **Зовнішній ffmpeg** — якщо ffmpeg вже є у системі або у data/, можна делегувати HLS-завантаження через `ffmpeg -i <url.m3u8> -c copy output.ts`. Проблема — ffmpeg не є частиною portable bundle.
3. **Ігнорувати HLS** — фільтрувати станції з `hls: 1` у Stream Browser і показувати попередження «HLS не підтримується».

## Критерії готовності
- [ ] `stream::connection` визначає HLS за розширенням `.m3u8` або Content-Type `application/vnd.apple.mpegurl`
- [ ] Реалізовано парсер Extended M3U8 (без DRM)
- [ ] Сегментний downloader з чергою і буфером
- [ ] PlayerEngine відтворює HLS-потік без артефактів
- [ ] RecordingEngine записує сегменти як безперервний файл
- [ ] Stream Browser показує індикатор `HLS` для таких станцій
- [ ] UI для «Зараз грає» при HLS показує лише назву станції (без метаданих треку)
- [ ] Усі нові елементи UI доступні через NVDA

## Відкриті питання
- Скільки % станцій у Radio Browser є виключно HLS (без ICY-альтернативи)? Варто перевірити перед початком роботи.
- Чи потрібно підтримувати DRM (`#EXT-X-KEY`)? Найімовірніше ні — це комерційні потоки.
- Чи підтримувати варіативний бітрейт (`#EXT-X-STREAM-INF`)? Якщо так — який вибирати автоматично?
- Як відображати «Зараз грає» в UI без ICY metadata? Тільки назва станції чи ховати цей рядок?
- ffmpeg як опціональна залежність чи виключно нативна Rust-реалізація?
- Чи є HLS-крейти з достатньою зрілістю для production (перевірити `m3u8-rs`, `hls_m3u8`)?
- Trigger для повернення до цієї ідеї: якщо з'являться конкретні запити від користувачів або якщо >20% популярних станцій виявляться виключно HLS.
