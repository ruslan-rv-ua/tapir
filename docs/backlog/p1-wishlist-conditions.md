# Умови та дії після запису у вішлісті

> **Контекст:** Наразі вішліст записує трек за будь-яких умов, якщо паттерн збігається. Потрібна підтримка фільтрів та автоматичних дій після запису.

## Опис

### Умови запису (фільтри)

1. **Мінімальний бітрейт** (`minBitrate: N`) — записувати тільки якщо бітрейт потоку ≥ N kbps. Якщо бітрейт нижчий — трек не записується.

2. **Формат потоку** (`format`) — записувати тільки якщо потік у вказаному форматі (MP3, AAC або будь-який).

### Дії після успішного запису

3. **Видалити паттерн після запису** (`removeAfterRecord: true`) — автоматично видаляти паттерн із вішліста після того, як трек записаний. Запобігає повторному записуванню тієї ж пісні.

4. **Перенести до ігнор-листа після запису** (`addToIgnorelistAfterRecord: true`) — після запису автоматично додати паттерн до ігнор-листа, щоб більше не записувати цей трек.

### Що потрібно реалізувати

- **Backend**: перевіряти умови (`minBitrate`, `format`) при матчингу вішліста.
- **Backend**: виконувати дії після запису (видалення з вішліста / перенос до ignorelist).
- **IPC**: зберігати ці умови та прапорці для кожного запису вішліста.
- **UI**: форма редагування запису вішліста з полями для всіх чотирьох умов.

## Критерії готовності

- [ ] Модель запису вішліста містить поля `minBitrate`, `format`, `removeAfterRecord`, `addToIgnorelistAfterRecord`.
- [ ] Backend перевіряє `minBitrate` і `format` перед записом; якщо умова не виконана — пропускає.
- [ ] Після успішного запису виконуються дії `removeAfterRecord` / `addToIgnorelistAfterRecord`.
- [ ] UI дозволяє редагувати всі чотири умови для кожного запису вішліста.
- [ ] Існуючі записи вішліста без умов продовжують працювати (зворотна сумісність).
