# aria-keyshortcuts — Анотація клавіатурних шорткатів для скрін-рідерів

- **Слаг:** `aria-keyshortcuts`
- **Тип:** ідея
- **Стан:** draft
- **Зусилля:** S (лише HTML-атрибут) / M (+ Settings toggle verbosity)
- **Оновлено:** 2026-06-15
- **Залежності:** Phase 2C (SettingsDialog + Shortcuts)

## Опис

`aria-keyshortcuts` — стандартний ARIA-атрибут (WAI-ARIA 1.1), що дозволяє анотувати елемент клавіатурним шорткатом, асоційованим з ним. Скрін-рідер може озвучити це значення при фокусі на елементі.

Приклад застосування у Tapir:

```html
<section aria-label="Потоки" aria-keyshortcuts="Ctrl+N">
  ...
</section>
```

NVDA при фокусі на цьому landmark може озвучити: _"Потоки, регіон, Ctrl+N"_.

### Де розмістити атрибут

**Варіант 1 — Landmark sections (зони навігації):**
Додати `aria-keyshortcuts` на `<section>` із `aria-label`, що відповідають зонам (`Потоки`, `Програвач`, `Список пісень` тощо). Це логічно відображає шорткати переходу між зонами (Alt+1, Alt+2 тощо).

**Варіант 2 — Кнопки та інтерактивні елементи:**
Додати атрибут безпосередньо на `<button>` або інші активні елементи. Підходить для дій із чітким UI-таргетом (наприклад, кнопка «Записати» → `aria-keyshortcuts="Ctrl+R"`).

Обидва варіанти можна комбінувати, але не всі дії мають видимий елемент-таргет (наприклад, глобальні шорткати в System Tray).

### Проблеми надійності (чому P3)

1. **NVDA та Browse Mode:** `aria-keyshortcuts` оголошується NVDA переважно у Forms Mode або при безпосередньому фокусі на елементі. Якщо фокус знаходиться глибоко в таблиці або списку, атрибут на landmark-батьку не буде озвучено.
2. **Неоднорідна підтримка між SR:** JAWS, NVDA та Narrator по-різному обробляють цей атрибут; поведінка непередбачувана між версіями.
3. **i18n значення атрибуту:** Значення `aria-keyshortcuts` має бути у форматі, зрозумілому для SR незалежно від мови інтерфейсу. Параграф WAI-ARIA рекомендує використовувати англійські назви клавіш (наприклад, `"Control+N"`, а не `"Ctrl+N"` або `"Ctrl+Н"`). Це суперечить принципу «українська перша».
4. **Settings toggle verbosity:** Якщо додати опцію «Озвучувати підказки шорткатів» у SettingsDialog — це додаткова складність як на рівні Rust-стану, так і на рівні UI.

## Критерії готовності

- [ ] Визначено перелік елементів (landmarks і/або кнопки), на які додається атрибут
- [ ] Атрибут `aria-keyshortcuts` додано на відповідні елементи у всіх компонентах зон
- [ ] Перевірено поведінку NVDA у Forms Mode і Browse Mode для кожного з анотованих елементів
- [ ] Перевірено, чи озвучується атрибут при фокусі з клавіатури та при Tab-навігації
- [ ] Визначено та задокументовано формат значення атрибуту (англійські назви клавіш vs локалізовані)
- [ ] (Опціонально) Settings toggle «Озвучувати шорткати» додано до SettingsDialog і підключено до Rust-стану
- [ ] Регресія: усі наявні ARIA-тести проходять після змін

## Відкриті питання

- Чи взагалі NVDA показує `aria-keyshortcuts` у Browse Mode (без фокусу на елементі)? Потрібне ручне тестування.
- Який формат значення атрибуту сприймає NVDA — `"Ctrl+N"`, `"Control+N"`, чи байдуже?
- Чи є сенс анотувати landmark sections, якщо шорткат спрацьовує глобально (незалежно від фокусу)?
- Чи потрібен Settings toggle «Озвучувати підказки шорткатів», і якщо так — за замовчуванням увімкнено чи вимкнено?
- Як обробляти глобальні шорткати (System Tray, фонові дії) без видимого UI-елемента?
- Чи варто інтегрувати це разом із Command Palette (ADR 2026-05-31), чи незалежно?

## Тригер повернення

Реальна скарга від користувача NVDA про те, що він не може знайти або не знає клавіатурні шорткати під час роботи з додатком.
