# Пауза запису без відключення від потоку

> **Контекст:** Деякі рекламні блоки не мають ICY-метаданих і не фільтруються
> через ignorelist. Користувач хоче тимчасово зупинити запис байтів на диск,
> але залишитись підключеним до потоку — щоб після паузи продовжити без переривань.

## Опис

Нова команда `pause_recording(stream_id)` / `resume_recording(stream_id)`:

- З'єднання з потоком залишається активним (байти читаються з сокета і викидаються)
- Запис на диск призупиняється
- Поточний файл треку не фіналізується — продовжується після resume
- Стан відображається у UI: нова іконка «пауза запису» в рядку потоку

Альтернативний підхід: фіналізувати поточний трек при паузі, а після resume — розпочати новий.
Це простіше технічно, але лишає «дірку» у записі.

## Критерії готовності

- [ ] `pause_recording` / `resume_recording` IPC-команди
- [ ] Байти читаються з сокета але не записуються під час паузи (щоб не накопичувати буфер і не відключатись)
- [ ] Новий стан `StreamState::RecordingPaused` (або `Paused`) у `StreamStatus`
- [ ] UI: кнопка «Пауза» у рядку запису (поряд з «Зупинити»); натискання toggle
- [ ] NVDA: оголошення «Запис призупинено» / «Запис відновлено»
- [ ] Паузований запис відновлюється коректно після reconnect

## Відкриті питання

- Чи продовжувати існуючий файл треку після resume, чи починати новий?
  Продовження складніше (потрібно тримати файл відкритим і писати у нього після паузи),
  але дає безперервний файл.
- Тривалість паузи: враховувати у тривалості треку чи ні?
- Чи додавати окремий гарячий клавіш для паузи запису?
