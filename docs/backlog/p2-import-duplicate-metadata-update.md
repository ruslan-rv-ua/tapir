# Оновлення метаданих існуючого потоку при імпорті дубліката

> **Контекст:** рішення прийнято 2026-07-23 (див. «Прийняті рішення»).
> Phase 3J реалізувала імпорт потоків; дублікати зараз пропускаються і навіть
> не зондуються, хоча probe часто має точніші метадані. Effort піднято S → M:
> окрім чекбокса, потрібен рефакторинг моделі `Row` (isDuplicate ≠ status),
> зміни в обох шарах (Rust + React) та i18n/тести.

## Опис

Phase 3J реалізувала імпорт потоків з файлів M3U8/PLS. Коли при імпорті
знайдено дублікат (потік з таким самим URL вже існує у профілі), він
позначається у `ImportStreamsDialog` як «дублікат» і вимикається для вибору —
тобто просто пропускається. Ба більше, дублікати виключені й із зондування
([ImportStreamsDialog.tsx:69](../../src/components/streams/ImportStreamsDialog.tsx#L69)),
тож свіжих метаданих для них зараз не існує взагалі.

Результат зондування (`ProbeResult`) часто точніший за збережене у профілі:
ICY-заголовки повертають офіційну назву станції, формат, бітрейт. Пропонуємо
для дублікатів опцію оновити метадані існуючого потоку, не додаючи новий запис.

**Поведінка в `ImportStreamsDialog`:**

1. Зондувати дублікати разом з рештою кандидатів (прибрати фільтр
   `alreadyInProfile` у `toCheck`) — той самий конвеєр з
   `PROBE_CONCURRENCY` і таймаутами, додаткове навантаження мізерне.
2. Для рядка-дубліката з успішним probe, у якого хоч одне поле відрізняється
   від профілю, — додатковий чекбокс «Оновити метадані». Підпис: зміна назви
   `стара → нова`, якщо назва змінилась; інакше — короткий перелік змінених
   полів (напр. «бітрейт: 128 → 192»). Основний чекбокс додавання для
   дублікатів залишається вимкненим.
3. Старі значення для порівняння — з фронтенд-стора `$streams`
   (`ImportCandidate` не несе id чи метаданих існуючого потоку).

**Технічні точки входу:**

- [stream_io_commands.rs:168](../../src-tauri/src/commands/stream_io_commands.rs#L168)
  — `commit_stream_import`: другий параметр зі списком оновлень
  (ідентифікація за URL — дедуплікація і так за URL); оновлює
  `name`/`format`/`bitrate`/`icy_name`/`icy_genre`/`icy_url` зі значень probe;
  один `save`, як зараз.
- `stream::probe` → `ProbeResult { icy_name, bitrate, format, … }` — поле
  називається `format` (тип `AudioFormat`), не `codec`.
- Модель `Row` у діалозі: «дублікат» зараз — значення `RowStatus`; після
  зондування дублікатів статус стане `ok`/`error`, тож дублікатність має
  стати окремим прапорцем (зачіпає всі місця з `status === "duplicate"`).
- Прецедент «probe точніший за плейлист» уже в коді: для не-дублікатів діалог
  підставляє `icy_name` замість назви з плейлиста
  ([ImportStreamsDialog.tsx:87](../../src/components/streams/ImportStreamsDialog.tsx#L87)).

## Прийняті рішення (2026-07-23)

1. **Обсяг оновлення** — усі probe-поля: `name`, `format`, `bitrate`,
   `icy_name`/`icy_genre`/`icy_url`. Єдине користувацьке поле — `name`
   (`update_stream` редагує лише його), і саме його diff чекбокс показує явно;
   решта полів належать probe, ручних правок там не буває.
2. **Probe для дублікатів** — зондувати разом з усіма при відкритті діалогу.
   Стану «probe вже виконано» для дублікатів не існувало — без цього фіча
   неможлива в принципі.
3. **Умова показу / грануляція** — чекбокс з'являється, коли будь-яке поле
   відрізняється; один чекбокс на рядок, без по-польових чекбоксів.
4. **Undo** — не робимо: послідовно з рештою застосунку (перейменування й
   видалення потоків undo не мають); захист від помилки — явний opt-in
   чекбокс з переглядом diff до підтвердження.
5. **Нормалізація назв** — порівняння без урахування регістру, з тримуванням
   пробілів. Спека ICY значення не нормалізує (довільний текст мовника),
   тож це прикладне рішення.

## Критерії готовності

- [ ] Дублікати зондуються разом з іншими кандидатами (фільтр
      `alreadyInProfile` у `toCheck` прибрано); основний чекбокс додавання
      для дублікатів лишається вимкненим незалежно від результату probe.
- [ ] `Row` розрізняє «дублікат» і стан probe (окремий прапорець, не значення
      `status`); підрахунок «дублікатів» у підсумку діалогу не ламається.
- [ ] Чекбокс «Оновити метадані» показується лише для дублікатів з успішним
      probe, у яких хоч одне поле (`name`/`format`/`bitrate`/`icy_*`)
      відрізняється від профілю; назви порівнюються без урахування регістру,
      з тримуванням пробілів.
- [ ] Підпис чекбокса: `стара → нова` для назви; якщо назва не змінилась —
      перелік змінених полів.
- [ ] Probe з помилкою або без відмінностей → чекбокса немає.
- [ ] `commit_stream_import` приймає окремий параметр зі списком оновлень
      (ідентифікація за URL); оновлює `name`/`format`/`bitrate`/`icy_name`/
      `icy_genre`/`icy_url` значеннями з probe; збереження профілю — одне.
- [ ] Логіка не зачіпає рядки, які не є дублікатами.
- [ ] Підсумок імпорту окремо рахує «оновлено метаданих: N» (`ImportResult`
      + повідомлення діалогу).
- [ ] Функціональність доступна з клавіатури; NVDA озвучує чекбокс разом з
      diff («стара → нова»).
- [ ] `pnpm test`, `pnpm vite:build`, `cargo test`, `cargo clippy` без
      регресій.
