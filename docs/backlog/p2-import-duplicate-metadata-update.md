# Оновлення метаданих існуючого потоку при імпорті дубліката

- **Слаг:** `import-duplicate-metadata-update`
- **Тип:** ідея
- **Стан:** draft
- **Зусилля:** S
- **Оновлено:** 2026-06-15
- **Залежності:** Phase 3J (Stream Import/Export ✅)

## Опис

Phase 3J реалізувала імпорт потоків з файлів M3U8/PLS. Коли при імпорті знайдено дублікат (потік з таким самим URL вже існує у профілі), він позначається у `ImportStreamsDialog` як «дублікат» і вимикається для вибору — тобто просто пропускається.

Однак результат зондування (`ProbeResult`) може містити більш точні метадані, ніж ті, що збережені у профілі: ICY-заголовки часто повертають офіційну назву станції, кодек, бітрейт. Якщо `icy_name` (або інші поля) відрізняються від поточних значень у профілі — є сенс запропонувати користувачу оновити метадані існуючого потоку, не додаючи новий запис.

**Пропонована поведінка в `ImportStreamsDialog`:**  
Для рядків, позначених як «дублікат», показати додатковий чекбокс:  
«Оновити метадані (назва: `<поточна назва>` → `<icy_name з probe>`)»  
— незалежно від основного чекбокса додавання нового потоку (який залишається вимкненим для дублікатів).

**Технічні точки входу:**
- `src-tauri/src/stream_io_commands.rs` → функція `commit_stream_import` — місце, де дублікати зараз пропускаються.
- `stream::probe` повертає `ProbeResult` з полями `icy_name`, `codec`, `bitrate`.
- Порівняння `ProbeResult::icy_name` з `Stream::name` у поточному профілі визначає, чи є що оновлювати.

## Критерії готовності

- [ ] `commit_stream_import` приймає список UUID потоків, для яких потрібно оновити метадані (окремий параметр від списку нових потоків).
- [ ] Для кожного такого UUID — оновлюються `name` (і, за бажанням, `codec`/`bitrate`) зі значень `ProbeResult`.
- [ ] `ImportStreamsDialog` показує для дублікатів чекбокс «Оновити метадані» з відображенням старої та нової назви (`стара → нова`).
- [ ] Чекбокс «Оновити метадані» відображається лише якщо `icy_name` з probe відрізняється від поточної назви (без урахування регістру, з тримуванням пробілів).
- [ ] Якщо probe не повернув `icy_name` (порожньо або `None`) — чекбокс не відображається.
- [ ] Логіка не зачіпає рядки, які не є дублікатами.
- [ ] Результат імпорту у підсумковому повідомленні окремо рахує «оновлено метаданих: N».
- [ ] Функціональність доступна з клавіатури та описана для скрін-рідера (NVDA).

## Відкриті питання

- **Що саме оновлювати?** Лише `name`, чи також `codec` та `bitrate`? Оновлення кодека/бітрейту може ненавмисно змінити відображення для потоків, де користувач міг вручну відредагувати ці поля.
- **Коли показувати опцію?** Лише якщо probe вже виконано (потік у стані `Probed`), чи запускати probe спеціально для дублікатів? Запуск probe на вже збережених потоках — додаткове навантаження при відкритті діалогу імпорту.
- **Чи показувати всі поля, що змінились?** Наприклад, якщо `icy_name` збігається, але `bitrate` відрізняється — пропонувати оновлення бітрейту окремо чи загальним чекбоксом?
- **Undo:** чи потрібне відміна оновлення метаданих (окремо від скасування всього імпорту)?
- **Нормалізація назви:** `icy_name` може бути у верхньому регістрі або містити зайві пробіли — чи потрібна нормалізація перед порівнянням?
