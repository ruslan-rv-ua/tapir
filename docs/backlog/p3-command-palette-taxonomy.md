# Командна палітра — таксономія категорій і потоки-навігація

> **Контекст:** спірна ідея реструктуризації пунктів палітри. Не братися в роботу, доки
> не закрито «Відкриті питання» нижче — вони ставлять під сумнів **саму суть** пропозиції.
> Готові-до-роботи дрібні покращення винесено окремо в
> [`command-palette-results-a11y`](done/p1-command-palette-results-a11y.md).

## Опис

Ідея: дати кожному пункту палітри явний **тип-категорію** й додати **новий тип пункту —
«потік»** для навігації до рядка у списку потоків.

| Категорія | uk | en | Приклади |
|---|---|---|---|
| `control` | керування | control | «Додати потік», «Імпортувати», «Записати все» |
| `stream` | потік | stream | назви потоків профілю |
| `navigation` | навігація | navigation | «Перейти до: Браузер», «Налаштування» |

Дві рушійні тези:

1. **Категорія як `sublabel`.** Другий рядок пункту показує тип (`потік` / `керування` /
   `навігація`) замість нинішнього контекстного підпису (назви потоку для дії Record).
2. **Пункт-потік замість дії.** Замість per-stream «Почати запис» / «Зупинити запис» — один пункт
   `label = stream.name`. Активація не виконує дію, а закриває палітру, переходить у
   секцію Потоки й ставить фокус на відповідний рядок; далі користувач сам тисне
   Enter / R / Menu.

## Відкриті питання

> Раніше ці пункти були позначені як «вирішено». Після оцінки (2026-07-23) їх
> **перевідкрито** — рішення сумнівні й мають бути підтверджені перед реалізацією.

1. **Категорія-як-`sublabel` — це сигнал чи шум?** Нинішній `sublabel` несе *контекст*
   (яка станція). Заміна на родовий ярлик типу для NVDA означає «потік, потік, потік…»
   у кінці кожного рядка — найменш корисну частину озвучення, тоді як тип майже завжди
   виводиться із самого `label`. Ризик: віддати реальну інформацію заради надлишкового тега.

2. **Заміна дій пунктами-навігацією — регрес головного сценарію?** Суперсила палітри —
   дія в один хід (`Ctrl+K` → набрати → Enter → пише). Нова модель додає крок: Enter лише
   переміщає фокус на рядок, дію користувач робить окремо. Для основної функції застосунку
   (запис потоку), і саме для клавіатурних/NVDA-користувачів, це **більше кроків**.
   Варіант: лишити одноходові «Почати запис» / «Зупинити запис», а навігацію додавати **паралельно**,
   не замість.

3. **Дві семантики Enter без групування.** Після зміни Enter інколи *виконує*, інколи
   *переміщає фокус*, а порядок «змішаний, без груп». Це непередбачувано, особливо для
   скрінрідера. Якщо пункти-навігація й дії співіснують — потрібне групування/розрізнення.

4. **Тай-брейкер для однойменних потоків — чи не YAGNI?** Триступеневий алгоритм
   (hostname → бітрейт → повний URL) — важка машинерія заради рідкісного випадку.
   Розглянути мінімальний варіант (лише hostname) або відкласти.

## Пропоновані рішення (за умови, що питання вище закрито «за»)

| Питання | Пропозиція |
|---|---|
| Per-stream «Почати запис» / «Зупинити запис» | Замінити пунктами-потоками (спірно — див. п.2) |
| i18n-ключі категорій | `palette_kind_control`, `palette_kind_stream`, `palette_kind_navigation` |
| Навігаційні команди | Чекати на `command-palette-phase-3` |
| Активація «потік» | Закрити палітру → секція Потоки → фокус на рядку потоку |
| Пошукова фільтрація | Тільки по `label`; substring `includes()` (не fuzzy); `sublabel` не шукається |
| Порядок пунктів | Змішаний, без груп (спірно — див. п.3) |
| Статус потоку | Іконка/емоджі перед назвою: `🔴 Radio Paradise` / `▶ Radio Paradise` |
| Гарячі клавіші у control-пунктах | Не показувати зараз |
| «Налаштування профілю…» (є з 2026-08-08, sublabel — активний профіль) | Не розкладено: жоден рядок таблиці його не покриває — вирішити при обговоренні |
| «Нещодавно використані» | Не додавати тут; phase-4 звужено до одного правила «на Songs — пісні першими», тож recency власника зараз не має |

## Критерії готовності (чернетка — фіналізувати після закриття питань)

- [ ] `docs/help/` оновлено — або зазначено, що запис видимої поведінки не змінює
- [ ] `PaletteItem` має поле `kind: "control" | "stream" | "navigation"`
- [ ] `sublabel` статичних пунктів = локалізована назва категорії (`palette_kind_*`)
- [ ] Пункти-потоки: `label = stream.name`, `sublabel = m.palette_kind_stream()`, `kind = "stream"`
- [ ] Статус: `🔴` перед назвою якщо записує; `▶` якщо програється
- [ ] `hintLabel` (між label і sublabel) = `hostname` з URL потоку
- [ ] Тай-брейкер однойменних потоків (обсяг залежить від рішення по п.4)
- [ ] Активація пункту-потоку: `$activeSection = "streams"` + фокус на рядку з відповідним `stream.id`
- [ ] Пошук фільтрує тільки по `label` (substring); `sublabel`/`hintLabel` не шукаються
- [ ] Доля per-stream «Почати запис» / «Зупинити запис» (замінити / лишити паралельно) — за рішенням по п.2
- [ ] Нові i18n-ключі: `palette_kind_control`, `palette_kind_stream`, `palette_kind_navigation` (uk + en)
- [ ] NVDA читає label + hintLabel + sublabel (перевірити через `aria-label` на `<li>`)
- [ ] Тести оновлені під обрану модель пунктів
