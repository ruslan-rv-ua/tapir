# Пункт трея зветься «Пауза», а живий звук зупиняє

> **Контекст:** знайдено під час grilling
> [preview-player-presentation](done/p2-preview-player-presentation.md), огрилено 2026-09-03.
> Той самий жест, четверта поверхня — але дефект інший: тут розходяться **слово й дія**,
> а не предикат. Усі розвилки закриті — читати §«Що вирішено» перед кодом.

## Опис

Мітка пункту трея залежить **лише від стану плеєра**, не від джерела:

```rust
let play_label = match snap.player_state {
    PlaybackState::Playing => i18n::t(Key::TrayPause),   // «Пауза»
    _ => i18n::t(Key::TrayPlay),                         // «Грати»
};
```
([menu.rs:71](../../src-tauri/src/tray/menu.rs:71))

А натискання йде в `toggle_playback` → `decide_toggle`, який для живого джерела віддає
`StopStream` або `StopPreview` ([playback_control.rs:64](../../src-tauri/src/playback_control.rs:64)).
Тобто поки грає станція, меню обіцяє «Пауза», а робить «Зупинити» — і повернутись «з паузи»
нікуди, бо з'єднання закрито.

Це **не** дефект прев'ю: він спрацьовує щоразу, коли грає будь-який живий звук, тобто в
основному сценарії застосунку.

Сусідній запис [preview-player-presentation](done/p2-preview-player-presentation.md) прибрав
паузу живого звуку з панелі й з медіаклавіш. Після нього трей лишається **єдиним** місцем,
де слово «Пауза» ще стосується ефіру.

**Зовнішня норма каже те саме.** GNOME HIG про пункти меню, що міняють мітку: "Two linked
actions can be combined into a single menu item, by changing the label when the item is
selected. For example, a Play item may change to Pause. However, only use this type of item
when actions are logical opposites which are obvious to users." Пункт-перемикач легітимний
рівно тоді, коли пара дій — очевидні протилежності; «Пауза», після якої повертатись нікуди,
протилежністю «Грати» не є.

## Чому окремим записом

Батьківський запис лікує **предикат**: `type === 'stream'` там, де питання «це живе?».
Тут предикат ні до чого — джерела в знімку меню взагалі немає
([`MenuSnapshot`](../../src-tauri/src/tray/mod.rs:16) несе `player_state`, `now_playing_label`,
`active_recordings`, `window_visible`). Дефект у тому, що мітка вибирається за станом, хоча
дія вибирається за джерелом.

Різні причини, різні користувачі (там прев'ю, тут потоки), різне приймання — тож окремо.

## Що вже відомо

- `build_snapshot` тримає `player_status` у руках ([mod.rs:63](../../src-tauri/src/tray/mod.rs:63)),
  тож дати меню ознаку живого джерела — один рядок.
- Предикат для цього дав батьківський запис: `PlaybackSource::is_live()`. Звідси `depends_on`.
- Ключ на «Зупинити» вже є — `Key::TrayStop` (`tray_stop`), його ж бере окремий пункт «Зупинити».
- Системний оверлей відтворення Windows сюди **не** входить: кнопку там малює сама система за
  `MediaPlaybackStatus`, перейменувати її не можна. Її натискання після батьківського запису
  зупиняє — це прийнята поведінка, а не дефект.
- Комбінація «на паузі й живе» **недосяжна**: усі три шляхи до `pause_playback` під охороною —
  панель ([PlayerPanel.tsx:196](../../src/components/player/PlayerPanel.tsx:196)), SMTC
  ([smtc.rs:227](../../src-tauri/src/smtc.rs:227)) і арм `PauseFile`. Незахищена лише сама
  IPC-команда, до якої більше ніхто не звертається. Модель може на це спиратися.

## Що вирішено

### 1. Для живого джерела в меню рівно один пункт зупинки

Розвилка, з якою запис заводили («прибрати окрему «Зупинити» / прибрати перемикач / лишити
обидва, розвівши тексти»), під час грилінгу звузилась до одного варіанта, бо **розводити
нічого**: для живого джерела обидва пункти — це одна команда.

| Пункт | Шлях | Кінець |
|---|---|---|
| `ID_TOGGLE_PLAYBACK` | `toggle_playback` → `StopStream` / `StopPreview` | `player.stop_playback` |
| `ID_STOP_PLAYBACK` | `persist_session_snapshot` + … | `player.stop_playback` |

`persist_session_snapshot` для живого джерела не робить нічого: `Preview` він пропускає явно,
а для `Stream` пише дискримінатор, уже виставлений на старті відтворення (це сказано в
коментарі арма `StopStream`, [playback_control.rs:213](../../src-tauri/src/playback_control.rs:213)).

Отже третій варіант мертвий — два пункти з різними словами й тотожним ефектом гірші за два
однакові слова. А перші два дають користувачеві **однакове меню**: рівно одна «Зупинити»,
у першій позиції. Розходяться вони лише тим, який id виживає.

### 2. Носієм лишається перемикач, перейменований на роль

`ID_STOP_PLAYBACK` **не малюється, поки джерело живе**; «Зупинити» несе головний пункт.
Причини:

- точна симетрія з панеллю плеєра — там зупиняє саме **головна** кнопка, а окрему «Зупинити»
  для живого не малюють;
- зберігається дебаунс, спільний із `Ctrl+Shift+K` і SMTC: клік у треї впритул до хоткея дає
  одну дію, а не дві;
- лишається правдивим доккоментар «Same entry point as Ctrl+Shift+K»
  ([handlers.rs:36](../../src-tauri/src/tray/handlers.rs:36)).

Константа `ID_TOGGLE_PLAYBACK` перейменовується на **`ID_PRIMARY_PLAYBACK`** (разом із
`MENU_ID_TOGGLE_PLAYBACK` і згадкою в `handlers.rs`). Без цього мінус варіанта лишався б у
коді: пункт із id «toggle» нічого не перемикає. Нове ім'я дзеркалить «головну кнопку плеєра»
з [CONTEXT.md](../../CONTEXT.md) §«Живе джерело» — воно називає **роль**, а не одну з двох
поведінок.

### 3. Знімок дістає власний тип стану, а не булеве поле

`MenuSnapshot.player_state: PlaybackState` замінюється на
`MenuPlayback { Idle, Live, FilePlaying, FilePaused }`, який `build_snapshot` виводить із
`PlayerStatus` через `is_live()`.

Недосяжна комбінація «на паузі й живе» зникає **за побудовою**, а не за коментарем; `match`
стає вичерпним, і мітка, наявність окремої «Зупинити» та `enabled` читаються одним списком
із чотирьох арм.

Булеве `is_live: bool` поруч зі станом **відхилено**: це рівно та форма, від якої стоїть
[ADR 2026-08-16](../decisions/2026-08-16-silence-is-mute-or-zero-volume.md) — читач мусив би
сам знати, які з шести комбінацій справжні, а компілятор мовчав би про решту.

`MenuSnapshot` уже не дзеркало домену, а модель відображення (у ньому лежать
`now_playing_label: Option<String>` і `window_visible`, яких у плеєрі немає), тож власний тип
стану там доречний. Доккоментар мусить це сказати: модель відображення трея, виводиться з
`PlayerStatus`.

Тултип переходить на той самий тип: `matches!(…, Live | FilePlaying)` замість перевірки
`Playing`. Тест `paused_does_not_show_play_arrow` стає `FilePaused` і перестає описувати стан,
у який ефір більше не потрапляє.

### 4. Рішення про пункти — чиста функція з тестом

`build_menu` бере `&AppHandle`, тож юніт-тестом не береться: сьогодні в `menu.rs`
протестований лише `tooltip`, а весь вибір пунктів не покритий нічим. Вичерпність `match`
ловить **пропущений** арм, але не **неправильний** — підміна `TrayStop` на `TrayPause`
скомпілювалась би й пройшла всі гейти.

Тому вся секція відтворення витягується вгору:

```rust
struct PlaybackItems {
    now_playing: bool,      // чи хоче цей стан рядок «Зараз грає»
    primary: Key,           // TrayStop | TrayPause | TrayPlay
    primary_enabled: bool,
    separate_stop: bool,    // чи малювати ID_STOP_PLAYBACK
}
fn playback_items(p: MenuPlayback) -> PlaybackItems
```

Один вичерпний `match`, один **табличний** тест, що називає всі чотири стани поіменно — той
самий візерунок, що вже стоїть під `is_live` (`is_live_answers_for_every_source`,
[engine.rs:1043](../../src-tauri/src/player/engine.rs:1043)).

`build_menu` лишається тонким малювальником і ANDить `now_playing` з
`now_playing_label.is_some()`: присутність підпису — не питання стану.

Очікувана таблиця:

| `MenuPlayback` | `primary` | `enabled` | окрема «Зупинити» |
|---|---|---|---|
| `Idle` | «Грати» | ні | ні |
| `Live` | «Зупинити» | так | **ні** |
| `FilePlaying` | «Пауза» | так | так |
| `FilePaused` | «Грати» | так | так |

### 5. i18n не змінюється

Нового ключа не треба в жодній локалі: `tray_stop` уже є, `tray_pause` лишається потрібним
для файлу. `messages/*.json` виходить зі списку `touches`.

### 6. Довідка посилається на власника правила, а не переказує його

В абзаці про меню значка **дві** неправди, не одна: перелік дій обіцяє паузу, а речення
«Пункти, яким зараз немає застосування, просто не показуються» хибне вже сьогодні — головний
пункт при зупиненому плеєрі показується, просто сірий.

Відмінність «ефір зупиняється / файл стає на паузу» лишається виключно в
[player.md:9](../help/uk/player.md:9) — правило 6 довідки, один власник пояснення.
`background.md` каже лише, що меню робить те саме, що головна кнопка.
[background.md:13](../help/uk/background.md:13), обидві локалі:

> Меню значка міняється разом зі станом. З нього можна керувати відтворенням — так само, як
> головною кнопкою програвача, — зупинити всі записи, показати чи приховати вікно і вийти з
> програми. Пункти, яким зараз немає застосування, не показуються або лишаються неактивними:
> зупиняти нічого, поки нічого не грає.

> The icon's menu changes with the state. From it you can control playback — just as the
> player's primary control does — stop all recordings, show or hide the window, and quit.
> Items with nothing to act on are either hidden or left inactive: there is nothing to stop
> while nothing is playing.

Зворот «так само, як … програвача» у цьому файлі вже вжитий про медіа-кнопки
([background.md:23](../help/uk/background.md:23)), тож шов не новий, а термін «головна кнопка»
збігається з `player.md` і `CONTEXT.md`. Стеля не тисне: `en/background.md` — 707 слів із 1000.

Друге речення свідомо каже «не показуються **або лишаються неактивними**»: це два різні
механізми в одному меню (окрема «Зупинити» й блок записів зникають, головний пункт сіріє), і
об'єднувати їх одним дієсловом було б новою неправдою.

### 7. `a11y: true` — правка змінює набір пунктів

Запис заводили з `a11y: false` і застереженням «якщо грумінг вирішить прибирати пункт меню —
перевести в true». Прибирає (§2), тож `true`.

Вирішує не наявність `aria` — її тут немає, меню нативне, — а те, що змінюється **набір
пунктів**, які людина зустріне. Чиста функція з §4 доводить **рішення**; що `build_menu`
справді те намалював, не доводить ніщо, бо він бере `AppHandle`. Чекліст закриває саме цю
половину.

`docs/testing/nvda-tray-toggle-label-vs-action.md`, п'ять сценаріїв: нічого не грає · ефір із
профілю · станція з каталогу (прев'ю) · файл грає · файл на паузі. Меню відкривається `Win+B`
→ стрілки до значка Tapir → клавіша контекстного меню.

### 8. Ані ADR, ані правок `CONTEXT.md`

Словник **уже правдивий**: §«Живе джерело» дослівно каже, що «головна кнопка плеєра,
`Ctrl+Shift+K`, **пункт трея** й системна клавіша `Pause` його зупиняють»
([CONTEXT.md](../../CONTEXT.md)). Модель була права раніше за код — міняти в ній нічого.

ADR не заводимо: з трьох умов провалюється перша й найважливіша — повернути «Паузу» коштує
одного арма, ціна зміни думки близька до нуля. Правило про мітки-перемикачі при цьому не
губиться: цитата GNOME HIG стоїть у §«Опис». Якщо такий самий дефект вилізе на другій
поверхні — тоді ADR стане правильним, бо буде що узагальнювати.

### 9. Три знахідки грилінгу винесено окремо

- **Сірий пункт при зупиненому плеєрі.** `.enabled(!matches!(…, Stopped))`
  ([menu.rs:78](../../src-tauri/src/tray/menu.rs:78)) — з `f9248f2` (2026-05-28), а
  `ToggleAction::ResumeLast` — з `ea6995c` (2026-07-17); трей після цього не переглядали.
  `Ctrl+Shift+K` на холодну відновлює останнє джерело, пункт трея — ні.
  → [tray-cannot-resume-last](p2-tray-cannot-resume-last.md).
- **Рядок «Зараз грає».** Подвійна двокрапка («Зараз грає: Файл: track.mp3») і префікс
  «Станція:», що відрізняє прев'ю від ефіру всупереч рішенню #1 батьківського запису.
  → [tray-now-playing-source-prefix](p3-tray-now-playing-source-prefix.md).
- **Гейти запису були неправильні** — стояло `[pnpm test, pnpm vite:build]` при суто
  Rust-правці. Виправлено в front-matter, окремого запису не потребує.

## Відхилені варіанти

- **Лишити обидва пункти, розвівши тексти.** Розводити нічого: §1 показує, що для живого
  джерела це одна команда. Два різні слова з тотожним ефектом гірші за два однакові.
- **Прибрати перемикач, лишивши `ID_STOP_PLAYBACK`.** Меню для користувача вийшло б те саме,
  але ціною розходження з панеллю, випадання кліку з дебаунсу й хибного доккоментаря про
  спільну точку входу з `Ctrl+Shift+K`.
- **`is_live: bool` у знімку.** Див. §3: булеве поле поруч зі станом лишає читачеві шість
  комбінацій, з яких справжні чотири.
- **`source: Option<PlaybackSource>` у знімку.** Та сама вада, плюс знімок тягнув би домен,
  з якого меню використає одну відповідь.
- **Витягти план усього меню**, а не лише секції відтворення. Рефакторинг усього `build_menu`
  заради дефекту в одній мітці; `effort` перестав би бути S.
- **Назвати відмінність «ефір/файл» у `background.md`.** Правило дістало б другого власника,
  і наступна правка `player.md` тихо розійшлася б із ним.
- **Прибрати відтворення з переліку в довідці зовсім.** Перелік став би неповним: головний
  пункт меню є, а довідка про нього мовчить — це гірше за неточність.
- **ADR «мітка-перемикач лише для очевидних протилежностей».** Див. §8.
