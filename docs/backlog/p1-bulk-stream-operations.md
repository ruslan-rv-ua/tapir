# Масові операції над списком потоків

- **Слаг:** `bulk-stream-operations`
- **Тип:** заплановано
- **Стан:** ready (усі дизайн-рішення узгоджені; старт реалізації — віха A)
- **Зусилля:** L
- **Оновлено:** 2026-06-14
- **Гілка:** `feature/bulk-stream-operations`
- **Залежності:** немає

## Опис

Зараз усі операції над окремим потоком (видалити, копіювати/перемістити в профіль,
копіювати URL, редагувати) працюють **строго по одному** через контекстне меню рядка (⋯).
Немає способу обрати кілька потоків і застосувати дію одразу.

Наслідок — лінійна вартість: видалити N потоків = N разів (меню → дія → підтвердження);
скопіювати/перемістити N у профіль = N разів, причому ціль доводиться щоразу обирати наново.
Найгостріше це після **імпорту** (треба прибрати половину кандидатів) і при реорганізації
профілів.

Єдині наявні «масові» дії — глобальні «Записати все» / «Зупинити запис» (увесь профіль,
лише стан запису). Часткові обхідні шляхи: експорт+імпорт (весь профіль, через файл,
зрізає паролі) і дублювання профілю (теж весь профіль). Підмножину вони не покривають.

**Контекст a11y підсилює проблему:** для NVDA-користувача кожен повтор циклу
(озвучення меню → стрілки → активація → діалог → підтвердження) значно дорожчий, ніж
зрячому «гумкою» виділити діапазон.

**Важливо — це окрема задача, не патч.** Поточний список — `role="application"` з
roving-focus на одному активному рядку; моделі виділення (`selectedKeys`/чекбокси/
`aria-selected`) немає взагалі.

## Рішення (узгоджено 2026-06-14)

1. **Модель виділення — спільна інфраструктура.** Повна модель виділення в
   `useCompositeList`/`CompositeList`; усі 6 списків (streams, wishlist, ignorelist,
   profiles, browser, schedule) переводимо разом → єдиний патерн multi-select на всіх
   екранах (консистентність для NVDA важливіша за менший обсяг).
2. **UI масових дій — стабільні кнопки в наявному тулбарі.** Кнопки завжди присутні,
   активні лише при виділенні (`aria-disabled` інакше — як уже зроблено для кнопки
   Експорт). Нічого не зʼявляється/не зникає. Кількість виділеного оголошується через
   live-регіон.
3. **Набір операцій:** Видалити · Перемістити в профіль · Копіювати в профіль (ціль
   обирається **один раз**) · Експорт виділених (M3U8/PLS) · Записати/Зупинити виділені.
4. **Фільтр/сортування:** «Виділити все» охоплює **лише видимі** (відфільтровані) рядки;
   будь-яка зміна фільтра **очищає** виділення; сортування виділення **зберігає** (за id —
   змінюється лише порядок).
5. **Непридатні елементи (частковий успіх):** дія виконується для придатних, непридатні
   (напр. потоки, що записуються, при move) **пропускаються**, далі оголошення-підсумок
   «Зроблено N, пропущено M (причина)». Узгоджено зі skip-семантикою `startAllRecordings`.
6. **«Виділити все / Зняти виділення» — і кнопка в тулбарі, і Ctrl+A** (обидва способи).
7. **Клавіша toggle-виділення — Ctrl+Space.** Space лишається за record/play-toggle у
   streams; Ctrl+Space перемикає виділення активного рядка. Однаково в усіх 6 списках.
8. **«Записати/Зупинити все» перемикають режим за наявності виділення.** Коли є виділення,
   ці кнопки діють на **виділені** потоки; без виділення — на весь профіль (як зараз).
   Окремих кнопок «…виділені» не додаємо. Той самий принцип у тулбарах інших списків з «…все».

> Нижче — рішення рівня *як* (9–14), узгоджені 2026-06-14 після ретельного перегляду коду.
> Пункти 1–8 фіксували *що*; 9–14 закривають реалізаційні розвилки, від яких залежить віха A.

9. **ARIA-подання виділення.** Список лишається `role="application"` з `role="listitem"`
   рядками (який **не** підтримує `aria-selected`). Стан кодується суфіксом в accessible
   name рядка (напр. «…, виділено») + polite live-лічильник; зрячим — лише CSS-підсвітка,
   без нового per-row контролу. NVDA не переозвучує назву без руху фокуса, тож кожен toggle
   явно викликає `announce()`.
10. **Сховище стану — nanostore + адаптер.** `$streamSelection = atom<Set<string>>` у
    `stores/streams`. `useCompositeList` отримує опційний selection-адаптер
    (`isSelected`/`toggle`/`selectAll`/`clear`); `StreamsPanel` і `StreamList` читають той
    самий atom через `useStore` (тулбар — сусідня зона, тож без prop-drilling через
    CompositeList→StreamList). Узагальнення на 6 списків — пізніше (spec just-in-time).
11. **Виділення діапазону (Windows-стандарт) — уже у віхі A.** Shift+↓/↑ розширює
    контінуальний діапазон від якоря; Shift+Click — спан якір→клік; Ctrl+Click — toggle
    одного (= Ctrl+Space). Якір = останній Ctrl+Space/Ctrl+Click або поточний фокус. Shift
    вільний для стрілок (резервований лише для Shift+Enter = «слухати»). Без цього NVDA-
    користувач платить N жестів на N рядків — суперечить мотивації задачі.
12. **Ctrl+A — toggle; Escape — clear.** Ctrl+A: якщо виділені не всі видимі → виділити всі
    видимі; якщо вже всі видимі → зняти. Escape очищає виділення, коли воно непорожнє
    (інакше проходить далі — у зоні списку Escape вільний). «Все» = лише видимі (рішення №4).
13. **Lifecycle — section-scoped.** Виділення живе, поки користувач у секції «Потоки»:
    переживає сортування, tab/F6 між списком і тулбаром, відкриття власних діалогів
    (transfer/confirm). Очищається при: зміні фільтра (рішення №4), перемиканні профілю,
    навігації в іншу секцію. id, що зникли з `$streams` (напр. після самих масових
    move/delete), авто-видаляються з множини, щоб лічильник лишався чесним.
14. **Назва «Записати/Зупинити все» — динамічна (ландить у віху C).** За наявності виділення
    видимий текст **і** accessible name стають «Записати виділені (N)» / «Зупинити виділені
    (N)»; без виділення — «Записати все» / «Зупинити запис». `disabled` перераховується по
    startable/active **серед виділених**. visible text == accessible name (WCAG 2.5.3 — назва
    не має «брехати» NVDA про справжню ціль).

## Підхід до реалізації (superpowers)

Цей запис — **парасолька** (north-star): рішення + розбивка на віхи. Сам по собі він
**не** реалізується одним циклом.

- Кожна **віха** — окремий повний цикл superpowers: `superpowers:brainstorming` →
  spec у [docs/superpowers/specs/](../superpowers/specs/) → план у
  [docs/superpowers/plans/](../superpowers/plans/) → TDD → merge → перевірка з NVDA.
- **Spec пишемо just-in-time**: наступну віху специфікуємо лише після того, як попередня
  змерджена й перевірена. Не специфікуємо все A–D наперед (рішення C/D зсунуться після A).
- **Віха A отримує найглибший brainstorming** — вона визначає спільний API виділення
  (`useCompositeList`), клавіатурну модель і ARIA, від яких залежать B/C/D.
- Кожна spec/plan віхи **посилається на цей запис** замість дублювати рішення.

## Віхи (A–D)

Порядок за ризиком; кожна віха — самодостатня цінність, мерджиться окремо.
Залежності: **A → B → C**; **D — після A** (бажано після C, щоб модель стабілізувалась).

### A. Фундамент + масове видалення (streams) — `P1`

- Шар виділення в `useCompositeList`/`CompositeList` (opt-in) поверх `$streamSelection`
  (`atom<Set<string>>`); адаптер `isSelected/toggle/selectAll/clear` (рішення №10).
- Виділення для NVDA — суфікс в accessible name рядка + polite `announce()` на кожен toggle;
  зрячим — CSS-підсвітка, без нового per-row контролу (рішення №9).
- Ctrl+Space — toggle активного рядка (+ ставить якір); Shift+↓/↑ — діапазон від якоря;
  Shift+Click — спан; Ctrl+Click — toggle (рішення №11). Space лишається за record/play.
- «Виділити все»/«Зняти» — кнопка в тулбарі та Ctrl+A (toggle); Escape очищає; «все» = лише
  видимі (рішення №12).
- Lifecycle section-scoped: фільтр/профіль/вихід із секції очищають, сорт/tab зберігають,
  зниклі id авто-prune (рішення №13); live-лічильник виділеного.
- Масове видалення з одним `ConfirmDialog` (точна кількість).
- Лише streams; інші списки ще не чіпаємо.

### B. Перенос у профіль (streams) — `P1`

- Масові «Копіювати»/«Перемістити» в профіль; ціль обирається **один раз**
  (адаптація `StreamTransferDialog` під множину).
- Частковий успіх + підсумок; skip move-while-recording.

### C. Експорт + запис/зупинка виділених (streams) — `P1`

- Експорт підмножини в M3U8/PLS (розширити backend, щоб приймав список id).
- «Записати/Зупинити все» перемикаються на режим «виділені» за наявності виділення (рішення №8);
  назва й accessible name стають «…виділені (N)», `disabled` — по виділеній підмножині (рішення №14).

### D. Розкочування на решту 5 списків — `P2`

- Увімкнути виділення у wishlist, ignorelist, profiles, browser, schedule.
- Релевантні bulk-дії (переважно видалення; для profiles — обережно з активним профілем).
- Має сенс лише після того, як модель доведена на streams.
