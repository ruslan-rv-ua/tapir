# Командна палітра — mode-prefixes (`>` команди, `@` контент)

> **Контекст:** спірна ідея, вирізана з [command-palette-phase-4](p3-command-palette-phase-4.md).
> Не братися, доки не закрито «Відкриті питання» — насамперед проблему розкладки.

## Опис

VS Code використовує `>` у Ctrl+P для фільтрації лише команд. Аналог для Tapir —
префікс першим символом запиту звужує список за типом пункту (`PaletteItem.type`
з phase-3):

| Префікс | Показує |
|---------|---------|
| `>` | команди: `action` + `navigate` («Перейти до: …» — теж команда з погляду користувача) |
| `@` | контент: `song` (+ `stream`, якщо [command-palette-taxonomy](p2-command-palette-taxonomy.md) ухвалить пункти-потоки) |
| *(без префікса)* | все |

Парсинг локальний в input-обробнику: якщо перший символ запиту `>` або `@` —
відтяти префікс перед пошуком і застосувати фільтр за типом до результатів.
Не торкається ні Rust-бекенду, ні Tauri IPC.

Пропозиції, зафіксовані при вирізанні (підтвердити перед реалізацією):

- явний `@` знімає поріг ≥ 2 символів phase-3: сам `@` без залишку запиту показує
  10 найновіших пісень (інакше `@` показував би порожнечу);
- плейсхолдер + aria-label підказують синтаксис (напр. `Пошук · > команди · @ контент`);
- префікс-символ не потрапляє у пошуковий запит.

## Відкриті питання

1. **Розкладка (головний блокер).** На стандартній українській розкладці `>` і `@`
   не набираються: Shift+2 дає `"`, клавіша `>` дає `Ю`. Користувач шукає українські
   назви саме в укр. розкладці — префікс вимагає перемикання розкладки туди-назад,
   що вбиває цінність «швидкого» фільтра. Варіанти: прийняти як є; приймати також
   символи тих самих фізичних клавіш в укр. розкладці (`Ю` для `>` — конфліктує з
   реальним пошуком на літеру «Ю»); інший механізм (окрема клавіша-перемикач типів
   у палітрі); відмовитись від ідеї. Суміжне:
   [command-palette-dual-language-search](p2-command-palette-dual-language-search.md).
2. **Чи потрібно взагалі?** Аудиторія — один NVDA-користувач, символи вводяться
   наосліп, у палітрі поки ~15–25 пунктів — фільтр типів мало що дає. Повернутися,
   коли контенту стане суттєво більше (fuzzy, taxonomy, ріст `$songs`) і
   context-бусту (phase-4) виявиться недостатньо.
3. **Навчання синтаксису для NVDA:** чи достатньо плейсхолдера/aria-label, чи
   потрібен також пункт у F1-довідці.

## Критерії готовності (чернетка — фіналізувати після закриття питань)

- [ ] Введення `>` фільтрує список до типів `action` + `navigate`
- [ ] Введення `@` фільтрує до контентних типів (`song`; `stream` — за наявності)
- [ ] Сам `@` без залишку запиту показує 10 найновіших пісень (поріг ≥ 2 знято явним префіксом)
- [ ] Введення без префікса — поведінка не змінюється
- [ ] Префікс-символ відтинається перед пошуком
- [ ] Плейсхолдер + aria-label підказують синтаксис; нові i18n-ключі uk/en, регенерація paraglide
- [ ] NVDA коректно зачитує результати після введення префікса (наявний анонс кількості працює)
- [ ] Юніт-тести: парсинг префікса + фільтрація за типом
