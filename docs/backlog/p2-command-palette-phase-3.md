# Командна палітра — Фаза 3: розширення контенту (станції, пісні, навігація)

> **Контекст:** сира ідея, розширення `CommandPalette.tsx` (зараз — лише дії над потоками) до станцій/пісень/навігації. Читати спершу ADR `2026-05-31-command-palette-and-search-ux.md`.

## Опис

### Що є зараз

`CommandPalette.tsx` — глобальний модальний overlay, відкривається через `Ctrl+K`.
Наразі містить **лише дії над потоками** поточного профілю:
- «Додати потік» (`add-stream`)
- «Імпортувати потоки» (`import-streams`)
- «Експортувати потоки» (`export-streams`)
- Per-stream: «Записати» / «Зупинити запис» для кожного потоку зі списку

Станцій вішліста, записаних пісень і навігаційних команд у палітрі немає.
Це відповідає стану **Phase 1/2** за roadmap — палітра «недобудована», а не «тільки про потоки».

### Що треба додати (Phase 3)

Згідно з ADR [`2026-05-31-command-palette-and-search-ux.md`](../decisions/2026-05-31-command-palette-and-search-ux.md) (DA1)
та [`implementation-phases.md`](../implementation-phases.md), командна палітра повинна стати
справжнім Spotlight / VS Code аналогом для Tapir — охоплювати **дії + станції + пісні + навігацію**:

#### 1. Станції (потоки поточного профілю)

> **Оновлено 2026-07-22** відповідно до рішень у `command-palette-taxonomy`:
> per-stream пункти змінені з «Відтворити/Записати: <назва>» на пункти-навігатори.

Джерело: стор `$streams`.

Кожен потік відображається одним пунктом:
- `label = stream.name` (назва станції)
- `sublabel = m.palette_kind_stream()` («потік»)
- `kind = "stream"`
- Активація → закрити палітру + перейти в секцію Потоки + фокус на рядку потоку

Пошук: по `name` (не по URL, не по sublabel).

> **Прибрано:** per-stream «Відтворити: <назва>» / «Записати: <назва>» як окремі дії.
> Загальні дії «Записати все» / «Зупинити все» залишаються у категорії `control`.

Пошук: fuzzy по `name`. Підказка (`sublabel`): категорія (`palette_kind_stream`).

#### 2. Записані пісні (Songs)

Джерело: Tauri IPC → `list_songs` (або аналог з фази 3C).
Команди на елемент:
- «Відтворити пісню: <назва файлу / artist – title>» — відкрити файл у програвачі Songs
- «Показати у провіднику: <назва>» — reveal у файловій системі (якщо є команда)

Пошук: fuzzy по `filename`, `artist`, `title` (якщо є metadata).
Підказка (`sublabel`): дата запису або тривалість.

> **Відкрите питання:** чи читати мета-теги файлів у беклог (backend) чи лише ім'я файлу?
> Зараз Songs Manager відображає лише filename — обмежитись тим самим.

#### 3. Навігаційні команди («перейти до…»)

Статичні записи, не залежать від даних:
- «Перейти до → Потоки» — `navigate('/streams')`
- «Перейти до → Браузер» — `navigate('/browser')`
- «Перейти до → Пісні» — `navigate('/songs')`
- «Перейти до → Вішліст» — `navigate('/wishlist')`
- «Перейти до → Розклад» — `navigate('/schedule')`
- «Перейти до → Налаштування» — відкрити Settings Dialog

Можна позначити категорію через `sublabel: 'навігація'`.

### Чому це цінно для незрячого користувача

NVDA navigates by Tab order; deep pages require many keystrokes to reach an item.
Коли вміст палітри збагачено, **один `Ctrl+K` + кілька символів** дає прямий доступ
до будь-якого потоку, пісні або екрана — без проходження зон і меню.
Особливо важливо для Songs (список накопичується — сотні файлів) та швидкого
перемикання між екранами.

## Критерії готовності

### Станції
- [ ] У результатах палітри є пункт-потік для кожного потоку профілю: `label = stream.name`, `sublabel = "потік"`, `kind = "stream"`
- [ ] Пошуковий рядок фільтрує пункти-потоки тільки по `name`
- [ ] Активація пункту-потоку → закрити палітру + перейти в секцію Потоки + фокус на рядку
- [ ] Per-stream «Відтворити/Записати/Зупинити» — **відсутні** (замінені пунктами-потоками)

### Записані пісні
- [ ] У результатах є записи «Відтворити пісню: <назва>» для файлів з Songs
- [ ] Пошук по назві файлу (як мінімум); по artist/title — якщо backend повертає metadata
- [ ] `sublabel` відображає дату або тривалість (якщо доступно)
- [ ] Пісні підвантажуються з Tauri IPC (не ламають TTI якщо список великий → lazy або обмеження)

### Навігація
- [ ] Є 5–6 статичних навігаційних команд «Перейти до → <екран>»
- [ ] Навігаційні команди завжди видимі у результатах при порожньому запиті (або за keyword «перейти»)
- [ ] Відкриття налаштувань з палітри працює

### Доступність (NVDA)
- [ ] `role="option"` і `aria-selected` коректно анонсують вибраний елемент при навігації стрілками
- [ ] Кількість результатів оголошена `aria-live` або `aria-label` на контейнері
- [ ] Вибір `Enter` виконує дію, закриває палітру, фокус повертається на елемент-opener
- [ ] Sublabel зачитується NVDA (перевірити: через `aria-label` чи окремий `<span>`)
- [ ] Нові категорії (станції, пісні, навігація) не ламають роботу з клавіатурою

### Якість
- [ ] Завантаження Songs не блокує відкриття палітри (debounce або prefetch при відкритті)
- [ ] Тести оновлені під нові джерела даних (`CommandPalette.test.tsx`)
- [ ] i18n: всі нові рядки додані в `uk.json` і `en.json`

## Відкриті питання

1. **Ліміт відображення результатів.** Якщо у Songs сотні файлів — палітра переповниться.
   Варіанти: показувати перші N (15–20), або «показати ще», або лише якщо є query.
   Рекомендація: при порожньому query — показувати тільки статичні дії та навігацію;
   при query ≥ 2 символів — підмішувати станції і пісні (до 10 кожен тип).

2. **Сортування результатів.** Чи підіймати «нещодавні» пісні/станції?
   Поточна реалізація не сортує, лише фільтрує. Sorting by recency — у Phase 4 (context-aware ranking).

3. **Пошук пісень: filename vs metadata.** Songs Manager зараз показує лише filename.
   Якщо backend не повертає artist/title — пошук обмежено filename. Уточнити при реалізації.

4. **Навігаційні команди при порожньому рядку.** Показувати одразу всі навігаційні?
   Або лише коли набрано «перейти» / «nav»? Рекомендація: показувати одразу (невеликий статичний список).

5. **Взаємодія з Phase 4 (context-aware ranking).** Phase 4 залежить від Phase 3.
   При реалізації Phase 3 не закладати жорсткий порядок — залишити місце для рейтингування.
   Детальніше: [command-palette-phase-4](p3-command-palette-phase-4.md).

6. **Видима кнопка «Команди» в шапці (DA5).** ADR рекомендує прибрати з усіх екранів —
   чи робити це в рамках цієї ж задачі чи окремо?
