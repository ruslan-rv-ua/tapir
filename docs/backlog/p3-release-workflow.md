# Release-workflow: exe у GitHub Release на тег

> **Контекст:** запис-заготовка, `draft`. Рішень немає жодного — самі питання;
> перед реалізацією потрібен окремий грилінг. Передумова —
> [ci-pipeline](p2-ci-pipeline.md).

## Опис

Після [repo-public-rename](done/p2-repo-public-rename.md) у проєкту з'являється публічна
сторінка, а Tapir — це «portable single EXE, без інсталятора». Такий продукт лягає в
GitHub Release ідеально: один файл, який завантажують і запускають. Першому ж тегу
(0.1.0) завантажуваний exe потрібен, інакше публічна сторінка пропонує відвідувачу
зібрати застосунок самому.

Форма зрозуміла: окремий workflow, тригер `push` тегу `v*`, збірка й публікація
артефакту в Release. У воротах exe **не** збирається (рішення
[ci-pipeline](p2-ci-pipeline.md)) — там це подвоїло б найдорожчий крок на кожному мержі
заради артефакту, який єдиний розробник однаково збирає локально однією командою.

Запасний шлях, якщо запис не встигне: тег публікується вручну зі свого дерева.

## Відкриті питання

- **`just build` чи `just build-fast`?** Перший дає мінімальний exe і довгу компіляцію,
  другий — навпаки. Для того, що люди завантажують, розмір, імовірно, важливіший за час
  збірки в CI, але це рішення, а не очевидність.
- **Підпис.** Непідписаний exe зустрічає користувача екраном SmartScreen. Користувач
  тут може бути незрячим, і цей екран йому треба вміти пройти — тобто питання не лише
  про сертифікат, а й про те, що написано в довідці. Сертифікат коштує грошей і
  прив'язаний до особи чи організації.
- **Контрольні суми** — публікувати SHA-256 поруч із exe?
- **Ім'я файлу артефакту.** `tapir.exe` чи `tapir-0.1.0-x64.exe`?
- **Release notes** — писати руками, генерувати з комітів чи брати з `docs/backlog/done/`?
- **Хто тегує.** Тег — це необоротна публічна дія; чи ставить його агент, чи людина.

## Критерії готовності

- [ ] `docs/help/` — перевірити окремо: якщо з'явиться сторінка завантаження, довідка
      про SmartScreen може стати потрібною
- [ ] Питання вище закриті рішеннями (окремий грилінг)
- [ ] `push` тегу `v*` збирає exe і публікує його в GitHub Release
- [ ] Ворота лишились без змін — release-workflow до них не домішується
