# Репозиторій стає публічним і зветься tapir

> **Контекст:** рішення грилінгу 2026-09-05, перша половина розвилки про ворота —
> див. [ADR «ворота відмовляють, а не радять»](../../decisions/2026-09-05-gates-refuse-rather-than-advise.md).
> Друга половина — [ci-pipeline](../p2-ci-pipeline.md), який без цього запису
> нездійсненний.

## Опис

Репозиторій сьогодні — `ruslan-rv-ua/Tapir_draft`, приватний. Це блокує три різні
речі одразу, і лише третя очевидна.

**Захист гілки.** Приватний репозиторій на плані Free не має ні branch protection, ні
rulesets: обидві точки API відповідають `403 Upgrade to GitHub Pro or make this
repository public to enable this feature`. Тобто ворота, які **відмовляють** прийняти
червоний коміт, у поточній конфігурації побудувати неможливо — жодним workflow.

**Адреса, яку застосунок уже показує.** `PROJECT_HOMEPAGE` у
`src-tauri/src/commands/app_commands.rs` дорівнює `https://github.com/ruslan-rv-ua/tapir`,
і тест `project_homepage_is_the_public_repository` це стереже. Адресу обрано свідомо ще
2026-09-02 у [about-app-info](p1-about-app-info.md) — як майбутню публічну. Сьогодні
кнопка **Відкрити сторінку проєкту** в розділі «Про програму» веде на 404, і туди ж веде
довідка: `docs/help/uk/troubleshooting.md` каже прикласти файли журналу до повідомлення
«на сторінці проєкту». Тобто зламаний не декоративний рядок, а описаний у довідці шлях
користувача, який зіткнувся з проблемою.

**Хвилини CI.** Публічний репозиторій отримує безлімітні стандартні раннери; для
приватного вони метровані, а `windows-latest` іще й множиться на два. Аргумент «CI на
Windows дорогий» після публікації просто зникає.

## Що робиться

1. `gh repo rename tapir` — ім'я стає тим, яке застосунок уже називає.
2. Видимість → public.
3. Заповнити опис репозиторію (зараз порожній) — одним рядком, тим самим, що
   `description` у `Cargo.toml`.
4. `.claude/settings.local.json` — прибрати з індексу, додати в `.gitignore`. Це файл
   локальних перевизначень, за конвенцією він поза git; у ньому лежать шляхи з іменем
   користувача Windows.
5. `AGENTS.md` — рядок про розробника переформулювати безособово: «проєкт розробляється
   й тестується з NVDA; доступність — вимога, а не опція». Обґрунтування конвенцій
   зберігається, факт про конкретну людину зникає з HEAD.
6. `docs/agents/issue-tracker.md` — ім'я remote у тексті.

## Межа: історію не переписуємо

Вилучення файлу з HEAD **нічого не ховає** — публікується вся історія, і `settings.local.json`
лишиться видимим у минулих комітах, як і email автора в 1477 підписах. Єдиний спосіб
справді прибрати — переписати історію; заради рядка зі шляхом це не робиться. Пункти 4
і 5 — гігієна на майбутнє, а не приховування.

`docs/backlog/` і `docs/agents/` публікуються **свідомо, цілком**. Це найцінніше, що є в
репозиторії після коду: саме вони пояснюють, чому код такий. Публікувати код без причин,
за якими він такий, — гірший з двох варіантів.

## Прийняте рішення: Issues увімкнено

Розробник закрив відкрите питання 2026-09-05: **Issues лишаються увімкненими** (публічний
репозиторій вмикає їх за замовчуванням, тож дія тут — не чіпати, а назвати роль).

Підстава — не симетрія з беклогом, а зобов'язання довідки. `docs/help/*/troubleshooting.md`
відправляє користувача, що зіткнувся з проблемою, «на сторінку проєкту» подати
повідомлення з файлами журналу; без Issues він приходить на сторінку, де подати нікуди.
Вимкнути їх означало б лишити описаний у довідці шлях без другої половини — рівно та сама
вада, що й 404 до перейменування, лише на крок далі.

Межа ролі: Issues — **вхідна скринька, не трекер**. Власні задачі проєкту там не
заводяться й звідти не беруться; єдине їх джерело лишається `docs/backlog/`. Чуже
повідомлення, з якого справді виростає задача, стає звичайним записом беклогу — так само,
як це вже описано для `.scratch/` у `/wayfinder`. Власник пояснення один — секція
«Вхідні канали» в [`docs/agents/issue-tracker.md`](../../agents/issue-tracker.md);
окремий ADR не заводиться, бо рішення відкочується одним перемикачем і живе там, де його
прочитають.

Рішення поставлено **поруч із сусіднім, а не окремо**: правило про зовнішні PR
(«вимкнено») — того самого класу, і два правила про вхідні канали в різних кінцях файла
читались би як незалежні. Самé воно не змінене: PR — це готовий діф, а не повідомлення
про проблему, і власного тригера не отримав.

## Критерії готовності

- [x] `docs/help/` змін не потребує — адреса в довідці не називається, названо лише
      кнопку; після перейменування описаний нею шлях починає працювати
- [x] `https://github.com/ruslan-rv-ua/tapir` відкривається; кнопка **Відкрити сторінку
      проєкту** в розділі «Про програму» більше не веде на 404 (ручна перевірка).
      Сторінку перевірено **неавтентифікованим** запитом (`curl` без токена, `200`) —
      автентифікований `gh repo view` віддав би `200` і приватному репозиторію, тобто
      довів би нуль. Сам натиск кнопки в застосунку не відтворювався: код кнопки цим
      записом не змінювався, а адресу стереже `project_homepage_is_the_public_repository`
- [x] Видимість — public; опис репозиторію заповнено
- [x] `.claude/settings.local.json` не в індексі й перелічений у `.gitignore`
- [x] `AGENTS.md` не містить факту про конкретну людину, а конвенції NVDA зберігають
      обґрунтування. Рев'ю показало, що одного файлу мало: крок 5 просить, щоб факт
      зник **із HEAD**, а критерій називав лише `AGENTS.md` — той самий факт стояв іще
      у двох **живих** агентських документах, і обидва прибрано
      (`docs/agents/triage-labels.md`, `.claude/skills/writing-nvda-checklists/SKILL.md`).
      У датованих архівах — закритий запис `done/p2-eslint-adoption.md` і плани
      `docs/superpowers/` — факт лишено свідомо: та сама межа, що й для історії комітів.
      Правити архів заради факту, який однаково лишається в 1477 підписах, не дає нічого
- [x] `docs/agents/issue-tracker.md` називає remote новим іменем
- [x] Відкрите питання про Issues закрито рішенням, а не мовчанням
