# Застосунок ніде не показує ні своєї версії, ні адреси проєкту

> **Контекст:** знайдено під час grilling `help-troubleshooting`, коли писався
> ескалаційний вихід довідки — «зберіть журнал і повідомте про проблему».
> Огрилено 2026-09-02: усі розвилки закрито, нижче — рішення. Читати спершу
> «Рішення», потім «Критерії готовності». Прийнято 2026-09-02 після NVDA-прогону (7/7).

## Опис

Версія застосунку в інтерфейсі **не показується ніде**: діалогу «Про програму» не
існує, у налаштуваннях рядка з версією немає, у заголовку вікна теж. Пошук по обох
файлах повідомлень (`src/i18n/messages/{uk,en}.json`) не дає жодного ключа про версію,
«about» чи адресу проєкту. Єдине місце, де версію можна дістати, — CLI-прапорець
`tapir.exe --version` (`cli.rs`), про який користувач застосунку не знає.

Так само немає **адреси**, куди повідомляти про проблему. `README.md` каже «open an
issue», але README користувач у застосунку не бачить, а вбудована довідка посилань не
має за конвенцією: клік по `http`-посиланню повів би webview із застосунку на чужу
сторінку, і захисту від цього в коді немає (`useWebviewGuard` гасить лише
акселератори перезавантаження).

Чому це варте запису: розділ довідки «Якщо нічого не допомогло» веде користувача
покроково — увімкнути детальне логування, перезапустити, повторити проблему, забрати
`data\logs\tapir.log` — і закінчується проханням повідомити про проблему. **Перше, що
питають у такому звіті, — версія**, а взяти її користувачеві нізвідки. Портативність
робить це гострішим: файл `tapir.exe` перейменовують і копіюють, тож «яка у вас збірка»
не відповідає навіть той, хто її завантажив.

### Що є в коді на 2026-09-02

- **Версія живе в трьох файлах**, не в одному: `src-tauri/tauri.conf.json`,
  `package.json`, `src-tauri/Cargo.toml`. JS-API `getVersion()` і
  `app.package_info().version` читають конфіг Tauri; CLI `--version` читає
  `CARGO_PKG_VERSION`, тобто `Cargo.toml`. Сьогодні всі три кажуть `0.1.0`, сторожа
  збігу немає.
- **Обидва механізми для адреси вже є.** `navigator.clipboard.writeText` працює у
  `StreamList` (копіювання URL потоку). `shell_open` (`commands/shell_open.rs`) віддає
  рядок `ShellExecuteW("open")`, а для `https://` шел знає рівно одну асоціацію —
  браузер за замовчуванням. Це саме те, чого запис
  [open-stream-with-default-app](p1-open-stream-with-default-app.md) уникав для
  потоків, і саме те, що потрібно тут.
- Поточний git-remote — `github.com/ruslan-rv-ua/Tapir_draft`; публічна адреса
  проєкту, яку показуватиме застосунок, — інша (див. рішення 2).

## Рішення (grilling 2026-09-02)

1. **Місце — секція «Про програму» внизу вкладки «Загальні»** налаштувань програми,
   після «Логування», заголовок `h3` як у сусідніх секцій. Довідка з «Усунення
   несправностей» уже приводить користувача саме на цю вкладку. Відкинуто: окремий
   діалог (нова поверхня заради двох рядків) і вкладка довідки (markdown-конвеєр
   кнопок не вміє, «відкрити в браузері» туди не покласти).
2. **Адреса одна — `https://github.com/ruslan-rv-ua/tapir`**, сторінка репозиторію, не
   issues: до issues звідти один клік, а сторінка проєкту показує ще README і релізи.
   Свідомо не збігається з поточним remote `Tapir_draft`: застосунок показує майбутню
   публічну адресу.
3. **Адреса — текстом, під нею одна кнопка «Відкрити сторінку проєкту»** через
   `shell_open`; Windows підіймає браузер за замовчуванням, webview лишається на місці.
   Кнопки «Скопіювати» немає: текст виділяється й копіюється сам, а друга кнопка на ту
   саму адресу лише подовжує вкладку. Помилка шелу — тостом, як у пісень і потоків.
4. **Одне джерело для адреси — поле `homepage` у `Cargo.toml`.** Rust читає його через
   `env!("CARGO_PKG_HOMEPAGE")` і віддає фронтенду **однією командою разом із
   версією** (версія — з `app.package_info().version`, тобто з конфігу Tauri). Кнопка
   викликає **закриту команду без аргументів** «відкрити сторінку проєкту»: у шел не
   потрапляє жоден рядок із фронтенду, загальної команди `open_url` не заводиться.
   TS-константи адреси немає; `getVersion()` не використовується, щоб у секції був
   один виклик і один стан завантаження.
5. **Сторож трьох копій версії — vitest-тест**, що читає `tauri.conf.json`,
   `package.json` і `Cargo.toml` і падає, коли рядки версії не збігаються. Дешево, і
   ловиться в гейті, який і так проганяється. Звужувати джерела (`"version":
   "../package.json"` у конфігу Tauri) не стали: `Cargo.toml` усе одно лишався б.
6. **Обсяг — лише назва, версія, адреса.** Збірка Windows і версія WebView2, а також
   кнопка «Скопіювати відомості для звіту» — окремим записом
   [diagnostic-report-block](../p3-diagnostic-report-block.md), який цей запис розблоковує:
   там потрібна ще одна команда в Rust, а цей запис S і стоїть у 0.1.0.
7. **Клавіатура: текст статичний, кнопка описана версією.** Версія й адреса фокуса не
   приймають (носій факту — видимий текст, як велить
   [ADR про видимий носій](../../decisions/2026-08-31-visible-carrier-for-announced-facts.md)),
   а кнопка отримує `aria-describedby` на абзац із версією й адресою: Tab у секції
   зупиняється рівно один раз і несе версію. Полів «лише для читання» не заводиться.
   До заголовка `h3` у режимі огляду ведуть клавіші `H`.
8. **Довідка — два місця.** Сторінка «Налаштування» описує вкладку «Загальні»
   посекційно й дістає одне речення про «Про програму». Ескалаційний абзац «Усунення
   несправностей» замість «на сторінці проєкту на GitHub» веде до кнопки (налаштування
   програми → **Загальні** → **Про програму** → **Відкрити сторінку проєкту**) і просить
   назвати версію, яку видно там же. Стеля `en`-файлу — 1000 слів, зараз 976: якщо не
   влазить, підрізати в тому ж абзаці, не деінде.

Дрібниці без розвилки: секція показує два рядки — «Версія: 0.1.0» і адресу — і кнопку
під ними; помилку шелу мапить наявний `shellOpenError.ts` — **одним формулюванням на всі
коди** («Не вдалося відкрити сторінку проєкту»): адреса стала, `not_found` неможливий, а
`no_assoc` («немає браузера») кличе до тієї ж дії, що й будь-яка інша відмова — відкрити
адресу вручну, вона на екрані просто над кнопкою; поки бекенд не відповів, у секції
стоїть «…», і мовчазна відмова IPC лишає його там без тосту (нема що озвучувати);
ADR не потрібен (рішення оборотне, нового терміна для `CONTEXT.md` немає).

> Після реалізації: `en/troubleshooting.md` — 999 слів зі стелі 1000. Наступна правка
> цього файлу мусить розщеплювати, не дописувати (див. правило 6 довідки).

## Критерії готовності

- [x] У налаштуваннях програми, вкладка **Загальні**, після «Логування» є секція
      «Про програму» з заголовком `h3`, рядком версії, адресою текстом і кнопкою
      «Відкрити сторінку проєкту»
- [x] Версія й адреса приходять **однією** командою Rust: версія з конфігу Tauri
      (`package_info`), адреса з `Cargo.toml` `homepage`; ні версія, ні адреса не
      дублюються рядком у TS чи в i18n
- [x] Кнопка викликає закриту команду без аргументів, яка віддає адресу з
      `CARGO_PKG_HOMEPAGE` у `shell_open`; webview лишається в застосунку, відкривається
      браузер за замовчуванням
- [x] Помилка шелу показується тостом через `shellOpenError.ts`
- [x] vitest-тест падає, якщо версії в `tauri.conf.json`, `package.json` і
      `src-tauri/Cargo.toml` не збігаються
- [x] Версія й адреса — статичний текст без фокуса; кнопка має `aria-describedby` на
      абзац із ними, тож при Tab на кнопку версія дочитується
- [x] `docs/help/{uk,en}/settings.md`: у переліку секцій вкладки «Загальні» є
      «Про програму»; `docs/help/{uk,en}/troubleshooting.md`: ескалаційна позиція веде
      до кнопки й просить назвати версію; `en/troubleshooting.md` ≤ 1000 слів
- [x] NVDA-чекліст пройдено 2026-09-02 (7 сценаріїв, без розбіжностей; файл видалено на прийманні): заголовок секції
      досяжний по `H`, версія читається в режимі огляду, Tab зупиняється в секції один
      раз і озвучує кнопку з версією, після натискання фокус лишається на кнопці
- [x] `pnpm test`, `pnpm vite:build`, `cargo test` — без помилок
