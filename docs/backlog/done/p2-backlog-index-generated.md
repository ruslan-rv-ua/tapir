# Індекс беклогу генерується з front-matter

> **Контекст:** заведено й закрито одним PR 2026-09-07. Порівняння варіантів і причина
> вибору — в «Прийнятих рішеннях»; що лишилось у процесі — у «Спадку».

## Опис

`ROADMAP.md` виріс до 277 КБ за місяць: 92 % обсягу займала секція «Виконано», де кожен
закритий запис мав есей про спадок у клітинці таблиці (у середньому 2,6 КБ, найдовший
8,7 КБ, 67 рядків довші за 2000 символів). Крок 1 алгоритму для агента велів відкривати
цей файл на кожному старті сесії — орієнтовно 55–80 тисяч токенів за читання, — а
крок закриття велів його редагувати, тобто читати ще раз. Знання про спадок жило лише в
індексі: з 99 done-записів окрему секцію про нього мав один. README чесно попереджав, що
файл «підтримується вручну й може дрейфувати»; на момент закриття два відкриті записи в
ньому були відсутні, один done-запис не мав `completed:`, один мав `target: v0.1.0`.

## Прийняті рішення

- **Індекс генерується, не пишеться.** `build/backlogIndex.mts` збирає `ROADMAP.md` і
  `done/README.md` з front-matter усіх записів; `build/backlogIndex.test.ts` у `pnpm test`
  порівнює файли на диску з тим, що записи рендерять зараз, і в разі розбіжності називає
  команду `pnpm backlog index`. Дрейф зникає як клас, а не як дисципліна.
- **Спадок живе в записі.** Текст колонки «Що лишилось у спадок» переїхав у секцію
  «Спадок» кожного done-запису; індекс несе один рядок — поле `summary:` (до 160 символів,
  без посилань, бо індекс рендериться з двох тек). Без поля індекс показує `title`.
- **Тема версії — єдина ручна частина.** `THEMES.md` тримає по секції на target; генератор
  вставляє її під заголовок як є. Хронологія «того ж дня закрився…» туди не пишеться.
- **Запит замість читання.** `pnpm backlog next` друкує поточну версію, `ready`-записи
  зверху вниз і заблоковані — крок 1 алгоритму більше не вимагає відкривати ROADMAP.
- **Відхилено:** лише розділити файл (лишає два ручні кроки на закриття й дрейф);
  Backlog.md чи beads (власна схема `type`/`kind`/`target`/`a11y`/`gates` не лягає в їхню,
  beads тримає JSONL замість markdown); GitHub Issues (відхилено раніше в
  [issue-tracker.md](../../agents/issue-tracker.md)).
- **Секцію «Перехресні рішення» знято.** Три закриті пункти вже записані в done-записах
  і ADR; відкритий A4 переїхав у `notes:` запису mpv-playback-engine.

## Спадок

Індекс беклогу більше не є документом, який хтось пише: обидва файли — вивід
`pnpm backlog index`, і сторож у `pnpm test` червоніє, щойно вони відстають від записів.
Правило, яке варто пам'ятати: **індекс не носить корисного навантаження** — усе, що хочеться
сказати про запис, пишеться в сам запис (`summary:` для одного рядка, «Спадок» для решти),
а не в клітинку таблиці. Другий урок — про вартість: файл, який агент читає на кожному
старті, коштує стільки, скільки важить, і 173 ручні правки за місяць кожна платили за
читання зростаючого файлу. Третій — сторож ловить не тільки застарілість: перший же прогін
знайшов done-запис без `completed:`, `target: v0.1.0` з зайвим префіксом і два відкриті
записи, яких у ручному ROADMAP не було. Свідома межа: `OPEN-QUESTIONS.md` — той самий ручний
агрегат, застарілий із 2026-07-23, — цим записом не чіпався і напрошується або на той самий
генератор, або на видалення окремим записом.
