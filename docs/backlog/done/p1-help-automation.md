# Довідка: Вішліст і Розклад

> **Контекст:** четвертий із шести записів, що наповнюють вбудовану довідку (F1).
> Специфікація — [help-content-polish](p1-help-content-polish.md). Обидва розділи —
> про те, як Tapir працює замість користувача: одне фільтрує треки, друге вмикає запис
> за годинником. Нових вкладок не потребує: обидві вже існують із заглушками.

## Опис

- **`wishlist.md`** — переписати заглушку: навіщо бажані й ігноровані треки, **якірність**
  патерна й синтаксис (`*`, `?`, регістр не важливий), із чим саме звіряється патерн,
  приклади, порядок правил у два кроки, що відбувається при збігу з кожним списком, кнопка
  «Додати приклад», вхід із меню рядка на «Потоках».
- **`scheduling.md`** — переписати заглушку: одноразовий і повторюваний запис, час початку
  й завершення, перехід через північ, дві умови роботи планувальника (Tapir запущений,
  активний профіль) і старт із запізненням, правило «хто зайняв потік», життя одноразового
  пункту, вмикання без видалення, наступний запуск, зупинка при правці, запас часу,
  результати минулих запусків, сповіщення.

Перелік обов'язкових позицій — у розділі «Мапа покриття» специфікації; він **звірений із
кодом 2026-08-13**, повторно звіряти не треба.

## Технічні кроки

- Нових вкладок немає, обидві вже стоять із заглушками. Ключі майже: `help_section_wishlist`
  збігається з міткою бару в обох локалях, а `help_section_scheduling` англійською був
  «Scheduling» проти «Schedule» у барі — виправлено при реалізації, бо заголовок `##` мусить
  дослівно дорівнювати назві вкладки (конвенція 3), а назва вкладки — мітці бару (рішення 1
  специфікації). Решта п'ять екранних вкладок звірено, розбіжність була єдина.
- Обидва розділи завершуються блоком «Клавіші на цьому екрані» — по три пункти, без
  `Delete` (він робить канонічне; прецедент — `streams.md`).
- Обсяг: `wishlist` — 200–400 англійських слів, `scheduling` — до 600, цільові ~500
  (виняток доданий у правило 6 парасольки цією ж сесією).
- У прозі — **«бажані треки»** й **«ігноровані треки»** (мітки вкладок). «Вішліст» лишається
  тільки заголовком розділу, слова «ігнор-лист» у тексті немає; терміни — в `CONTEXT.md`.
- Синтаксис патернів **дублює** `DEVELOPERS.md` свідомо — це різні аудиторії; але приклади
  й формулювання пишуться заново, простою мовою, без слова «wildcard».

## Критерії готовності

- [x] `wishlist.md`, `scheduling.md` написані (uk + en) за мапою покриття
- [x] Якірність патерна названа прямо, з парою `Tycho` / `Tycho*`; сказано, що звіряється
      рядок «Виконавець - Назва» з метаданих ефіру
- [x] Сказано прямо, що вішліст нічого не відсіює, і що ігнорований трек лишається в
      суцільному файлі ефіру
- [x] Порядок дії правил (ігнор-лист → вішліст → звичайна поведінка) названий явно й
      звірений із кодом; ігнор-лист окремого потоку не згадується
- [x] Приклади патернів подані списком, не таблицею; перший збігається з набором кнопки
- [x] Названо обидві умови, без яких розклад мовчить: Tapir має працювати, і працює лише
      активний профіль
- [x] Пояснено, що станеться з пунктом розкладу, якщо застосунок не працював (зокрема старт
      посеред вікна), потік уже писався, розклад відредагували під час запису або потік
      видалили
- [x] Блоки «Клавіші на цьому екрані» — по три пункти
- [x] `wishlist.md` ≤ 400 англійських слів, `scheduling.md` ≤ 600
- [x] `pnpm test`, `pnpm vite:build` — без помилок
