# Довідка: Профілі, Налаштування, Робота у фоні

> **Контекст:** п'ятий із шести записів, що наповнюють вбудовану довідку (F1).
> Специфікація — [help-content-polish](p1-help-content-polish.md); мапу покриття для
> всіх трьох розділів звірено з кодом під час grilling 2026-08-13, **читати її як є**.
> Три розділи разом, бо ділять одну межу: що налаштовується для всієї програми, що — для
> профілю, а що взагалі живе поза вікном (трей, автозапуск, глобальні клавіші, ярлик
> з параметрами).

## Опис

- **`profiles.md`** — переписати заглушку: що таке профіль, перемикання зупиняє все
  активне, CRUD із заборонами, експорт-імпорт, налаштування навіть неактивного профілю,
  автовідтворення при старті.
- **`settings.md`** — новий: **фізична межа** `Ctrl+,` (програма) проти `Ctrl+Shift+,`
  (профіль), одне речення-правило про те, чим вони різняться по суті, і повний склад обох
  діалогів по вкладках і секціях; автозбереження без кнопки «Зберегти»; перепризначення
  глобальних клавіш із типовими комбінаціями й трьома видами відмови; один рядок про
  вимкнену вкладку «Постобробка».
- **`background.md`** — новий: закриття вікна не виходить із програми, трей і його
  динамічне меню, сповіщення про трек, глобальні гарячі клавіші, системні медіа-кнопки,
  автозапуск і переміщений `tapir.exe`, другий запуск, підтвердження виходу під час
  запису, підрозділ **«Запуск з параметрами»** (CLI) двома групами.
- **`player.md`** — одне речення: назвати перемикач **Автовідтворення при запуску** й
  сказати, що він **типово вимкнений**. Написана редакція описала механіку «підняти
  останнє», але не назвала важіль і дефолт, тож обіцяє поведінку, якої у свіжого Tapir
  немає (стиль-гайд, правило 7).

Перелік обов'язкових позицій — у розділі «Мапа покриття» специфікації.

## Рішення цієї сесії

Наскрізні (шов, правило 6, опис фонового шару за дією) живуть у парасольці. Тут — те, що
стосується лише цих файлів:

- **`settings.md` перелічує по секціях, а не по контролях.** Рядок на секцію, усі мітки
  дослівно через кому, пояснення — тільки для позицій без іншого власника. Близько
  двадцяти контролів уже пояснені в `recording.md`, `scheduling.md` і `player.md`.
- **Жирний — за першою згадкою в межах свого розділу**, не в межах усієї довідки:
  наскрізного обліку ніхто не вестиме, а мітка без жирного в переліку налаштувань
  втрачає сенс.
- **Типові комбінації восьми глобальних клавіш називає `settings.md`** — це єдине
  можливе місце — а `background.md` описує, що вони роблять.
- **Заборони в `profiles.md` вплетені в кроки**, не зведені в регламент; обмеження на
  активний профіль подане дією («спершу перемкніться на інший»).
- **Блок «Клавіші на цьому екрані» в `profiles.md` — три пункти**, третій із них меню
  рядка: воно канонічне, але за ним єдині двері до налаштувань чужого профілю.
- **CLI — двома групами** («діють лише при запуску» проти «діють і на вже запущеному»),
  два приклади, півречення про відсутність консолі й про точний збіг назви.

## Технічні кроки

- Дві нові вкладки в `HelpDialog.tsx`: `settings` і `background` — після `templates`,
  перед `troubleshooting` (якого ще немає), згідно з порядком зі специфікації.
- Два нові ключі: `help_section_settings` («Налаштування» / "Settings"),
  `help_section_background` («Робота у фоні» / "Running in the background").
- Склад вкладок налаштувань звіряти **з кодом**, не з `docs/keyboard-shortcuts.md`: там
  уже є дрейф — перемикач системних медіа-кнопок стоїть в `AudioTab.tsx`, а не у вкладці
  «Гарячі клавіші».
- `profiles.md` завершується блоком «Клавіші на цьому екрані».
- CLI-аргументи формулювати як побутовий інструмент (ярлик, автозавантаження), а не як
  «режим для розробників»; це свідомий виняток із межі README/DEVELOPERS, зафіксований
  у специфікації.
- Ворота йдуть у порядку **`pnpm vite:build` → `pnpm test`**: нові `help_section_*`
  генерує paraglide-плагін vite, і до генерації тести їх не бачать.

## Критерії готовності

- [x] `profiles.md`, `settings.md`, `background.md` написані (uk + en) за мапою покриття
- [x] Кожен із трьох укладається в 200–1000 слів по **англійському** файлу, і обсяг
      понад 600 має причину в змісті
- [x] Межа «програма проти профілю» названа явно, з обома комбінаціями й **одним
      реченням-правилом**; склад обох діалогів звірено з кодом по вкладках і секціях
      (`GeneralTab`, `AudioTab`, `HotkeysTab`, `ProfileRecordingTab`, `ProfilePlaybackTab`,
      `ProfileInterfaceTab`, вкладка «Постобробка»), включно зі згорнутими блоками
      **Перепідключення** й **Додатково**
- [x] Жодна позиція, пояснена в `recording.md`, `scheduling.md` чи `player.md`, не
      пояснюється вдруге в `settings.md` — лише називається
- [x] Сказано, що налаштування зберігаються самі й кнопки «Зберегти» немає
- [x] Вимкнена вкладка «Постобробка» згадана одним рядком, без вибачень
- [x] Типові комбінації восьми глобальних клавіш названі в `settings.md`; `background.md`
      описує їх за дією й відсилає по поточні значення в налаштування програми
- [x] Три види відмови при призначенні клавіші описані, і «які клавіші приймаються» —
      позитивним переліком
- [x] `background.md` відкривається тим, що закриття вікна не виходить із програми;
      сказано, якими саме дверима видно підтвердження виходу під час запису
- [x] Меню трею, підказка значка й діалог виходу описані **за дією**, без жирних міток,
      і `en`-файл не містить українських рядків
- [x] Підрозділ «Запуск з параметрами» подає аргументи двома групами, з прикладом на
      кожну; перелік звірено з `src-tauri/src/cli.rs`
- [x] `profiles.md` не обіцяє перемикача профілю в лівій панелі й називає обмеження на
      активний профіль
- [x] `player.md` називає **Автовідтворення при запуску** і його дефолт
- [x] Вкладки «Налаштування» і «Робота у фоні» на своїх місцях
- [x] `pnpm vite:build`, потім `pnpm test` — без помилок
